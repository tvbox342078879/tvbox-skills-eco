# tvbox-inspect · 监察司（生态监测总控）

> **一句话职责**：整个生态的**监测中枢** —— 所有"该被盯着的东西"，都在这一个技能里被盯。

## 0. 为什么存在（S105 拆分）

拆分前，"管监测的"散在三处，用户难以找到统一入口，且职责重叠：
- `legacy-watchdog` 里塞了 19 个检查器 + 26 个监测命令（**监测**）**同时**兼做遗留处置（**处置**）——一锅烩。
- `ecosys-conductor` 里塞了 20 路信号源探针 + 6 判据终验（**自监测**）**同时**兼做并行提速/分工协调（**调度**）。
- `probe-hub` 里上游跑路检测（**上游监测**）与搜索采集混在一起。

**S105 拆分口径**：
| 技能 | 新定位 | 关键词 |
|---|---|---|
| **tvbox-inspect（监察司）** | **发现层**：监测/扫描/探针/体检 | 盯 |
| **legacy-watchdog（遗迹哨）** | **处置层**：分级/派活/跟踪/报告 | 修 |
| **ecosys-conductor（总指挥）** | **调度层**：提速/分工/协调 | 派 |

**"发现 → 处置 → 调度"是水流关系，不是重叠**：检查器逻辑**只有一份**（在本技能），
遗迹哨通过 `inspect_engine` 调用，结构上不可能两边各扫一遍。

## 1. 三类监测（本技能全部收口）

| 面 | 管什么 | 命令 |
|---|---|---|
| **A 生态自监测** | 20 路信号源活体探针（注入已知异常验证检测器能抓到）/ 6 判据终验 / 生态五维评估 | `signal-check` / `verify` / `assess` |
| **B 库·数据监测** | M01-M19：台账未闭环、失效库复测超期、快照新鲜度、合约缺口、命名合规、数据质检、上游跑路、生态平衡性… | `scan` / `status` / `monitors` |
| **C 上游监测编排** | 仓库弃更/跑路检测的**调度**（探活实现在探源司，本技能编排时机与结果处置） | `scan`（含 M18） |

## 2. 命令（`tvbox inspect <cmd>`）

```bash
# ── 核心扫描 ──
tvbox inspect scan                       # 全量扫描 → 分级遗留清单（M01-M19）
tvbox inspect status                     # 按监测项看达标情况
tvbox inspect monitors                   # 查看监测项登记册（monitors.json）
tvbox inspect add-monitor --id Mxx ...   # 登记新监测项（只改登记册，引擎零改动）

# ── 生态自监测 ──
tvbox inspect signal-check               # 20 路信号源活体探针
tvbox inspect verify                     # 6 判据一键终验
tvbox inspect assess                     # 生态五维评估

# ── 监测引擎自诊（"监测者自己也要被监测"）──
tvbox inspect health                     # 监测项自身健康（防看门狗睡着）
tvbox inspect rootcause                  # 遗留根因聚类（系统性 vs 偶发）
tvbox inspect gain                       # 检查器增益量化（哪个检查器真抓到过）
tvbox inspect tune                       # 阈值调优建议（放宽/收紧/剔除，只出建议）
tvbox inspect noise                      # 检查器噪声（假阳性）度量
tvbox inspect attribution                # 豁免原因自动归因（反推口径缺陷）
tvbox inspect regress                    # 预豁免规则健全性回归
tvbox inspect latency                    # 监测延迟度量（发现及时性）
tvbox inspect drill                      # 延迟归因下钻

# ── 生态健康度 ──
tvbox inspect hygiene                    # 跨技能卫生分排名
tvbox inspect coverage                   # 监测覆盖率地图（哪些风险面还没检查器）
tvbox inspect docsync                    # SKILL 文档一致性（声明 vs 代码）
tvbox inspect balance                    # ★ 生态平衡性体检（五维：谁进化慢/谁拖后腿）

# ── 进化：新风险自动接手 ──
tvbox inspect expand                     # 风险面动态扩展雷达（新业务/新技能/新数据源三路信号）
tvbox inspect replay                     # 检查器时效回归（口径变更回放历史）
tvbox inspect track                      # 扩面决策留痕（候选件件有去向）
tvbox inspect add-decision --entity X --verdict 扩面|暂不 --note ..
```

## 3. 标准流程（监测 → 处置）

```
① tvbox inspect scan            # 监察司：发现（扫出遗留清单）
      │
② tvbox inspect signal-check    # 监察司：自检（确认检测器本身没失灵）
      │
③ tvbox watchdog report         # 遗迹哨：处置（分级 → 派活 → 报告上云）
      │
④ 按报告里每条遗留的「下一步命令」闭环（tvbox log / block review / evolve upgrade ...）
```

## 3.5 生态平衡性体检（S106 · `inspect balance`）

**用户诉求**："监测生态间各环节，包括技能进化，各技能薄弱环节，整体技能谁进化慢，拖后腿了，
把这些薄弱相优先处理掉，让生态平衡性强。"

**五维模型**（权重可调，写死在 `_BAL_WEIGHTS`，改须人工确认）：

| 维度 | 权重 | 判定依据 |
|---|---|---|
| 进化停滞 | 30 | 末次升级距今 > 2 天（台账 ts 与进化留痕取较新者） |
| 质量短板 | 25 | 卫生分（hygiene ≤ 阈值触发） |
| 监控盲区 | 20 | flow.json `self_check` 项数（0 项 = 未覆盖） |
| 联动断点 | 15 | 是否 import 生态门面（`file_to_janitor`/`register_monitor`） |
| 实绩质量 | 10 | 未清 backlog 数（含完成标记的条目不计） |

**量化输出**三件套：
- **平衡指数** = `100 − 各技能加权总分的标准差`（越高越均衡；100 = 完全齐平）。
- **木桶最短板** = `min(技能, key=加权总分)` 所对应的维度（最低分维）。
- **薄弱环节优先级清单** = 按「维度分升序」排序的 `(技能, 维度, 分数, 说明, 下一步命令)`。

**处置原则（只诊断不自动改）**：
```
先补最短板（木桶）→ 缩小离散度（拉齐头部尾部）→ 复跑 balance 看指数回升
```
- 监控盲区 → 补 flow.json `self_check`（或 `add-monitor` 登记薄弱面）
- 联动断点 → 在技能里 `from core import file_to_janitor / register_monitor`
- 实绩质量 → `tvbox inspect gain` 看命中率 / 清 backlog（逐条闭环或标 `[已清零]`）
- 进化停滞 → `tvbox evolve upgrade <技能>` 推动版本前进

**M19 检查器**：仅对「加权总分 < 70」或「任一维度 < 50」产遗留（防噪声）——
健康技能的"最弱维度"未必是缺陷，不到阈值不入统一遗留流。

`check_eco_gap` 调 `tvbox janitor census --json`，判据三层：
- 缝占比 > `gap_threshold`（`monitors.json` 顶层配，默认 0.60）→ 报遗留 + 无主区排名
- 单个无主分区 > 100 节点 → **单独报**（一块大区比总量更值得先处理）
- census 未成功退出 / 未打印「明细已落盘」/ `total=0` → **一律「无法判定」**，不许折叠成"没有缝"

> ⚠️ 最后一条是踩过坑的：census **写失败时不删旧文件**，旧结果还在。
> 检查器若无条件读那个文件，失败时会读出上次的数据并照常报真阳性——
> **看起来在正常工作**。故必须以前置的「明细已落盘」为"这次真的写了"的判据。

> 加监测项 = 往 `monitors.json` 加一行 + 在 `CHECKERS` 注册对应 `check_*`；
> 未实现的 check 类型允许**先登记后补**（`add-monitor` 登记册可成长）。

## 4. 铁律

1. **单一事实源**：检查器/监测项逻辑**只在本技能**，遗迹哨 import 调用，禁重复实现（防重叠）。
2. **0 遗留≠真达标**：scan 开头先跑检查器健康预检（`health`），检查器集体失灵时必须报"假达标"。
3. **新增风险面不改代码**：加监测项只改 `monitors.json` 登记册；未实现的 check 类型允许先登记后补代码。
4. **阈值只建议不自动改**：`tune` 出建议，调整须人工确认后改 monitors.json。
5. **三态不折叠**（M-R60）：库读失败/快照损坏 → 显式"无法判定"，绝不当"达标"。
6. **平衡性只诊断不自动改**（S106）：`balance` 出优先级清单与下一步命令，处置须人工确认后逐条走；
   薄弱项判定须带证据（末次升级天数 / self_check 项数 / 未接门面 / 未清 backlog），非拍脑袋给分。
7. **完成标记口径**（S106）：backlog「真未清」= 不含任何完成标记（已清零/已兑现/MVP已兑/已闭环…）；
   把已完成项误判为未清是假阳性来源，须同口径修正 `check_backlog_items` 与 `_hygiene_rows`。

## 6. 进化机制（"以后还有啥需要监管的能自动接手"）

1. **登记册可成长**：`monitors.json` 加监测项零改代码（已具备）。
2. **风险面动态扩展雷达** `expand`：三路信号（新业务提示 / 新技能 / 新数据源）自动提议新监测项。
3. **覆盖率地图** `coverage`：标记"无检查器的风险面" → 提示登记。
4. **接手闭环**：`coverage` 发现缺口 → `expand` 提议 → `add-decision` 留痕 → `add-monitor` 登记 → 下轮 scan 自动跑。**新风险自动被接手**。
5. **登记门面**：`core.register_monitor(risk_face, check_type, desc)` —— 任何技能一行登记新监测面，无需改本技能代码。
