# unfinished-audit · 清账司（未完成事项搜集官）

> **一句话职责**：把散在六个地方的「没做完」收成**一张账**，每笔都有归属和期限，不收口就过不了验收。

## 0. 为什么存在

生态里「未完成」原本散落在**六个互不相通的地方**，各记各的：

| 源 | 载体 | 原状态（S136 实测） |
|---|---|---|
| ① 问题总账 | `conductor/plans/issues_ledger.json` | 15 条，状态机 open→next→done |
| ② 各技能 backlog | 9 × `scripts/flow.json` 的 `backlog[]` | 57 条，格式自由、全靠人读 |
| ③ CHANGELOG 敞开段 | 9 × `CHANGELOG.md` | 「仍敞开」「留档不装睡」等段落 |
| ④ 监测项未实证 | `tvbox-inspect/monitors.json` | 29 项，缺 `proven` 即未证明有效 |
| ⑤ 云端台账/经验库 | DB_SESS / DB_LIB | 待跟进/待补记录 |
| ⑥ 技能正文待办 | 9 × `SKILL.md` | 正文里的 TODO/待补/后续 |

**没有第七处**——所以「还有什么没做完」这个问题，从来没有一个命令能回答。
每次都是人问一句、AI 临场各处翻一遍、翻完就散。这就是「产出后又啥都不做」的根因：
**产出没有落到一个会被人反复查的账上**。

本技能补的就是这一处：**唯一的未完成事项账本** `unfinished_ledger.json`。

## 1. 铁律（M-R79 ~ M-R86）

| 编号 | 铁律 | 守护方式 |
|---|---|---|
| **M-R79** | **未完成不得无主**：每条欠账必须有 `owner`(监察官) + `next`(下一步) + `due`(期限)；缺任一即 `verify` 判红 | 判据⑧ |
| **M-R80** | **七源只读不猜**：任一源读失败，显式报「无法判定」，**不得**折叠成「无欠账」（M-R60 同款） | 采集器三态 |
| **M-R81** | **收尾唯一入口**：任何技能干完活，收尾一律跑同一条命令，不许各写各的。**派单必须真送达**（写进对方 `flow.backlog` 并回读），不是打印一行「已派给谁」 | `tvbox close`（`finish` 别名） |
| **M-R82** | **账要能清**：欠账只能靠「真实做完 + 显式收口（带证据）」变绿，**不许**因为采集器看不见了就自动消失；反向也成立——**不许因为自己派单写了副本，下轮就把它当新欠账采回来**（回声抑制） | `signature` 指纹 + 消失告警 + `ECHO_TAG` |
| **M-R83** | **规则不得打架到死锁**：「按规则做事就永远验收不过」是最坏的治理，它把人逼成「把表填绿、真账不记」。两条规则对同一事实要求相反时，必须做**口径拆分**而非二选一 | M03 只报「无人认领的脏尾巴」，在册者算「在办」 |
| **M-R84** | **新建技能须过八面纳管**，第八面为「收尾绑定」：统一收尾命令必须采得到它、它自己也必须能交账。只建目录不接收尾 = 造新孤岛（隐性欠账 + 假绿） | `onboard` ⑧ 双检 + `flow.backlog` 键 |
| **M-R86** | **已结区必须幂等**：同一条欠账只留一条，重复**判红**不告警。成因链隐蔽——收口 → 采集把同 signature 当新增写回（状态回滚 open）→ 再收口一次，`append` 无条件执行。危害不是多一行，是**账目数字失真**（「已结 8 条」里 3 条是影子）；数字是本技能唯一对外交付物 | `close_item` 去重 + `verify_ledger` 判红 + T15 双回归 |
| **M-R87** | **改代码前必查账（P1）**：动手改某文件/某功能之前，先跑 `tvbox close mine <技能名> --before <文件\|关键词>`。⚠️ 这条的由来要写清：它**不是**从账上查出来的，是"事后才发现自己重复劳动 / 改完才看到账上早已记载"这件事逼出来的——所以它必须做成**命令**，不能只写在规则里。只写在规则里的约束，在"我正想改这个文件"的那一刻永远想不起来 | `mine --before` 三档命中（🔴强/🟡同技能/✅无） |

> 这几条为什么是铁律：欠账清单最典型的失败不是「收不全」，而是**看起来全清了**。
> 采集口径一变、源文件一挪、解析器一改，清单就悄悄空了，而命令仍然打印 ✅。
> 更隐蔽的是**回声**：自己派出去的副本被自己采回来，总数「变多」看着像发现了新欠账，实际全是自己的影子。

## 2. 命令

| 命令 | 作用 |
|---|---|
| `tvbox close [--dry]` | **统一收尾（九技能共用）**：采六源 → 分诊派单 → 落账 → 打印「本次完成/未完成」 |
| `tvbox close status` | 看当前欠账单（按 owner 分组、按期限排序） |
| `tvbox close done <id> <证据>` | 显式收口一笔（必须带证据，不接受空口） |
| `tvbox close defer <id> <理由>` | 显式延期（须给新期限 + 理由） |
| `tvbox close mine <技能名>` | 只看某个监察官名下的欠账 |
| `tvbox close mine <技能名> --before <文件\|关键词>` | **★ 改代码前必查账（P1 硬约束）**：账上有涉及它的未结欠账当场摊开，别改完才发现重做 |
| `tvbox close verify` | 欠账单自检（指纹对账 + 无主项 + 过期项） |
| `tvbox close promise "<承诺>"` | **登记会话承诺**——AI 答应了但还没做的（不登记就没人记得） |
| `tvbox close promise list` / `done <Cxxx> <证据>` | 看未收口承诺 / 收口一条 |
| `tvbox close link` | **四向联动验证**（技能↔技能/↔资料库/↔云端/↔规则，每向真实可达性） |
| `tvbox close --dry` | 只采集不落账（先看六源各报几条、有没有读失败） |
| `tvbox close learn biz "摘要"` | **写 ③ 会话台账**（业务经验）★M-R67 收口必落池 |
| `tvbox close learn plat "场景"` | **写 ④ 经验库**（平台经验） |
| `tvbox close learn status` / `today` | 双池最新编号 / 今日是否已落池 |

> **`learn` 只是转接，不是写入器**（S148）。真正的写入器是 `tvbox log` / `tvbox lib-log`
> （`tvbox-source-hub/scripts/link.py`），它们一直都在。这里只做参数转接：
> `biz` → `--summary`，`plat` → `--scene`。
> **禁止在此复制写入逻辑**（M-R38）：初版新建 `learn.py` 是重复实现，已删除。
>
> 为什么当初会误判「全生态 0 处写入」：grep 只查了 `DB_SESS`/`DB_LIB` 变量名，
> 而真实写入器是拼 `subprocess.run(['python3', .../batch_add_database_records.py'])`，
> 不含 `add_records` 字样。**判据错，结论就错**——见 M-R105。

### 为什么要有「第 7 源：会话承诺」

六源都在文件里，只有一种「没做完」不写在任何地方——**AI 在会话里答应的事**。
会话一结束上下文就没了，承诺随之蒸发，用户以为有人在做，实际没有任何账记着它。
所以有 `close promise`：登记是显式动作，不做这个动作就说明没打算真做，那正好应该被标出来。
**超期未收口的承诺直接判红**（比普通欠账更严，因为它消失了就再也想不起来）。

## 3. 六源采集规则

见 `scripts/collect.py`，每源一个 `collect_*` 函数，返回统一的 `Item` 结构：

```python
Item(sid, source, skill, title, kind, owner, next, due, evidence, signature)
```

- `signature`：`sha1(source|skill|title[:40])` —— 用于**跨次对账**，防「看不见了=已清零」
- 采集失败一律返回 `CollectError(source, reason)`，上层原样打印，**不吞**

## 4. 分诊规则（谁欠的活派给谁）

| 欠账性质 | 派给 | 判据 |
|---|---|---|
| 代码/检查器/本地文件缺陷 | `legacy-watchdog` | 标题含 检查器/脚本/bug/异常/伪/失效 |
| 路由/触发词/技能纳管/体积 | `ecosys-conductor` | 含 路由/触发/纳管/体积/SKILL/onboard |
| 技能能力/规则固化/招式 | `skill-evolution` | 含 规则/招式/进化/固化/承载 |
| 数据源/上游仓库/采料 | `probe-hub` | 含 源/仓库/上游/采集/线路 |
| 库结构/去重/整包 | `tvbox-source-hub` | 含 总库/入库/去重/整包 |
| 监测项/检查器有效性 | `tvbox-inspect` | 含 监测/proven/探针/信号源 |
| 云端节点/删除不了 | `tvbox-janitor` / `ecosys-conductor` | 含 云端/节点/删不掉 |
| 兜底 | `ecosys-conductor` | 无法判定归属 → 总指挥收口（**不许留空**） |

### 4.1 显式声明优先于关键词猜（M-R127）

上表全靠**标题关键词**判性质——但标题是给人读的自由文本，里头常写的是
**手段**而非**归属**。实测翻车：P030「备份系统三处遗留…③ 探针遗留物
`__uptest_s179.md`」只因末尾出现「探针」，被判 `code` → 派给
`legacy-watchdog`（代码遗留巡检），可它下一步是「**用户在客户端核对附件**」。

所以账本自己可以两路直通：

| 手段 | 写在 `issues_ledger.json` 的 | 效果 |
|---|---|---|
| 指定性质 | `"kind": "cloud"` | 跳过标题猜，直接定 owner/next/due |
| 指定下一步 | `"next": "用户在客户端核对…"` | **覆盖**命令模板；`tvbox janitor scan` 这类"跑一遍自欺"不许盖上人话 |

两者都没有才退回关键词猜，且把**猜出来的原值写进 `evidence`**
（`kind=route（标题猜·未声明性质，猜原值=route）`），事后一查就知道
分诊是不是被关键词带跑了。

> **判据**：能落到「等人做」「等外部确认」的欠账，**必须显式写 `next`**。
> 用命令模板兜底等于把"等人"伪装成"已安排动作"。

## 5. 与监察官的联动

```
                 ┌──────────────────────────────┐
   六源 ────────→│  unfinished-audit（清账司）   │
                 │  采集→去重→分诊→落账         │
                 └───────────┬──────────────────┘
                             │ 按 owner 派单
      ┌──────────────┬───────┴───────┬──────────────┐
      ▼              ▼               ▼              ▼
 legacy-watchdog  tvbox-inspect  skill-evolution  probe-hub ...
   （处置层）      （发现层）       （进化层）    （上游层）
      │              │               │              │
      └──────────────┴───────┬───────┴──────────────┘
                             ▼
                    收回 `close done <id> <证据>`
                             ▼
                   账本变绿 → verify 判据⑧通过
```

**闭环关键**：派单**不能只是打印一行字**。`close` 会把派单写进
`unfinished_ledger.json`，而 `verify` 判据⑧ 会检查「有没有无主项/过期项」——
不处置就等于验收过不了。
