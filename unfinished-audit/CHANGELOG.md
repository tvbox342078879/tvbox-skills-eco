## v1.4.7 — 无 sid 收口盲区：修了三层，最后一层才是真因（S158 九补）

### 一、事故：上一版写了 fallback，一行效果都没有

v1.4.6 我写下「需在 `_echo_close_to_backlog` 增加同标题 fallback 匹配」并记了账。
本版动手去修，实测发现**上一版根本没写 fallback**——真正的问题是函数第一行：

```python
if not (sid and owner):
    return          # ← 无 sid 直接 return，一声不吭
```

野生 backlog（从没被采集过、因而没有 sid）收口时：**不写、不报、不提示**。
人以为收口了，M03 下一轮照旧报它没清。

> 兜底代码写在 `return` 后面，**永远走不到**。
> 这解释了为什么我"改了"却"测不出效果"——我把改动放在了一条死路径上。

### 二、三层缺陷，逐层剥开

| 层 | 缺陷 | 后果 |
|---|---|---|
| ① | `if not (sid and owner): return` | 无 sid 的条目从不回写，静默 |
| ② | `_need_title = (not _sid_hit)`，按**整份** backlog 判 | 同技能里只要有一条派过单，其余野生条目全部兜不到底 |
| ③ | sid 命中后 `continue` | 同一件事的多份副本（sid 一份 + 野生一份）只标得掉一份 |

三层都修了。判据同时收紧：sid 命中**不再等于标对了**。

### 三、★ 新判据：sid 命中 ≠ 标对了

故障注入时撞出来的事故：

```
账本：title = 「jar 抽取链路缺失」
backlog：["（sid=EEEE77778888）别的完全无关的欠账"]
```

sid 对上了，标题毫无关系，**照样被标成"已清零"**。

> sid 是「账本 ↔ 副本」的**关联键**，不是"内容对不对"的证明。
> 关联键会写错、会被复用；拿它当内容的证明，等于拿门牌号证明屋里住的是谁。

现加判据：sid 命中 **且** 标题重叠 < 30% → **不标，喊出来**让人工看。
阈值 30% 明显低于兜底阈值 55%——sid 已是强证据，这里只拦"完全不像"。

### 四、★ 顺手挖到的真 bug：写完不关就回读

`json.dump(d, open(fp, 'w'))` —— 文件对象没绑定变量、靠 GC 关。
`open(fp,'w')` 先把文件**截断**，dump 往里写，而**回读发生在关闭/刷新之前**，
读到的就是自己写了一半的内容。

实测：回读稳定报 `JSONDecodeError: Extra data: line 5 column 2`。

> 这条一开始被我当成"测试脚本写坏了"，差点漏过去。
> 定性的关键：报错是 `Extra data`（两份 JSON 叠在一起），不是"文件不存在"——
> **叠在一起说明文件被写过两次**，其中一次没关。

同款缺陷共 3 处，全修（`with` + `os.replace` 原子替换，与 `_save_ledger` 同一姿势）：

| 文件 | 位置 | 修复前 | 修复后 |
|---|---|---|---|
| `dispatch.py` | `_echo_close_to_backlog` 写 backlog | 裸 dump + 立即回读 | `with` 写 tmp → `os.replace` |
| `link_eco.py` | 派单写对方 backlog | 同上 | 同上 |
| `promises.py` | `_save` 承诺落账 | 裸 dump tmp → `os.replace` → 回读 | `with` 包住 dump |

三处都**靠回读结果决定结论**，所以这个 bug 会让"写成了"被误判成"写坏了"，
或者更糟——被误判成"写坏了"之后人就不再相信回读，真正的失败也就看不见了。

### 五、验证（7/7，每条走各自设计的分支）

| # | 场景 | 期望分支 | 实测 |
|---|---|---|---|
| ① | 整份有 sid / 本条无 sid | 野生条目被标题兜底标 | ✅ `（无 sid·标题匹配93%）` |

### 二、为什么现有去重抓不到

`signature = sha1(source|skill|title[:40])`。这两条：
- source 不同（`promise` / `backlog`）
- skill 不同（`ecosys-conductor` / `probe-hub`）
- title 前缀不同（`[jar地址结构性缺口]` / `[遗留 S110]`）

**三要素全不一样 → 指纹必然不同。** 去重器对"换个说法再登记一次"完全无感。

### 三、判据怎么定的（试错过程如实记）

| 尝试 | 结果 | 问题 |
|---|---|---|
| Jaccard bigram ≥0.55 | **0 条**（漏报） | 两条 87 字 / 51 字，并集惩罚长度差，实测 0.26 |
| 交集/较短 ≥0.55 | 0 条 | 实测 0.54，差 0.01 |
| overlap 系数 ≥0.42 | 3 条（**全误报**） | 用 `skill` 过滤，而同一技能派出的单 skill 全一样 |
| 改按 `owner` 过滤 | **0 条**（又漏） | 那两条 `next` 不同（`watchdog scan` / `probe monitor status`） |
| **同 due + 不同 owner + overlap≥0.35** | **1 条，精准** | ✅ |

> 结论：**单一指标不够**。"同一个截止日 + 两个不同 owner + 讲同一件事"，
> 三条合起来才是真信号 —— 它说明同一根因被拆成两笔各自排期。
>
> 顺带记一个坑：`skill` 是"哪方写的这条"（写单方），`owner` 才是"谁该去干"。
> 我第一次用 `skill` 过滤，等于没过滤。

### 四、反例验证（三组）

| 注入 | 期望 | 实测 |
|---|---|---|
| 删掉重复项之一 | 归零 | ✅ 0 |
| 注入两条无关事项 | 不误报 | ✅ 仍 1 |
| 注入一对真重复（同 due/不同 owner/同描述） | 抓到新那对 | ✅ 2 |

### 五、只报警告，不自动合并

合并要先判"哪条是正本"，那是语义决策，**算法不该替人做**（做错了会把真账并掉）。

### 六、顺带修掉的呈现问题

`warnings` 原先在 CLI 里统一挂在「⚠️ 超期未处置」标题下 ——
重复项会被当成超期项读。已按类型分组（超期 / 疑似重复）。
另：`cmd_verify` 里旧循环与新增分组**各打印一遍**，告警重复显示，已删旧循环。

实测：`tvbox close verify` → `⚠️ 疑似重复 becf9081fdbc（legacy-watchdog）≈ 5e79eeb5ba4f（probe-hub）`
`✅ 无硬问题（1 项疑似重复仅告警）`

### 一、症状与成因链

```

32ec6b4325b4  「slim 对总册判 0 候选」  → 出现两次
```

成因是一条完整的回归链，三个环节各自都「看起来正常」：

1. 某一轮 `close` 把条目从 `items` 移进 `closed`；

3. 再 `close` 一次 —— `close_item()` 里那行 `db.setdefault('closed', []).append(hit)` **无条件执行**。

危害不是「多一行」。是**账目数字本身不可信**：`已结 8 条` 这个数会被人（和 AI）当成工作量读，
而里面 37.5% 是影子。清账司唯一对外交付物就是数字，数字失真等于交付物失真。

| 位置 | 改动 |
|---|---|

| `dispatch.verify_ledger()` | 新增判据：已结区出现重复 sid **判红**（不是告警）。理由是重复使数字不可信，属于硬缺陷 |

> 这修的不是「多一行」，而是**「账要能清」（M-R82）的最后一公里**：

### 五、`tvbox` 入口：失败被记成成功（已立 **M-R87**）

审计长期打印一句 `（须复核 exit code 区分假警报）`。这句话本身就该被当成缺陷——
它等于承认「我不知道这算不算失败」，然后把判断推给未来的自己。

真因两层：

- `safe_dispatch` 里 `except SystemExit: pass` 把退出码一起吞了。于是 `exit(1)`
  （**发现了问题**）在 journal 里记成 `ok=True` —— 方向整个反了；
- 清账司 `dispatch_cmd` 走的是另一条风格：吞掉异常后 `return 1`。入口只 `except Exception`，
  看不到返回值，于是 `return 1` 也记成 `ok=True`。

**实测证据**（注入损坏账本，让 `close status` 必失败）：

| 阶段 | journal 记录 |
|---|---|
| 修前 | `{"verb":"close","arg":"status","ok":true}` ← 账本已损坏却报成功 |
| 修后 | `{"verb":"close","arg":"status","ok":false,"exit":0,"err":"dispatch 返回 1（命令自报失败，非崩溃）"}` |
| 还原 | `{"verb":"close","arg":"status","ok":true,"exit":0}` |

改法：入口统一收集三证据 —— **①真实退出码 ②`dispatch` 返回值 ③异常类型摘要**，
任一非成功即判 `ok=False` 并写进流水。另加 `--strict-exit` 开关把真退出码传给 shell
（默认行为不变，零回归风险；CI/脚本需要判成败时显式启用）。

`audit-compliance` 也随之改为**直接显示证据**，不再打印「须复核」：
旧记录（无 `exit`/`err` 字段）如实标注「旧版入口记录·无法追溯真因」，不含糊其辞。

### 一、修掉的四个真 bug

**① 派单回声：账本自我增殖（最严重）**
