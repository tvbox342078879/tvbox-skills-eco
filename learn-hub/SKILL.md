# learn-hub（学习工坊 · 学习资料单类业务全能选手）

> **定位**：不是"流水线"，是**业务块的唯一归属地**。与探源司同构——
> 探源司管「TVBox 上游的源」，学习工坊管「学习资料的进、整、出、验、存」。
> 判断标准只有一条：**这件事属不属于"把学习资料做好"，属于就归我，不属于就转出去并说明转给谁。**

**成员中文名**：学习工坊（与 探源司 / 源枢库曹 / 质检闸 / 整包坊 / 遗迹哨 / 进化舵 / 总指挥 同构）。
**建制位次**：位于**资料一侧**——与「探源司」并列，探源司对**外**（上游源），学习工坊对**内**（学习资料）。

## 1. 用途：四梁八柱

> **"全能选手"不等于"什么都能做"**。全能指的是：这一类业务里，**任何一个环节出问题都能在我这里找到入口**，
> 而不是每个环节都自己重写一遍。**自己重写 = 造第二个事实源，比缺功能更坏。**

| 模块 | 职责 | 输出去哪 |
|---|---|---|
| **intake 采集** | 公众号文章 / 网盘资料 / 本地文档 / PDF / 扫描图 / 网页 / 音视频 | `materials/` 统一收纳 + `manifest.json` |
| **sort 分类整理** | 去重 → 切知识点 → 建层级 → 标难度 → 归章节 | `outline.json`（知识点树） |
| **forge 特有工具库** | 学情诊断 / 记忆曲线排程 / 检索回查 / 资料体检 | 见 §3.4 |
| **gate 质检闸** | 覆盖率 / 答案自洽 / 难度分布 / 无出处单列 | 不通过不出品 |
| **store 入库** | 成品归档、可检索、可复用、可追溯来源 | `library/` + 索引 |
| **watch 监测** | 素材源存活、文章更新、网盘失效、版本漂移 | 变更摘要 |

**核心命题**（用户原话·2026-10-19）：
> "学习工坊以后还要加入公众号文章处理，网盘资料处理，本地文档处理等功能，
> 他的定位和探源司一样，是一个**单类业务板块的全能选手**"

**推论（三条，必须守住）**：

1. **加功能不叫升级，加判据才叫升级**。又多支持一种格式，只是"能吃了"；能判断"这类素材质量够不够用"才是升级。
2. **每接一个新来源，必须同时回答"它为什么会坏"**。公众号会删文、网盘会 412、本地文档会编码乱。
   不知道它怎么坏，就等于没接。
3. **不与子技能抢活**。出卷有 `exam-generator`，框架有 `knowledge-framework-builder`——
   **我编排它们，不替代它们**；我只管它们都不管的那段：**跨来源的整合与全链质检**。

## 2. 触发词

**术语类**：学习资料 · 学习工坊 · 知识点切分 · 学情诊断 · 资料体检 · 覆盖率 · 记忆曲线 · 素材库

**业务语言类（用户不会说术语，说的是需求）**：
把这几篇文章做成一份资料 · 这个网盘里的课能不能整理成笔记 · 我这堆 PDF 太乱了 · 这份资料能不能直接拿来背 ·
帮我看看这套复习资料全不全 · 这个知识点讲过没有 · 我孩子这块为什么老错 · 下次什么时候复习 ·
这份资料哪里来的 / 靠不靠谱 · 这些东西能不能串成一条线

> 当用户提到以上任一，或**手上有一堆散素材想变成能用的东西**、**怀疑现有资料有漏/有编造**时触发。

### 2.1 ★ 铁律一：不许凭空生成"资料"（M-L01）

**病根**：学习资料最容易出的错不是"生成不了"，是**"生成了看起来很像的东西"**——
讲义里有这段话，但原文没有；题目有答案，但原文推不出来。**用户拿去背，背的是错的。**

**判据**：**每一条产出都必须能指回原文的具体位置**（文件 + 段落/页/时间戳）。
指不回去的，不许写成正文，只能写成"⚠️ 无出处（推测）"并单列。

**硬约束**：
1. 生成时逐条记 `source_ref`，**没有 ref 的不进正文**；
2. 交付时报「N 条有出处 / M 条无出处」，**不许只报总数**；
3. 无出处条目在成品里**必须可见**（醒目区块），不许静默删掉——删掉是另一种骗人。

### 2.2 ★ 铁律二：覆盖率是分母问题，不是分子问题（M-L02）

**病根**：说"这套资料覆盖了 90% 的知识点"，但没人知道**分母是哪来的**。
分母若是模型自己编的知识点表，90% 就是自说自话。

**判据**：分母必须**来自外部**——教材目录 / 考纲 / 用户给的框架 / 已入库的 outline。
**没有外部分母时，覆盖率这个数不许报**，只能报"生成了 N 条内容，未做覆盖评估"。

### 2.3 ★ 铁律三：三态不折叠（M-L03·继承探源司）

采集失败分三种，**不许合并成"失败"**：

| 态 | 含义 | 处置 |
|---|---|---|
| **取到了** | 拿到了内容且可解析 | 进下一步 |
| **确定取不到** | 404 / 已删 / 明确拒绝 | 记死因，可换源 |
| **无法判定** | 超时 / 412 / 登录墙 / 编码异常 | **不许当失败**，重试或标注待人工 |

> 实例（S171 实测）：网盘 412 不是"文件坏了"，是机房 IP 被 CDN 拒——归因错，处置就全错。

### 2.4 ★ 铁律四：用户编号选项引用约定（M-R109·全局）

单个数字/字母/复合编号（`1`、`b`、`2.1`）默认指代**我最近一次回复中的对应选项**，直接执行；
仅当有歧义或涉及不可逆操作时才澄清。

## 3. 用法（引擎 `scripts/learn.py`）

### 3.1 intake 采集

```bash
learn intake file <路径...>            # 本地文档：pdf/docx/md/txt/epub/图片
learn intake url <链接>                # 网页/公众号文章（自动分诊：正文页 vs 列表页 vs SPA）
learn intake pan <分享链接>             # 网盘（复用探源司 pan；412 单列不并进失败）
learn intake scan <目录> --recursive   # 目录批量收，先出清单再决定收不收
learn intake list                      # 盘点已收素材（按来源/类型/时间）
```

**统一落地**：`materials/<日期>_<来源>_<短名>/` + `manifest.json`（原路径/大小/哈希/采集时间/三态结果）。

**判据**：
- 同一文件按**内容哈希**去重，不按文件名（改名包很常见，S170 实测 4 个 apk 里 2 个是改名的 zip）；
- 采集失败**逐条给原因**，`412/超时/登录墙` 归"无法判定"，不归"失败"；
- 收完先出**清单**，人确认后再进下一环（避免几百个文件全跑一遍才发现收错目录）。

### 3.2 sort 分类整理

```bash
learn sort outline <素材目录> --from <外部框架>   # 按外部框架建知识点树（分母来源）
learn sort auto <素材目录>                        # 无外部框架时自动切分（结果须标注"自建分母"）
learn sort dedupe <素材目录>                      # 近重复检测（同一份资料多个版本）
learn sort difficulty <outline.json>              # 标难度（基础/进阶/拔高 + 依据）
```

**判据**：
- `outline.json` 每个节点必须带 `evidence`（出自哪份素材的第几段）；**无 evidence 的节点标 `unverified`**；
- 自动切分的树**不能当作覆盖率分母**（见 M-L02），只能当"素材里都有什么"的概览；
- 难度标注必须给**依据**（题面长度/是否含公式/是否多步推理），不许只给标签。

### 3.3 gate 质检闸（★本技能的立身之处）

```bash
learn gate run <outline.json> <成品目录>   # 四查：覆盖率/答案自洽/难度分布/无出处
learn gate coverage <outline> <成品>       # 单查覆盖率（分母须外部）
learn gate grounding <成品>                # 单查出处：每条能否指回原文
learn gate ratio --expect <分布>           # 难度分布是否偏离
```

**四查，任一不通过即不出品**：

| 查什么 | 怎么查 | 不通过的典型症状 |
|---|---|---|
| **覆盖率** | 外部框架节点 → 成品里能否找到对应内容 | 缺章、整节没讲 |
| **出处** | 每条产出 → `source_ref` 是否真实存在 | 编造段落、张冠李戴 |
| **答案自洽** | 题目答案 → 能否从引用的原文推出 | 答案对但原文不支持；或答案与原文矛盾 |
| **难度分布** | 实际难度 vs 声明难度 | 标"基础"的题要三步推理 |

**验收格式（强制）**：
```
质检结果：覆盖 42/48（缺 6，逐条列出）｜有出处 137/140（无出处 3，已单列）
          ｜答案自洽 39/42（3 条原文不支持）｜难度偏离 5 处
判定：❌ 不通过 —— 覆盖率未达 95%、有 3 条无出处。
```
**不许写"质检通过"四个字就完事。**

### 3.4 forge 特有工具库

> 这三个工具是"学习"这类业务**独有**的，TVBox 那套没有，别的技能也没有。

| 工具 | 解决什么 | 判据 |
|---|---|---|
| `forge diagnose` **学情诊断** | 错题 → 归因到知识点 → 找薄弱链路 | 归因必须落到 outline 的**具体节点**，落不到就说"无法归因"，不许硬套"基础不牢" |
| `forge schedule` **记忆曲线排程** | 按遗忘曲线排出复习计划 | 间隔依据必须可查（SM-2 或明确的自定公式），不许"感觉差不多" |
| `forge check` **资料体检** | 现有资料的老化/失效/矛盾检查 | 教材改版、课标变动、来源失效三类，逐条给证据 |

### 3.5 store 入库

```bash
learn store put <成品目录> --tags ...     # 归档 + 建索引（可检索：按知识点/来源/难度）
learn store find <关键词>                 # 找已有资料，避免重复造
learn store trace <成品>                  # 回溯：这份成品用了哪些素材、哪次采集
```

**判据**：`store find` 命中高度相似内容时，**先提示"已有"，不直接新建**——重复造资料是最大的浪费。

### 3.6 watch 监测（对标探源司 monitor）

```bash
learn watch sources          # 素材源存活：公众号是否删文、网盘是否失效、链接是否还在
learn watch refresh          # 已入库资料的上游是否有更新（教材改版/文章修订）
learn watch stale --days 180 # 多久没更新的资料
```

**判据**：监测结果三态（在/已失效/无法判定），**"无法判定"不许写成"已失效"**。

## 4. 联动（大生态 / 小生态）

### 4.1 与子技能的分工（不抢活）

| 用户想干的事 | 归谁 | 我在其中的角色 |
|---|---|---|
| 出一套卷子 | `exam-generator` | 我供知识点树 + 质检产出 |
| 搭知识框架 | `knowledge-framework-builder` | 我供素材，它出框架；**它的框架可当我的覆盖率分母** |
| 做备课 PPT | `office-kejian` | 我供结构化内容 |
| 错题/练习 | `exam-paper-generator` | 我供学情诊断结果 |
| 单文件转换 | `pdf-converter` / `scan-pdf-ocr` | 我调用，不重写 |
| 公众号抓取 | `wechat-article-*` | 我调用，不重写 |
| **多源整合成一套可用资料** | **本技能** | — |
| **这份资料全不全 / 有没有编造** | **本技能** | — |

**判据**：用户要的是**单点产出**→ 转出去；要的是**跨来源的整合或全链质检**→ 我来。

### 4.2 数据流

```
intake ──► materials/ + manifest.json（三态）
   └─► sort ──► outline.json（带 evidence）
        └─► [生成：本技能 or 子技能]
             └─► gate 四查 ──❌──► 回炉（逐条列出问题）
                        └─✅──► store 入库 ──► 索引可检索
watch ──► 源失效/内容更新 ──► 提示重生（不自动覆盖，人确认）
```

- **上游**：`library`（云读写）、`probe-hub`（网盘取料 `pan` / 容器 `pak`）
- **下游**：无强依赖（本技能是资料业务的终点站）
- **横向**：`exam-generator` / `knowledge-framework-builder` / `office-kejian` / `pdf-converter` / `scan-pdf-ocr` / `wechat-article-*`

### 4.3 责任田（大生态接入·必填）

新建技能若不声明 `TERRITORY`，它的产出**天然成为"缝"**（无主区，见总指挥 §3.5 三层一缝）。
本技能的责任田：

| 区 | 路径 | 说明 |
|---|---|---|
| 素材区 | `learn-hub/materials/` | 采集落地，按 `日期_来源_短名` |
| 成品区 | `learn-hub/library/` | 通过质检的成品 |
| 索引区 | `learn-hub/scripts/index.json` | 检索索引（机器可读） |
| 过程区 | `learn-hub/work/` | outline / 中间产物（可清理） |

## 5. 持续优化（与探源司同构的进化通道）

> 用户原话："以后还会像探源司一样不断优化"。**优化不是"加功能"，是"把这轮吃过的亏变成尺子"。**

### 5.1 三轮驱动的进化闭环

| 驱动 | 触发 | 产出 |
|---|---|---|
| **亏驱动**（主） | 任何一次交付发现错/漏/假绿 | 一条判据 + 一条探针，写进 §3 与 `self-check` |
| **源驱动** | 接一个新来源（公众号/网盘/新格式） | 该来源的**坏法清单** + 三态分诊规则 |
| **用户驱动** | 用户说"这块不对/我不满意" | 归因到具体判据，改判据不改文案 |

**硬约束**：**每轮必须留一条可复验的探针**。只改文档不加探针 = 没优化（下次还会犯）。

### 5.2 自检

```bash
learn self-check      # 跑全部命门探针，输出 N/N
```

每条探针必须能**被注入破坏后抓住**（S171 教训：探针与被检代码同居一文件会自己判自己通过，
故探针一律用 AST 只取目标函数字面量）。

## 6. 升级契约（规则 48 + 54 三件套）

- 顶部 `version` + 本 `CHANGELOG.md` + `scripts/flow.json` 三件套齐备。
- 版本提升：`tvbox evolve upgrade learn-hub`。
- ⚠️ 本技能**非 `tvbox-` 前缀** → `evolve scan` 靠目录扫描可能扫不到，
  **必须** `register_eco` 登记进生态库（DB_ECO）才会被进化引擎发现。
