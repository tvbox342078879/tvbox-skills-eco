## v1.0.0 — 学习工坊立项（S172）

### 起象：一句"和探源司一样"

用户原话：

> 「学习工坊以后还要加入公众号文章处理，网盘资料处理，本地文档处理等功能，
> 他的定位和探源司一样，是一个**单类业务板块的全能选手**」

这句话里有两件事要分开听：

1. **"加入更多格式"** —— 这是能力清单，加条目容易。
2. **"和探源司一样"** —— 这是**结构要求**：有责任田、有铁律、有三件套、每轮沉淀判据。

第二件才是难的那件。所以这一版**不是先把公众号/网盘/本地文档都接上**，
而是先把这个"业务块的骨架"立起来：六环 + 四条铁律 + 四查验收格式 + 15 条自检探针。
**格式可以后加，判据必须先有**——不然接一堆格式，只是"能吃"，不知道"吃进去的是不是坏的"。

### 立了什么

| 环 | 命令 | 一条判据 |
|---|---|---|
| intake 采集 | `file / url / pan / scan / list` | 按**内容哈希**去重，不按文件名（改名的包很常见） |
| sort 整理 | `outline / dedupe / difficulty` | 归一化**双侧同归**，单边清洗 = 假匹配 |
| gate 质检 | `run / coverage / grounding / ratio` | **四查逐项报数**，禁止"质检通过"四个字结案 |
| forge 工具 | `diagnose / schedule / check` | 归因落到具体节点，落不到就说"无法归因" |
| store 入库 | `put / find / trace` | 先找后建，重名不覆盖 |
| watch 监测 | `sources / stale / refresh` | 无法判定 ≠ 已失效 |

### 三条铁律的由来（不是抄的，是"这类业务真会犯"的）

- **M-L01 不许凭空生成**：学习资料最要命的错不是"生成不了"，是**生成了看起来很像的东西**——
  讲义里有这段话，但原文没有。用户拿去背，背的是错的。所以每条产出必须 `source_ref` 指回原文。
- **M-L02 覆盖率是分母问题**：说"覆盖 90%"，但没人知道分母哪来的。分母若是模型自己编的
  知识点表，90% 就是自说自话。**没有外部分母，这个数不许报。**
- **M-L03 三态不折叠**：直接继承探源司。网盘 412 不是"文件坏了"，是机房 IP 被 CDN 拒。

### 这一轮踩的坑（比功能本身更值得记）

写引擎加探针，一共 15 条探针，**前 8 条里有 6 条第一版是假的**。逐个记：

| # | 假在哪 | 真相 |
|---|---|---|
| ㉔类 | 查"函数里有没有某个字面量" | 字面量可能只出现在**报错文案**里，判定条件删了文案还在 |
| ⑤ | 测 `sha256_file` **工具函数** | 工具没问题不代表**调用点**用了它。改 `cmd_intake` 按文件名去重，照过 |
| ⑥ | `'__NUXT__' in l6 or 'vite' in l6` | 同一正则的两个并列分支，**OR 判据等于没判**（删一个另一个还在） |
| ⑦ | 只验"412 返回 unknown" | 末尾 `return ST_UNK` 兜底也会给 unknown，**验不出 412 有专门判据** |
| ④ | 对整函数取字面量**并集** | `'不通过'` 在 coverage/ratio 分支也有，删掉 grounding 那个，并集里还剩 |
| ⑮ | 在探针里**自己重算一遍序列** | 那是在验探针自己。改实现为 `append(seq[-1])` 照样过 |

**共同病根只有一句：判据没有落在执行路径上。**

S171 已经定过一条（"探针与被检代码同居一文件会自己判自己通过"），
我照做了——改用 AST 取目标函数字面量。**但 AST 只缩小了取样范围，没解决"这个字面量是不是判据"。**
所以这一轮要再进一步：

> **判据的三条硬要求**（写进 flow.json 自检末条）
> 1. 取自**执行路径**，不取自说明书（报错文案里的字不算）；
> 2. 不许用「字面量存在 = 功能存在」；能行为测就行为测（喂输入看返回）；
> 3. 不许查**一个自己会说的话**（提示语里写着"不许报归因 0 条"，那串字本身就会命中）。

### 端到端实测抓到的 6 个真缺陷

这些不是推演出来的，是真跑 `/tmp/e2e` 抓到的：

1. **`sort outline` 有出处 0/6** —— 素材是 `# 第一章`，标题被 `lstrip('#')` 洗过，
   `find` 永远对不上。**归一化双侧同归**才修好。
2. **`sort difficulty` 崩** —— `_save_json('outline.json')` → `dirname` 得 `''` → `makedirs('')` 抛。
3. **`gate coverage` 又是 0/6** —— 归一化在 gate 里被**重写了一遍**，修了 sort 没修 gate。
   这正是 M-R38「同一判据只许一份实现」要防的：**修一处、漏一处，等于没修**。
4. **`forge diagnose` 归因 0/4** —— 拿带编号的标题整串去做 `in` 匹配，撞不上。改 2-gram 重叠。
5. **`forge diagnose` 路径写死** `work/outline.json` —— 换成别处的 outline 就 `titles=[]`，
   于是报「归因 0 条」。**这种错最毒：它给了一个很具体的数，让人以为是分析结果。**
6. **`forge schedule` 输出「第1天 → 第1天」** —— `d = 1 if i==0 else ...` 把 d 又设回 1。

### 探针从 10 条加到 15 条（后面 5 条是补漏）

| 探针 | 补的是什么 |
|---|---|
| ⑪ 归一化双侧同归 | 带 `#` 的素材 vs 带 `#` 的标题必须能对上；框架多出的章节必须 unverified |
