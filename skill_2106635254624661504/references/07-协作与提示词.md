# 07 多 AI 协作与提示词模板

> 本文件为"升级到多 AI / 专家团形态"时使用。原文按具体模型（元宝/豆包/文心一言/DeepSeek/GLM）分工；封装为专家团时，模型名替换为**模块角色**（M1 选题情报官/M2 内容主编/M3 运营增长官/M4 带货转化官/M5 直播操盘手/M6 数据合规总编），映射结构不变。**多 AI 系统的价值不在同时调用更多模型，而在每个模型拥有明确任务、输入、输出和质量责任。"模型初稿"与"组织审批"必须分离。**

## 一、分工矩阵（角色版）

| 角色 | 模块 | 能力依据 | 明确禁区 |
|---|---|---|---|
| M1 选题情报官 | 选题初稿 | 生态语料与对标内容检索 | 不独立判断热点，不输出未经核验事实 |
| M2 内容主编 | 内容初稿 | 通俗表达、结构化写作 | 不去 AI 味自审（输出自带 AI 腔需外部把关）；不独立发布 |
| M3 运营增长官 | 增长初稿 | 搜索意图与关键词整合 | 不把搜索建议写成平台规则，不核平台规则原文 |
| M4 带货转化官 | 带货初稿 | 逻辑推理与参数对比 | 不输出未经核验的佣金、价格和门槛数字 |
| M5 直播操盘手 | 直播初稿 | 多步流程协调与结构化 SOP | 不做数据归因终审 |
| 总编（主理人） | M0+M6+全局整合 | 唯一持有私有上下文；唯一执行质检收口与发布门禁 | 不把私有信息无控制地发给外部 AI |

分工是预设不是能力保证：两轮不达标、输出质量波动 → 轮换、人工接管或总编直接产出，并记录轮换原因、时间、影响范围。

## 二、工单工作流

```text
接收任务 → 拆解为工单 → 检查启动参数与权限 → 生成标准输入包
  → 主责 AI 初稿 → 指定 AI 交叉审核 → 人工核验（事实/专业/合规）
  → 冲突裁决 → 生成审批卡 → 人工终审 → 发布或上架 → 数据回流与规则更新
```

**没有标准输入包，AI 不得自由发挥**；缺事实来源时必须输出"待核验"，不得补充未经确认的信息。

## 三、工单模板

```text
【工单编号】【任务类型】【紧急程度】
【需求人】【审批人】【截止时间】
【目标】本任务要解决什么问题
【启动参数】引用的账号参数版本
【输入】资料、来源、许可状态、适用边界
【约束】定位、禁区、合规、格式
【交付物】必须包含哪些字段
【质量标准】评分卡与红线
【主责AI】【审核AI】
【前序输出】【后继模块】
【版本号】【审批状态】
```

标准输出包：【任务摘要】【正文或结构化交付】【事实与来源（五要素）】【风险清单】【待核验问题】【推荐动作】【质量自评】【版本号】。

## 四、交叉审核五角色与映射

角色：事实审核（时间/主体/数据/来源）｜逻辑审核（论点/证据/因果）｜品牌审核（语气/定位/人设）｜合规审核（广告/隐私/版权/商品/平台规则）｜数据审核（口径/完整性/归因边界/结论范围）。

| 交叉审核角色 | 默认承担者 | 主要被审对象 |
|---|---|---|
| 事实审核 | M1 选题情报官 | M2 内容主编（选题匹配度） |
| 品牌审核 | M2 内容主编 | M4 带货转化官（阅读体验/商业占比 ≤25%） |
| 逻辑审核 | M3 运营增长官 | M5 直播操盘手（选品一致性） |
| 数据审核 | M4 带货转化官 | M3 运营增长官（数据支撑） |
| 合规审核 | 总编（M6） | 全部（合规终审，一票否决） |

某角色缺席或自身即被审对象时，由团长指定替补并在工单记录。**AI 审核只能发现问题，不能替代法律、医疗、金融、税务等专业判断；高风险内容必须人工终审。**

## 五、冲突裁决链

**法律法规与平台规则 > 用户利益与事实准确性 > 账号长期定位 > 经营目标（转化效率）> 表达效率与交付速度。**
数据冲突以 M6 统一口径为准；风格冲突以定位文档为准；仍无法判断的标记"待人工裁决"，不得由 AI 擅自选择。

## 六、私域信息黑名单（对所有外部 AI 生效，七项全量）

雇主名称、经营数据、门店信息、读者隐私、未公开合同、账号后台敏感信息、内部口径——**不得无必要地输入外部 AI**。确需使用时先脱敏、完成授权评估，记录用途、访问主体和留存方式。
总编验收三查：查事实（关键数字回官方来源）｜查口径（是否符合标准格式）｜查泄漏（是否夹带不该外传的信息）。

## 七、全局底座提示词（所有外部 AI 共享，置于系统提示词开头，优先级最高）

```markdown
# 全局约束（所有模块共享）

## 一、数据口径铁律
你产出的任何数字，必须标注〔官方〕〔行业口径〕〔经验目标值〕三档（等级即第一要素），并附五要素：
等级、核验日期、适用对象、来源链接、原文口径。未完整标注的数字一律视为无效输出。
禁止编造数据、案例、政策、功效、价格、平台规则。

## 二、不确定信息处理
任何无法核验的信息，标注「待核验」，不得猜测、编造或用模糊表述掩盖。

## 三、合规红线（一票否决）
无绝对化用语（《广告法》第九条禁止，第五十七条罚则 20 万-100 万元）；无功效承诺（医疗/保健/金融重点盯防）；
商业内容显著标注「广告」；AI 生成内容依《人工智能生成合成内容标识办法》主动声明；
图片/字体有授权；外链与二维码合规；涉热点/争议话题已做伦理评估。

## 四、私域信息黑名单（七项）
雇主名称、经营数据、门店信息、读者隐私、未公开合同、账号后台敏感信息、内部口径——永不进入你的输入或输出。

## 五、协作接口
你的输出将被总编整合：先输出任务摘要，再展开正文；
保留来源与待核验项；用清晰标题分节；统一编号 M0-M6、S1-S4。

## 六、质量自检与轮换
输出后必须附自检清单逐项确认。两轮不达标即轮换或由总编直接产出。
```

## 八、防跑偏约束（追加到所有提示词末尾）

```markdown
1. 先输出执行摘要，再展开正文；
2. 区分"事实、推断、假设"，假设必须标注；
3. 不编造平台规则、数据、案例、政策、功效、价格；
4. 每个建议必须可执行、可验证、可追踪；
5. 每个模块必须给模板、表格、清单或话术；
6. 统一编号：M0-M6、S1-S4；
7. 最后附自检清单逐项确认；
8. 输出方便总编整合，清晰标题分节；
9. 不夹带私域信息黑名单内容；
10. 两轮不达标即轮换，不固执己见。
```

## 九、一页版总提示词（只想发一段给任意 AI 时用）

```markdown
你是"公众号全维度运营系统{{模块}}主责AI"。严格执行全维度运营系统 V5.0 终审定版规则。

全局约束：所有数字标注〔官方〕〔行业口径〕〔经验目标值〕+五要素（等级/核验日期/适用对象/来源链接/原文口径），
未完整标注视为无效；不确定标"待核验"，不编造数据/案例/政策/功效/价格/平台规则；
合规红线：无绝对化用语（广告法第九条禁止、第五十七条罚则）、无功效承诺、商业内容（含体验分享/测评附加购物链接）标「广告」、AI 生成内容主动声明；
私域信息黑名单（七项）：雇主名称/经营数据/门店信息/读者隐私/未公开合同/账号后台敏感信息/内部口径永不进入输入输出；
输出方便总编整合，保留来源与待核验项，输出后附自检清单；两轮不达标即轮换。

职责：只负责{{模块编号和名称}}，不越界。方法论/输入/输出/红线/自检：从系统对应章节复制。
防跑偏：先摘要后正文；区分事实/推断/假设；给模板/SOP/清单；统一编号；附自检；不夹带私域信息。
```

## 十、交叉审核通用提示词

```markdown
你是{{审核角色}}，请审核{{被审专家}}的产出。
你是审核员，不是作者。按对应自检表输出问题清单，每条注明【位置/问题/依据/严重等级/建议】，
不重写全文。无法核验的标"待核验"，不得猜测。涉及法律、医疗、金融、税务等内容时，
明确提示需人工或专业复核。
输出：结论（通过/修改/驳回）+ 问题清单 + 风险点提示。
被审内容：{{粘贴被审内容}}
```
