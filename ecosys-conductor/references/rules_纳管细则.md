## ask 字段（S148）：从「该守什么」到「用户会怎么问」

**病根**：108 条规则**全部只有 `summary`**——那是维护者视角的结论句（「批量入库判重只用库内快照」）。
用户不会这么说话，他说「我把这批源一次导进去，怎么还是有重复」。中间没有任何桥梁，
规则写得再准，也全靠**在场的人恰好想起来**。

**两个字段的分工**：
| 字段 | 视角 | 回答 | 谁写 |
|---|---|---|---|
| `summary` | 维护者 | 该守什么 | 立规则时写 |
| `ask` | 用户 | 他会怎么问（2–4 句，禁术语） | 同上，**必填** |

**写法约束**（违反即返工，`rules check` 会报）：
1. 用用户口吻，**不出现术语**（不说 bigram/三态/幂等/指纹）；
2. 是问题形态，不是命令形态（「怎么会这样」>「必须三态」）；
3. 覆盖不同问法：有人问现象、有人问原因、有人问怎么避免；
4. **不得照抄 summary 换几个字**——那是假补（字段有了，用户还是问不中）。

```bash
tvbox conductor rules --ask "我把这批源一次导进去怎么还是重复"   # 按用户话找规则
tvbox conductor rules --ask-coverage    # 覆盖率 + 是否照抄 summary（>0.8 判雷同）
tvbox conductor rules --ask-golden      # 黄金用例回放（独立话术，非 ask 原文）
```

**打分口径 `_score_rule`**：`ask命中×1.5 + summary命中×1.0 + 具体坑+1`。
为什么不能只用通用 bigram 分：方法论类规则 summary 数百字，bigram 池比 8 字的具体坑大一个数量级，
导致**具体规则被泛化规则淹没**（实测 L025 与 L023 同分 4.0 分不开）。

**验证教训（这一节比结论更值钱）**：
- 拿每条自己的 `ask` 考匹配 → 108/108，**这是自测自绿，毫无信息量**（第二次踩）；
- 换人工另写的 41 条话术 → 真实 **28/41**；
- 针对用例调 `ask` 刷到 41/41 → **这是照考题改答案**，不算验证；
- 最后用一批**从未参与调优的新话术**重考 → **10/10**，这一层才是证据。

**守它的检测器**：`rules check` 第 5 项 + 信号源 33（缺失/雷同**双注入**探针 + 假阳性基线）。

注册表是唯一事实源（M-R38），回灌会覆盖后续手工改进。
