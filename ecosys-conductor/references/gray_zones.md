# 灰色地带处置（gray_zones）

> **来源：对 skills 目录、monitors.json、unfinished_ledger、settings.json 的实测。**
> 这些是"大生态方案"原先没覆盖的六处。**不处置就会在改造中变成新的假绿。**

---

## 灰 1 · 3 个符号链接

**实测**

```
/root/.codebuddy/skills/library                     → 链接
/root/.codebuddy/skills/workbuddy-office-routing    → 链接
/root/.codebuddy/skills/workbuddy-local-office-edit → 链接
```

**为什么会坏事**

- `os.listdir` 会把它们当技能，`os.walk` 默认不跟随 → **数出的技能数虚高**
- `git add` 会存成链接字符串 → **换机器就断**

**处置**

```
① 扫描时用 os.path.islink() 单独识别
② 技能数统计只算"实体目录"，链接单列
③ registry 里标 "type": "symlink"
④ git 里保留（平台需要它们），但不参与技能计数
```

**验收**：`tvbox eco state` 输出 `完整 59 / 无正文 2 / 链接 3 / 空 0`，四类相加 = 64。

## 灰 2 · 2 个目录没有 SKILL.md

**实测**

```
skill_2103442534925787136   （技能列表显示为 de-ai-flavor）
skill_2095616110808244224   （技能列表显示为 multi-wordcheck）
```

**为什么会坏事**

按"有 SKILL.md"当唯一判据扫描 → 这两个被漏掉 → 它们永远不入账。

**处置**

```
① 扫描判据改成"有目录 && 有任意内容"
② 分四类：完整（有 SKILL.md）/ 无正文（有文件无 SKILL.md）/ 链接 / 空
③ "无正文"类要报出来，标注"需确认是否半成品"
```

**验收**：这 2 个出现在"无正文"类，不被静默吞掉。

## 灰 3 · 16 个监测项无法自动检测

**实测**

```
monitors.json 共 43 项
其中 check=manual_track 的 16 项：
  M23/M24/M25/M28/M33  升级后回退风险
  M29 黑名单新失效类型
  M31 上游新失效模式
  M36 账实/账账不符
  M37 体积破缓冲线
  M38 停用探针未清理
```

**为什么会坏事**

如果把这 16 项算进"监测项总数"，任何依赖这个数的等式都会**永远差 16**，最后只好加个"豁免"把它抹平 —— 又变成假绿。

**处置**

```
① 拆两本：auto 27 / manual 16
② 等式只用 auto
③ manual 单独统计为"需人工复核"，不算失败也不算通过
```

**验收**：`eco check` 里看到 `监测项 auto 27（等式用）/ manual 16（人工复核）` 两个数，不是一个 43。

## 灰 4 · 3 类豁免没有到期时间

**实测**

```jsonc
"waiver_keywords": ["索引", "清单", "追踪表", "可用底包"]        // 4 条
"ledger_waiver":  { "entries": [...5 条...] }                  // 5 条
"ws_name_waiver": ["工作区常用入口.md", "S1"..."S5"]            // 6 条
```

**为什么会坏事**

豁免本身没错，但**没有到期机制** —— 2026 年 10 月的豁免，2027 年还在生效。这正是 M-R16 说的坑。而且它会让"通过率"虚高。

**处置**

```
① eco check 单列豁免数：豁免 15 条
② 每条豁免必须有 expires 字段；没有的报"无到期豁免 N 条"
③ 通过率计算：实际通过 = 检测通过 - 豁免数，两个数都报，不许只报一个
```

**验收**：输出里有 "豁免 15 条，其中 9 条无到期时间 ⚠️"。

## 灰 5 · 探针快、verify 慢

**实测**

```
rule_probe 全量 9 条        0.8 秒   ✅ 可进钩子
tvbox now                   0.0 秒   ✅
tvbox ledger audit-call     2.2 秒   ⚠️ 勉强
conductor verify 十二判据   几分钟   ❌ 绝不进钩子
```

**为什么会坏事**

把 verify 放进 `PostToolUse` 钩子 → 每次改文件卡几分钟 → 会话无法对话（正是 M-R120 要防的）。

**处置**

```
① 钩子只跑"单条技能的自检"，不跑全量
② verify / assess 只人工触发
③ 钩子必须有超时（建议 10 秒），超时即放弃并提示"未验证"
```

**验收**：改一个文件后，钩子总耗时 < 10 秒。

## 灰 6 · 26 项未完成全部 open

**实测**

```
unfinished_ledger.json：items 26 项，status 全部 open，closed 0 项
其中 2 项是同一件事写了两遍（台账回写线缺口）
```

**为什么会坏事**

这本账**自己就是"只增不撤"的活例**（M-R29）。26 项全 open 说明**没有任何东西在关闭它**。如果直接"批量关闭"，会把没做完的也关掉。

**处置**

```
① 先逐项确认：真欠账 / 已完成未关 / 重复登记
② 已完成未关的 → 标 closed 并写证据
③ 重复的 → 合并，保留信息多的那条
④ 真欠账 → 保留，补 owner / next / due（M-R79 三重必填）
⑤ 全程不许删除记录
```

**验收**：26 项分成三堆，每堆有明确归属，且 `closed` 项带证据。

## 七、这六条与 11 条硬禁令的对应

| 灰 | 对应禁令 | 关系 |
|---|---|---|
| 灰 1 符号链接 | M-R60 | 数错 = 把"不存在"当成"存在" |
| 灰 2 无正文 | M-R80 | 漏扫 = 静默蒸发 |
| 灰 3 manual 16 | M-R113 | 无法自动检测的混进自动数 = 语义不符 |
| 灰 4 豁免无到期 | M-R16 | 预豁免只凭状态放过 |
| 灰 5 探针快慢 | M-R120 | 慢命令前台跑 = 会话锁死 |
| 灰 6 26 项 open | M-R29 | 只增不撤 |
