## v1.4.0 — `commit` 加回读闸门：标 done 前先回读技能（S182）

### 问题：`commit` 说「已吸收」，但它从未回读过技能

`evolve commit` 原来只做四件事：改 frontmatter 版本号、CHANGELOG 追一行、写 note、登记 ECO + 监测项。
**不碰技能正文任何一行指令。** 然后把提案标 `done`。

于是 `done` 的实际含义是「升级流程跑过了」，不是「招式真落进技能了」。
两者之间没有任何校验 —— 这是「技能不会自动进化」的根子：
不是进化不动，是**它把"动了"当成了"该动了"**。

### 修法：加 `_move_landed()` + `_gate_moves()` 回读闸门

判据用 `SEED_MOVES[tid]['kw']` —— 招式库自己记的概念关键词，**不是招式代号**。
扫技能目录下全部 `.py` 与 `.md`，分别数命中：

| 状态 | 含义 | 处理 |
|---|---|---|
| `landed` | 脚本命中 ≥1 关键词 | 标 `done` |
| `doc` | 脚本 0 命中、文档命中 ≥1 | 标 `done`，但记 `landed=doc`（只说不做，要看得见） |
| `none` | 脚本与文档均 0 命中 | **退回 `pending`**，记 `landed_blocked` |
| `unknown` | 技能目录不存在 / 招式不在 SEED_MOVES | **退回 `pending`**（不许把"查不到"当"没落地"） |

`unknown` 单列一态，是为了不重犯本轮已修过的病：**「无法判定」不许当成「否」**。

### 两处 `done` 赋值，其中一处是闸门自己的漏洞

第一处在循环内，按闸门结果分流。第二处在循环外：

```python
if id(p) in sel_ids and p.get('status') == 'pending' and id(p) in _passed_ids:
    p['status'] = 'done'
```

改之前是「凡是选中的、状态还是 pending 的，一律标 done」。闸门刚把没落地的写成 `pending`，
**下一行就被这里重新标回 `done`** —— 闸门白装。

这一版还修了这行里的另一个死穴：`sel_ids` 在本函数里**从未定义**。提案一旦走到这行必然
`NameError`。而 `py_compile` 只查语法，照样通过 —— 本轮差一点就凭着「编译过了」宣布完工。
另外 `id(p)` 当键也不成立：提案结构里根本没有 id 字段，`propose` 判重一直用的是
`(skill, type, ref)`。故新增 `_prop_key()`，闸门与标 done 用同一把钥匙。

### 实跑验证（不是推导）

拿三条已知真值的提案跑 `commit --all`：

```
probe-hub/T-A        landed → done
tvbox-janitor/T-C    doc    → done（标记 landed=doc）
legacy-watchdog/T-D  none   → pending（landed_blocked=none：脚本与文档均 0 命中——纯空转）
```

### 对上一轮判据的纠正（必须记账）

上一轮我做过一个结论：*「41 条 status=done 的已吸收招式，招式代号 T-A…T-I 在正文出现 0 次 = 全空转」*。
**那个判据是错的。** 技能正文写的是招式的**名字和做法**（「写后回读验证」「移动替代删除」），
不是代号 —— 拿代号去搜，当然 0 次。这不是技能空转，是我的尺子坏了。

用 `SEED_MOVES[tid]['kw']` 重测，29 条 `type=move` 的 `done` 提案：

| 判据 | 结果 |
|---|---|
| 正文+脚本有命中 | 27/29 |
| **只看脚本 `.py`（最终）** | **19 landed / 9 doc / 1 none** |

正确结论是「**有一部分真落地了，另一部分只停留在文档**」，不是「全空转」。

`doc` 9 条分布：`tvbox-janitor` 4、`ecosys-conductor` 2、`unfinished-audit` 2、`tvbox-inspect` 1。
这 9 条是**只把做法写进了文档、脚本里没有对应实现**，不是空转，但也还没真吸收。

### 判据第四次修正：终验抓到「自证闭环」——自己写的回执把自己判成已落地

加完闸门后跑终验：造两条提案（`legacy-watchdog` 的 T-I、T-D）真跑 `commit --skill`。
结果 T-D 判成 `doc` —— 但**几秒前**单独调 `_move_landed()` 判的还是 `none`。

查出来是我自己造的：

```
CHANGELOG.md:4  [移动.{0,4}删除]  - 依据 M-R111 提案：吸收通用招式 [T-D] 移动替代删除（终验）
```

`commit` 会把提案原文写进 CHANGELOG 作为留痕，而提案原文**含招式全名**。
闸门回读 CHANGELOG 时看到这行，就认为"文档里有这个做法"。**等于**：

> 我写下"我要吸收 T-D" → 闸门看到"T-D" → 判定已吸收。

越用越像真的，而且同一招第二次起永远判 `doc`，再也不会被判成 `none`。
**这是判据被自己的输出污染**，比单纯误判更坏 —— 它会随时间自动变绿。

修法：回读前先剥掉提交痕迹（`- 依据 M-R111 提案：…`、`- 由 skill-evolution upgrade 自动提升…`），
只认真实叙述。剥前有命中、剥后 0 命中 → 单独给出判词
`仅命中「提案依据」回执行（自我证明，不算落地）`，不含糊成 `none`。

双向验证（用临时假技能造，不动真技能）：

| 场景 | 期望 | 实测 |
|---|---|---|
| 文档里**只有**提案回执 | `none` | `none` ✅ |
| 文档里有真实叙述（"删除接口不可用时改为移动到回收夹"） | `doc` | `doc` ✅ |
| 脚本里有实现 | `landed` | `landed` ✅ |

修复没过严：真实叙述仍判 `doc`，脚本实现仍判 `landed`。

### 判据第三次修正：关键词只认自己的黑话，会把真落地判成空转

首轮跑出 `none` 2 条（`legacy-watchdog` 的 T-D、T-I）。逐条核对后发现**判错了一条**：

`watchdog.py:458` 写的是

```python
saved, _ = save_snapshot(findings)   # 落盘本期指纹，供下期 diff
if not saved:
    print('   ⚠️ 快照未落盘：… 已**保留原文件不覆盖**（防销毁上期基准）')
```

`save_snapshot` 在 `tvbox-inspect` 里是 `return False, []  # 写失败：不得谎报已落盘`。
**这就是 T-I「写后回读验证」本身** —— 写函数自报 saved 布尔、失败时拒绝覆盖、保留现场。
只因为它没写"回读验证"四个字，被 T-I 原有 8 条关键词判成 0 命中。

T-I 关键词已补 7 条同义形态：`saved\s*,` / `不得谎报` / `拒绝覆盖` / `写失败` /
`落盘失败` / `回读.{0,6}不一致` / `回读.{0,4}校验`。补完实测：只有
`legacy-watchdog/T-I` 一条从 `none` 变 `landed`，**其余 10 条判定无一动**（未放宽其他口径）。

> 教训与上一节同源：**判据不许只认自己的黑话。** 一个招式在真实代码里往往不叫自己那个名字。

`legacy-watchdog/T-D`（移动替代删除）维持 `none`，但**不是欠账**：
该技能全库无删除动作（只有 `report`/`trend`/`aging`/`diff`/`upload` 五类命令），
T-D 的适用条件是"目标没有删除能力时"，它压根没触发场景。这类应在 `propose` 层就不提案，
属提案精度问题，另账。

### 顺手补的真缺陷：`watchdog.py` 锚点回写是假的"已回写"

`last_report_node.json` 的回写原来是这样：

```python
json.dump(payload, open(anchor, 'w', encoding='utf-8'), ensure_ascii=False, indent=2)
print(f'   锚点已回写: {anchor}')
```

dump 完直接宣布成功。磁盘满/只读会抛异常被 except 抓到，但**写了一半截断**不抛异常 ——
下一轮读锚点拿到坏 JSON，走 except 当"没有锚点"，表现为「每次都新建云端节点」而毫无报错。
已改为写后回读比对 `latest`，不一致就告警并提示保留原文件。

实测三情形：正常写回读一致 ✅ / 截断写回读抛 `JSONDecodeError`（旧代码正是被 except 吞掉）✅ /
内容不符能被比对抓到 ✅。

### 实证：招式挖掘是"事后统计"，不是"驱动力"

`mine` 的两个跑法放在一起看，才看得清它在生态里的真实位置：

| 跑法 | 扫了多少 | 结果 |
|---|---|---|
| `mine`（全量） | 13 技能 9848 行 CHANGELOG | **9 招全部命中，每条跨 8–11 技能**，回读验证 9/9 |
| `mine --skill probe-hub` | 1 技能 2084 行 | 「未发现跨技能通用招式」 |

第二行为什么必然是这个结果：**判据是「跨 ≥2 技能」，而限定单技能后候选只剩一个技能内的样本**。
它并不是"probe-hub 没有招式"，而是"这个问法在原理上答不出"。所以：

> `mine` 是**全库横切的统计**，用来发现"什么做法已经在很多技能里反复出现、应该被命名"。
> 它**不驱动**任何技能去吸收某招 —— 驱动是 `propose`（招式库 → 未用技能的提案）和
> `cross-learn`（招式 → 尚未用它的技能）。

这也决定了 `skill-evolution` 自己的定位：它**不会替技能写代码**。本版给它加的回读闸门，
作用是**不许它再虚报功劳**，而不是让它真的会写。真正的"会写"必须由人（或另一个执行体）动手，
闸门只负责在事后把"写了"和"说了"分开。

### 未做（留账）

`doc` 的 9 条**没有**退回 `pending`。理由是它们至少把做法写进了文档，比 `none` 强，
且退回会让 9 条待办同时压回队列，掩盖真问题。当前做法是**标出来、让它可见**，
后续是否要「doc 也算不算吸收」另立规则裁定，不在本版擅自决定。

## v1.3.9 — `solved` / 招式入库两处三态改造（S158）

`evolve.py` 里两处 `except` 把「通路坏了」折叠成看着正常的数字。

### 一、`solved` 归档：`except: ok = 0`

原写：

```python
except Exception as e:
    ok = 0
```

下游紧接着打印 `api 自报成功 {ok} 条` —— 通路挂了就打印「成功 **0** 条」。
**等于替失败编了个看起来正常的数字**，人去查会以为是"数据被拒了"。

改成 `ok = None` 哨兵，下游分流：

- `ok is not None` → 打印真实条数
- `ok is None` → 打印「（自报数也未取得）」

回读失败时仍照原样 `return 4` 报"无法判定"（那条 S159 的逻辑保留，它本来就是对的）。

### 二、招式入库：`except: _ok = False`

同一形态。`_ok = False` 让"更新被拒"和"调用通路坏了"都记进 `fail` 计数，
日志报「失败 N 条」时人分不清两种原因，会照着去重写已经成功的数据。

改成三态：`_ok = None` → 单独计入新增的 `unk`（未判定），输出显式区分
`成功 N / 失败 M / **未判定 K（更新通路异常，勿当作失败）**`。

### 三、检测器侧

两处 `= None` 会被信号源16（基座折叠扫描）扫到——那是**语法形态判别**的固有边界，
它分不清"三态哨兵"与"折叠成空"。已按既定流程登记白名单，每条写清改造前后对照。

## v1.3.8 — 触发词划界 + 真源回填（S157）

S157 做技能指向核查，发现 6 个触发词同时归两个技能（`监测/生态/对账/终验/直链/轻量json`），
同分时靠列表顺序决胜负——用户问记账被推给总指挥、要看体检被推给处置层。

  `_SKILL_INTENTS` 里新增的词同步进 description，否则信号源32 报"投影孤儿词"
  （打分器认识、模型看不见，用户这么说模型想不起该用哪个技能）。

**这轮实测结论要记住**：补词只能拟合不能泛化——按一批口语补到 100%，
换一批从没见过的掉回 47%。故 `conductor ask` 已改为**候选+依据**输出而非单选。

## v1.3.7 — `solved` 回读失败曾被当成「全部没生效」，会伪造一份失败清单（S159）

v1.3.6 加了 `solved` 归档 + 回读复核，但回读逻辑是这么写的：

```python
backstate = {str(r.get(idf) or ''): r.get(sfld) for r in rs}   # 抛异常就什么都没
if ...
```

异常一抛，`backstate` 就是 `None`，然后下游 `backstate.get(...)` 拿到 `None`，
一律判「未生效」——**明明归档成功，却打印一份"3 条全部未生效"的失败清单**，
还引导用户去重试。重试是错的：真正坏的是回读通路。

**改三态**：
```python
good = []
backstate = None
_err = ''
try:
    ...
    backstate = {str(r.get(idf) or ''): r.get(sfld) for r in rs}
except Exception as e:
    backstate = None; _err = f'{type(e).__name__}: {e}'
if backstate is None:
    print(f'📦 归档结果：**无法判定**（回读失败 {_err}）')
    print(f'   api 自报成功 {ok}/{len(ids)} 条，但回读校验没做成 → 不要重跑，先修回读通路')
    return 4
```

要点：**「读失败」不等于「读到空」**，更不等于「写没成功」。三者要分开报。

**这是三态纪律（M-R60）在本轮的第 4 张脸**，前三张：读缓存≠读现状、字段缺失≠值为空、
读错库≠读失败（`ok=True, rows=[]` 能绕过所有三态守卫）。

## v1.3.6 — 经验池「已解决归档」：让经验池只统计还欠着的（S159）
