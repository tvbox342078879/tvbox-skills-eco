# 技能自我进化引擎（skill-evolution）

> **定位**：把「规则 48：技能自我进化机制」从纸面变成可执行能力。
> 它不绑定任何业务，是**全局元技能**——监控所有技能/规则的「复发问题」，一旦达标自动立项生成新技能。

## 1. 为什么需要它（规则 48 的核心命题）

技能不是建完就完，而是**活物**。进化的三个来源：

1. **历史任务经验** —— ③ 会话台账（业务经验）+ ④ 资料库经验库（平台经验）
2. **新任务过程** —— 执行中新发现的更短路径 / 可自动化点 / 更优解法
3. **自身判断** —— 对规则合理性、逻辑性、效率的自审（不等新任务触发）

进化的触发（命中即执行，不等人说）：
- 新任务中发现改进方向 → **当场自己改**（更新 SKILL.md / 追加规则 / 补工具）
- 同一问题第 **≥2** 次出现 → 记入 ④ 经验库，标「易复发」
- 同一问题第 **≥3** 次出现（或 ③+④ 合计命中 ≥3）→ **自动立项**：生成独立可升级技能

## 2. 引擎命令（`scripts/evolve.py`）

| 命令 | 用途 | 何时用 |
|---|---|---|
| `evolve.py recurring --min 3` | 扫描 ③+④，按「问题签名」聚类，列出复发 ≥N 的候选 → 应技能化；**输出3「已固化途径·直达」**带出命中聚类的解法/可复用点（规则52）；**输出4「用户偏好·持久指令」**读 `user_standing_instructions.json` 列出待固化/已固化偏好（M-R108）。**已标「已解决/已固化」的记录不再参与聚类**，过滤条数显式打印（S159） | 周期性 / 新会话开工 |
| **`evolve.py solved <编号...> [--ledger] [--state 已解决\|已固化]`** | ★ 已解决归档（S159）：把经验库/台账记录标记完成，使其退出 recurring 聚类——没有这一步，治好的坑会永久顶着阈值反复报警，经验池退化成噪声源。`--list` 只列不改 | 问题根治后 / 清账时 |
| `evolve.py standing` | 用户偏好持久指令清单（M-R108）：列出已登记偏好、重复次数、固化状态、开工核对标记、云端补登点 | 新会话开工核对 / 用户重复提要求时 |
| `evolve.py create <name> --trigger "..." --desc "..."` | 脚手架式生成新技能（SKILL.md 模板 + scripts/ + CHANGELOG + 扩展点） | recurring 命中后，或用户要求 |
| `evolve.py review` | 对比当前规则数与上次快照，输出「新增/待整理」提示 | 周期性整理前 |
| `evolve.py scan` | 就绪度体检：技能全集 = 生态登记库 ∪ 本地自建（S022 修复前缀硬编码漏技能）；检查项 = 三件套（version+CHANGELOG+flow.json，规则48+54）+ 触发词，4/4 才算就绪 | 每次生态升级 / 新技能立项后 |
| `evolve.py note --what "..."` | 把一次进化动作写进 `evolution_log.jsonl`（本地留痕） | 每次进化后 |
| **`evolve.py mine [--min 2] [--dry] [--skill X]`** | ★ 招式挖掘（规则57）：扫 9 技能 CHANGELOG → 按招式签名聚类 → 跨≥N 技能入「🥋 通用招式库」；`--dry` 只审计；末节列"候选新招式（人工确认后补 SEED_MOVES）" | 周期 / 新招式入库 |
| **`evolve.py lend <name> [--own] [--json]`** | ★ 查某技能可借鉴招式（升级前**必查**）：列"已用 / 未用但适用" | `upgrade` 前 |
| **`evolve.py review-lend`** | ★ 对账（规则57）：哪些技能"升了版但 CHANGELOG 无对照留痕" → 供 conductor 扫成遗留 | 周期 / 终验 |
| **`evolve.py propose [--skill X] [--min N]`** | ★★ M-R111 吸收→提案：扫**招式库未用招式** + **复发聚类** + **cross_queue**，产出《升级提案清单》→ `upgrade_proposals.json`。**只提案、绝不改技能** | 定期（建议每日）/ 新会话 |
| **`evolve.py commit --skill X \| --all \| --reject 1,2`** | ★★ M-R111 授权→执行：**唯一**会改技能 SSOT 的入口（用户显式调用 = 授权）；升版本 + CHANGELOG 写"依据哪条提案" | 用户批准后 |
| **`evolve.py cross-learn --move T-X`** | ★★ 技能间互相学习：把某招式推给**尚未用过**的其它技能（进 cross_queue → 下轮 propose 成提案） | 新招式入库后 |


## 2.4 经验池驱动的技能升级闭环（M-R111 · 1018 立）

> **用户原话**：「技能升级现在只停留在被动升级上……经验池的一个作用就是供技能升级使用，
> 各技能应该在经验池吸收经验来成长；吸收后如有改进计划，咨询我的授权进行升级；
> 还有一个是技能间互相学习的机制也没有。」

**为什么以前没做成**：`lend` 能列出"该技能还没用的招式"，但到此为止——**没人把它变成动作**；
`upgrade` 只改版本号，**不读经验池**；技能之间没有"推送学习"的通道。三个环节各在一处，连不成闭环。

**闭环（四步，缺一不可）**：

```
① absorb   扫招式库未用招式 + recurring 复发聚类 + cross_queue 待推送
      ↓        （数据源：④经验库 138 条 / ③会话台账 99 条 / SEED_MOVES 9 招）
② propose  产出《升级提案清单》：改哪个技能、改什么、依据哪条 ← 只写 upgrade_proposals.json
      ↓
③ 授权闸   用户批准（commit --skill/--all）或驳回（--reject）。**propose 永不改技能**
      ↓
④ commit   升版本 + CHANGELOG 写入"依据 M-R111 提案：…" + 提案转 done
```

**技能间互相学习（cross-learn）**：新招式沉淀后，`cross-learn --move T-X` 自动找出"还没用这招"
的技能，推入 `cross_queue`；下轮 `propose` 变成它们各自的提案，同样等你授权。
（例：清道夫踩到的"`node-info.parentNodeId` 恒为 None"就该推给所有用节点 API 的技能。）

**定时化（关键——治"只被动"）**：挂每日任务跑 `propose`，有提案就摆到你面前等你点头，
没提案不打扰。这样技能是"自己长"的，而不是"你喊它才动"。

```bash
# 建议定时（每日 09:00）：只生成提案，不自动升级
python3 /root/.codebuddy/skills/skill-evolution/scripts/evolve.py propose
```

**安全边界（重要）**：
- `propose` **只读不写**技能文件，产出仅是 JSON 清单；
- `commit` 是唯一写入口，且必须带 `--skill`/`--all`（=人工授权信号）；
- 提案可逐条 `--reject`，驳回理由留档，不会被反复提。


## 2.5 用户偏好固化（M-R108 · S154）

> **规则48 的盲区**：过去 recurring 只聚类「问题」（③/④ 里的坑与解法），**不聚类「用户偏好」**。
> 用户反复提的要求（如「会话保持中文」）从不进入 ③/④，于是同一要求提了 ≥3 次仍不被固化，
> 切模型/切会话即回退、反复重提。M-R108 补上这条：用户重复≥3次明确要求 → 立即固化为持久指令。

**机制**：
- 任何用户重复≥3次的要求，即时写入 `ecosys-conductor/scripts/user_standing_instructions.json`（本地持久档；沙箱无法直写③云库时作等价落点，联网后补登 `tvbox log --db TO4LwsjVVdR8JRAUlkejk3`）。
- `evolve.py standing` 列出持久指令清单（重复次数 / 固化状态 / 开工核对 / 云端补登点）——会话开工首步核对并主动声明已生效。

> **S156 补强（M-R108）**：会话开工首步除核对持久指令外，还须**主动触发生态联动**——跑 `tvbox brief`(四极联动速览) 且命中任一技能触发词时必调 `Skill` 工具，使联动设施从「设计存在」变为「每次运行」。治 S148 实证「12884 次调用 Skill 仅 3 次、10 技能全 0 触发」的双向盲区。
- `evolve.py recurring` 输出4 自动带出该清单，使「偏好」与「问题」在同一入口被看见。
- 属主：**skill-evolution** 负责聚类捕获（standing 命令 + recurring 输出4），**ecosys-conductor** 负责规则册（M-R108）与开工核对门禁。

## 3. 「自动创建可升级技能」的硬性要求

生成的技能**必须**满足「可升级」契约，否则视为不达标：

- ✅ 顶部 `version` 字段 + 独立 `CHANGELOG.md`
- ✅ SKILL.md 写明**触发词**（让引擎未来能自动识别命中）
- ✅ 预留**扩展点**（subcommand / 配置项 / 新规则位），本技能后续可继续改写它
- ✅ 自身遵循规则 48：它的进化也走「发现→自改→复盘→升级」
- ✅ 落地后在 ③台账记一条「规则维护」+ ④经验库补一条「建库建夹」

## 4. 周期性系统整理（强制，命中即做）

触发：累计新增 ≥5 条规则 / 距上次整理 >7 天 / 用户要求。

动作（六步，缺一不可）：
1. **去重** —— 重复/重叠规则合并（参考《规则治理总览》主题章）
2. **简化** —— 高效性原则：宁少勿多、宁简勿繁、能合并就合并
3. **强化逻辑** —— 消除矛盾、补齐前提条件
4. **增强合理性** —— 每条规则必须可操作、有判据
5. **复盘** —— 本次改了什么、为什么
6. **技能升级** —— 版本号 + CHANGELOG

## 5. 高效性原则（规则的生命线）

- 一条规则只表达一个可操作判定；含糊、不可执行的规则**不立**
- 能合并就合并，能引用就不重述（数字只存唯一权威源，见规则 47）
- 规则**宁少勿多**：每增加一条先问「能否并入已有规则」
- 历史规则标「已归并」但保留原文，保证可追溯

## 7. 经验对照（规则57 · 招式库 · 方法极联动）

**命题**：技能升级过程中存在大量可相互借鉴处——A 技能的成熟打法（三态契约、SSOT、活体探针…），
B 技能往往也能用上。把这些"跨技能通用招式"抽出来对照，可**显著提速各技能进化**。
此前招式只散落在各技能 CHANGELOG，**无机制记录/检索/回流**（S107 核查结论：确实没做）。

**定位**：生态已有三极联动（数据极 / 技能极 / 用户极），招式库是**第四极·方法极**——
跨技能传递"经验打法"。

### 7.1 招式库（`🥋 通用招式库` `qBQcYoVTqg7v3NAYBa4eSF`）

字段：招式编号(T-A…) / 招式名 / 判据 / 出处技能 / 跨技能数 / 热度(热招≥3/常用2/单点1) / 适用条件 / 时间。

**抽取算法（三层判据 + 防噪）**：
1. **段切分**：只按 `## ` 切段——招式判据只在段内匹配，不跨段串味（抗噪第一道闸）
2. **正则匹配**：`SEED_MOVES` 的判据关键词逐段匹配（**一段可命中多招**——真实 CHANGELOG 常在一段讲多招）
3. **跨技能去重**：判"通用"看**技能数**（set）非出现次数；跨 ≥2 技能才算通用
4. **防噪**：`MOVE_NOISE` 排除元技能自指（skill-evolution 自己讲招式定义）；
   `MOVE_EXCLUDE_RE` 排除 `upgrade` 自动追加的空段
5. **新招式发现** `discover_new_moves`：挖"跨≥2技能但未归类的高频短语" → **只提示不自动入库**

### 7.2 规则57 正文（强规则）

> **规则57｜经验对照**：任何技能升级前，必须先跑 `evolve lend <name> --own` 查有无可借鉴的跨技能通用招式；
> 升级后须把本次新招式回写招式库并登记出处。
>
> **三条判据（可执行）**：
> 1. **升级前必查**：执行 `evolve upgrade <name>` 前，须先跑 `evolve lend <name> --own` 看"未用但适用"清单。
> 2. **升级后必回写**：本次若产生可复用新招式，跑 `evolve mine --skill <name>` 更新出处；
>    若**借鉴了**某招式，须在 CHANGELOG 显式写"借鉴 T-X"；全部不适用须写"不适用 T-X（原因）"。
> 3. **漏项即遗留**：升级了但无对照留痕（既无 lend 记录、CHANGELOG 也无"借鉴/不适用"声明）→
>    由 `review-lend` 报出，conductor 信号源21 扫成遗留项（`未做经验对照`）。
>
> **边界**：① **只诊断不自动改**——mine 产出候选招式交人工确认后入 SEED_MOVES；
> ② 跨≥2技能才叫"通用"，单技能私有打法不入库；
> ③ 借鉴是**建议非强制**，不适用须显式声明（防为凑数硬套，M-R34 双向验证思想）。

### 7.3 与 `evolve upgrade` 的挂钩（软阻断）

- **默认软阻断**：`upgrade` 开头自动跑 `lend --own`，有适用招式则**打印清单提示**，不阻断——
  符合生态门面「旁路、永不阻断主流程」哲学（core.file_to_janitor/register_monitor 同理）。
- **`--strict` 硬阻断**：供 CI/终验用；**`--force`** 确认借鉴后绕过。
- **三态**（M-R57/M-R60）：`lend` 读招式库失败 → 前置检查返回 `None`（无法判定）→ **不阻断、仅告警**，
  绝不折叠成"0 条待借鉴"。
