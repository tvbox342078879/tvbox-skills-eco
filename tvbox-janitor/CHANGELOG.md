## v1.2.6 — 空夹不再自动投递 + 结构性容器双义交人裁（M-R125 · S179）

### 事故：判据挂在了名字上

`scan` 判"空夹"用 `kind=='folder' and not _kids(nid)`，随后 `reason='空文件夹（无子节点）'`
→ 直接进 `hits` → 被搬进待删收件箱。

**这个判据不成立**：备份文件以 attachment 挂在节点上，**不占目录树槽位**。
实测证据：
- `node-info` 字段全集 16 个，无任何附件字段（`attachments`/`attachmentCount`/`size` 都没有）；
- `api-manifest.json` 41 个接口，**没有 attachment-list**；`attachment.py` 只有 upload/download；
- `get-doc-review` 对"有 81 个附件"与真空返回**完全同形**；
- 同一批 14 个备份夹 `list-nodes` 全返回 0 子节点，而 `backup_state` 记着 81 件已上传。

> 「0 子节点」不是弱证据，是**不成立的证据**：接口返回的 0 是真值，
> 只是它回答的不是"这里有没有东西"。

原 `EMPTY_KEEP` 关键词表（`备份/backup/归档/库/…`）确实兜住了这 14 个夹——
**但兜底挂在命名习惯上**：改叫 `20261020_eco` 就失守。这轮实测就抓到 3 个
不命中关键词却是 0 子节点的夹，全都被推进过投递路径。

### 修法

1. **空夹一律不自动投**（`EMPTY_NEVER_AUTOPOST`）：改为登记 `nocontent` 候选，
   显式打印"AI 无法判定（附件不可见）"，交用户到客户端核对附件列表。
   用词守三态：**输出里不出现"空夹/可删"**。
2. **标题双义交人裁**：标题同时命中废弃词与结构性容器词（如 `📁 归档·废弃归档库`，
   `废弃`+`归档`/`库`）时不投递，标"须人工裁决"——搬走一个"库"的代价远大于少投一条。
3. **`库` 加否定前瞻**：`(?<!入)库(?!存|房|内)`。实测「🗄️ 待清·DmaxPro908（已入库待删）」
   因"入库"含"库"被误判为结构性容器，而它本该投递。
4. **去重段不再替事实撒谎**：原逻辑对 `「20261020_生态备份」×13` 直接打印
   "投递 12 份副本"，而 `cmd_add` 的护栏会把这 12 个全拒 → **屏幕上写 12，清单里 0 条**。
   现改为预筛 + 分账打印：`可投递 N 份 / M 份因结构性容器不动 / 二道闸拦下 K 份`。

### 验收

- `scan --dry-run`：16 个夹标"无法判定"且**零投递**；`20261020_生态备份 ×13` 显示
  「可投递 0 份副本，12 份因名字属结构性容器**不动**」；`重复副本：实际投递 0 份`。
- 已跑探针验收（`attach_guard.py`，126 个脚本，rc=0）：自测可捕获 3 类真实误判形态、对 2 类合法遍历零误报。

规则：**M-R125 附件不计入子节点**（正本 `ecosys-conductor/docs/M-R125_evidence.md`）。

## v1.2.1 — 触发词划界 + 真源回填（S157）

S157 做技能指向核查，发现 6 个触发词同时归两个技能（`监测/生态/对账/终验/直链/轻量json`），
同分时靠列表顺序决胜负——用户问记账被推给总指挥、要看体检被推给处置层。

本技能相关划界：

- **legacy-watchdog 去裸词 `监测`**：判据是「遗迹哨不是"盯"的人，是拿到盯的结果之后
  派人去修的人」。裸词归监察司，本技能留 `遗留监测/老问题监测/处置/派活/账龄/分级`。
- **tvbox-source-blacklist 去裸名词 `失效源`**：`失效源` 是事物不是动作。
  「有多少个失效源」是盘点（归监察司）、「这个失效源拉黑」是治理（归本技能）。
  故名词让给盘点方，本技能只留**治理动作**（拉黑/封掉/拦截/标一下）。
- **probe-hub / tvbox-interface 分 `直链`、`轻量json`**：探源司"从上游找"、
  整包坊"把手上这份加工"。裸名词从两家都移出，各留带动作的短语。
- **skill-evolution / tvbox-interface / probe-hub** 回填 M-R76 真源：
  `_SKILL_INTENTS` 里新增的词同步进 description，否则信号源32 报"投影孤儿词"
  （打分器认识、模型看不见，用户这么说模型想不起该用哪个技能）。

**这轮实测结论要记住**：补词只能拟合不能泛化——按一批口语补到 100%，
换一批从没见过的掉回 47%。故 `conductor ask` 已改为**候选+依据**输出而非单选。
