## v1.2.4 — 账本自净暴露的三处真缺陷：回写不统一 / 币种没人校验 / 多币种户被求和使用（S176）

### 起因

S175 的注入回归污染了真实账本，冲销自净后发现 `ledger balance` 挂着 5 处
「⚠️账册不符」。逐笔在总账里查实，其中**只有 1 处是自净残留，另外 4 处是早就存在的真缺陷**。

| 户 | 账面 | 登记 | 查实结论 |
|---|---|---|---|
| `版本·eco-ledger` | 10203 | 10202 | **真缺陷**：`sync-versions` 只记分录、不回写 |
| `暂记·无主变动` | -19 | -18 | 登记滞后（同上，只是换了个命令触发） |
| `期初·建账基准` | 四币种求和 | -125729 | **真缺陷**：多币种户被 `sum()` 压成假数 |
| `产能·治理会话` | 记录数 -1 | 事项数 0 | **真缺陷**：错币种分录写进去了，无人拦 |
| `暂记·待核销` | +1 | 未登记 | 手写 post 编出来的户名，从未进科目表 |

### 缺陷一：回写账户库有三份实现，其中两份忘了写

`settle` 在 S165 补上了"回写登记值"，`sync-versions` 与 `reconcile` 都没有。
于是**每升一次版本、每消费一条待过账，`balance` 就多一行账册不符**。

实测证据：`AUTO-VER-10192007` 把 `版本·eco-ledger` 从 10202 推到 10203，
分录记了、账面涨了，账户库那行没人去改。

**修法**：提成 `sync_registered_balances()`，`settle` / `sync-versions` / `reconcile`
三处共用一份。回写只有一个实现（M-R38）。

### 缺陷二：`make_entry` 只校验币种名合法，不校验账户币种

`S165-LOG-119-CLAIM` 拿「记录数」借记 `产能·治理会话`（该户是「事项数」）。
写进去了，试算还平（记录数整体仍归零），但那户从此挂着记录数 -1，**没有任何一处报错**。

**修法**：校验放在 `post()`（唯一入口，绕开 `make_entry` 也拦得住），不在构造器。
`make_entry` 只加可选参数 `strict_currency`，不重复实现。

**踩到的死锁（值得记下来）**：加了校验后，**连冲销这笔错账也被拒了**——
一条为了防错的规则，把 M-R29「错账只能冲销」的纠错路径彻底堵死。
故 `post` 对 `动作类型 == '冲销'` 放行币种校验，但**必须打印告警**，不静默放行。

### 缺陷三：多币种对价户被 `sum()` 算成一个数

`期初·建账基准` 是每笔分录的对手方，必然要装记录数/版本号/事项数/分数四种币种。
`balance` 和 `settle` 一律 `sum(b.values())`，得到 **-125730**——
那是 -1255 条 + -94 件 + -49 分 + -124332 版本号，**四个不同单位硬加**。

更要命的是这个假数被回写进账户库，然后 `balance` 拿假数比假数，**永远显示对得上**。

**修法**：
- 引入 `COUNTERPARTY = '*'` 多币种户声明，`期初·建账基准` / `暂记·无主变动` 如实声明；
- 币种校验对 `*` 户放行（它本就是替任何币种做对手方）；
- `balance` 对多币种户**按币种分行显示**，不求和；
- `sync_registered_balances` **不对多币种户回写**（账户库的「当前余额」装不下四币种）。

### 缺陷四：科目表漏了 10 个版本户，币种校验空转

`INITIAL_ACCOUNTS` 只硬编码了一个 `版本·eco-ledger`，其余 10 个由
`version_accounts()` 从各 `SKILL.md` 动态生成。`acct_currency_map()` 只读前者，
于是加上币种校验后，**10/11 的版本户被当成 ghost 空转放行**——校验看着生效，其实没管。

**修法**：`acct_currency_map()` 合并两处声明，以 `version_accounts()` 为版本户唯一来源。

顺带收益：`finalcheck ③` 从硬编码的 `12/12` 变成按真源算出的 `12/12`（此前报 12 但实际 11 户）。

### 同时修掉的

- `暂记·待核销` 补登科目表 + 账户库（全仓搜索证明这个户名**代码里根本不存在**，是手写 post 编的）；
- `post` 对未登记户**不拦但喊一声**（拦死会逼人绕开 post 直接写库，更难管）；
- 清理 3 个自造临时脚本（`orphan_scan.py` / `inject_layer.py` / `orphan_probe.py`）；
- `conductor.py` 的 `layer = None` 登记折叠扫描白名单（三态降级哨兵，非折叠）。

### 同时更正一处**我上一轮的错误归因**

上一轮处理 B3 错账时，把 `S129-LEDGER` 从「技能交付」改记到「产能·治理会话」，
用 `S129-LEDGER-REV` 冲销了原分录——但那笔冲销**连带把台账 +1 也撤掉了**。
实测 `S129` 是台账里的真实记录（`会话编号=S129` 确实在库）。
把"改事项归属"做成了"撤台账记录"，是归因错误。已用 `S176-FIX-S129` 按事实补回。

> 归因错了比不报错更毒——这笔错账当初是我自己"修"出来的。

## v1.2.3 — 待过账闭环：把「每次会话都欠一笔」从人工改成自动（S175）

### 病根（P019 缺口③，10-18 诊断，10-19 仍在复发）

`tvbox log` 写会话台账后**不会自动记账**，于是台账实际数永远比总账多 1，
`reconcile` 每次都报「会话台账 账实不符」。以前的做法是人工 `ledger post` 补一笔，
再被 `writeoff` 收进暂记——**补一次多一笔无主变动**。

实测证据：`暂记·无主变动` 17 笔里，**10 笔**备注清一色是
「writeoff 对齐: 实际 X vs 账面 Y」，全是同一个缺口反复结的果。
其中 5 笔直接写着「根因是时序不是错账」「差额成因同 P019 缺口③（tvbox log 不自动过账）」。

### 修法：投递而非直调（B 法）

```
tvbox log  写入台账成功 → 投递 pending_post.json
                              ↓
ledger reconcile 开头 → _drain_pending_post() 自动消费
```

**为什么不直调**：源枢库若 `import ledger`，账房一挂连台账都记不进去，
把「记账失败」放大成「留痕失败」。投递只依赖一个 JSON 文件，账房挂了台账照写。

### 三个防御

- **队列读失败不折叠成空**（M-R60）：坏队列时返回错误文字，**不覆盖**（覆盖会吞别人的待办）
- **单条失败留队列**：`post` 本身幂等（凭证号+指纹），重放不记双账
- **投递失败不影响台账**：台账已落库且回读通过，那是既成事实；只意味着「还没人过账」，
  `reconcile` 仍会报不符——降级回修复前行为，不会比现在更坏

### 顺带改掉一处「替自己开脱」的口径

原文账账线（与上期快照环比）一律写「确认有凭证支撑」——
**快照变了不等于变对了**。实测会话台账 账面130/实际133 被这句解释成正常，
而同屏「生态登记库 12 vs 13」却标「账实不符」，两套标准。
现改为：账实线才是结论；账账线单列一节，只报「比上期变了多少」，**标注「仅供参考·非结论」**。

### 实测（端到端，非模拟）

```
✅ 台账已写入 S134 | 读回验证 通过 | 累计 134 条
   📮 已投待过账 LOG-S134
📮 待过账消费：入账 1 笔
⚠️ 1 项账实差额：生态登记库 账面=12 实际=13
```

**「会话台账 账实不符」不再出现。** 注入回归 3/3 真抓住。

### 另修：一笔借贷币种不一致的错账

`S129-LEDGER`：借方「会话台账」（资产·记录数）却记「事项数」币种，
贷方「技能交付」不在科目表。导致 `会话台账` 带上 `事项数: 1`，且多出一个未登记户。
按 M-R29（只增不撤）冲销后重记为 `产能·治理会话 / 暂记·无主变动`。
冲销后「技能交付」未登记户消失，`会话台账·事项数` 归零。

## v1.2.2 — 把「退出码不可信」归成一族（S165 第三轮·跨语言）

### 文档：新增跨语言缺陷对照表

同一族错误第三次出现，这次是在 shell 里（`scheduler-api.sh`）：

| 语言 | 写法 | 为什么吞 |
|---|---|---|
| Python | `a.f(a)` / `DISPATCH[x](a)` | 不 return，掉到末尾返回 None |
| Shell | 函数体内 `exit 1` | exit 只结束函数体，调用方拿的是函数返回值 |
| Shell | `case` 分支裸调用 | 返回值被 case 吃掉，main 恒 0 |

判据一句话写进 SKILL.md：**判定算出来之后，有没有一条 return 把它送到进程退出码上**。
改判定逻辑时必须顺手 `echo $?` 验一次——三种语言的错法不同，错的是同一件事。

不改代码，只补判据与对照表。

## v1.2.1 — 定时任务压测：退出码一族缺陷 + quiet 语义 + 参数校验（S165 续）

拿真定时任务压测统一调用入口，发现的问题不在功能，在**判定不可信**。

**退出码一族（同一错误四处重复）**
- `ledger.main`：`a.f(a)` 不接返回值 → 所有 `return 2/1` 被吞
- `ledger.dispatch`：硬编码 `return 0`
- `link.dispatch`：`DISPATCH[a.cmd](a)` 不接返回值 → **整个 link 系恒 0**
- `conductor.cmd_whoami`：缺参打印用法却 `return`（→exit 0）

最典型的后果：`ledger call ingest`（没给候选文件）**一条都没入库，判 ✅ok**。

**quiet 语义**
- ①零字节（哑巴）→ ②只有判定行（读不到内容）→ ③判定行 + 关键行摘要。用"关键行"而非"前 N 行"：
  脚本输出长短不一，截前几行常常只截到标题，结论在最后。

**参数校验**
- 必填判据：`[方括号]` 内是可选、`<尖括号>` 才是必填。首版把 `[<定时任务名>]` 当必填，
  `debt` 被自己的校验拦住。
- 技能名存在性：不存在的技能"名下 0 条欠账"是**假绿**。建议只给一步之差的
  （`prob-hub`→`probe-hub`），不给"看起来像"的（首版把 `nonexist-skill` 推荐成 `skill-evolution`）。

**实测**
- 全动词回归 14 个：必填 4 个被拦（exit=2）、其余放行；
- 全系回归 20 条命令 exit 全 0，无"成功被当失败"；
- `conductor verify` 11/12 → exit 1（此前恒 0，门禁形同虚设）。

## v1.2.0 — 跨界统一调用总线：四个界 + 统一入口 + 调用体检（S165）

用户原话：「做跨对话，跨任务的，跨场景，跨生态的调用机制闭环，合并进账房，做统一调用入口，
不然如同刚才一样，调用麻烦，做好联动和分工接入」。

### 新增：`scripts/call_bus.py`（+ `ledger call/verbs/relay/map/audit-call/metrics`）

- **四个界**（各有出入参、凭证号前缀、记账科目）：对话 `DLG-` / 任务 `TSK-` / 场景 `SCN-` / 生态 `ECO-`。
- **14 个调用动词**，每个绑定归口技能 + 底层命令；`tvbox ledger call <动词> …` 参数原样透传。
- **每次调用落一笔分录**（1 事项数），备注写全命令/耗时/首行输出；四态判定 `ok/fail/partial/unknown`。
- **`relay`**：跨场景接力，占位符步骤**显式跳过**（S023 教训：静默失败比报错更坏）。
- **`map`**：直接解析 `/usr/local/bin/tvbox` 的 ROUTE 字面量（不复制），自报"谁能调谁"。
- **`audit-call`**：三查——①登记了没接线（幽灵命令）②接了线没记账 ③账上记了命令却不存在。
- **`metrics`**：各界调用次数/成功率，复用指标户，与 `reconcile` 同口径。

### 修掉两个真缺陷（都是本层建起来才暴露的）

1. **`core_ledger.add_entries` 静默类型错（存在已久）**
   批量新增接口入参是 `[{字段: {类型: 值}}]`，原实现多包一层 `{"properties": …}` →
   `validate_properties` 见每个 value 非 dict 直接返回 `{}` → 报「records[0] 校验后为空」
   **但 exit=0**。账房真实写入走 `post()`（扁平 properties，恰好对），故只在建账/补登等
   边缘路径发作——**同一条通道一半对一半错**。实测补登 11 个户全失败才挖出来。
   修：两种入参都接（兼容而非强改，避免造出新断层）。

2. **`settle` 只拍快照、不回写账户库「当前余额」**
   `balance` 早就能摆出「账面 vs 登记」并标 ⚠️账册不符（实测一度 5 户挂红：
   版本户 4 + 暂记），`settle` 却不补登记值——**诊断出来了、处方不写**。
   修：settle 内对差额 ≥0.005 的户回写余额，实测一次同步 5 户，挂红归零。

3. **`balance` 新户不可见**
   只遍历账户库的行 → 有余额却未登记的户**一行都不显示**（"记账了却看不见"的假绿）。
   修：新增 ghost 分支，显式列出并给补登指引。

### 补登的科目（6 户一直有余额但从未进科目表）

`跨界·对话/任务/场景/生态`、`指标·调用×4`、`版本·eco-ledger`、`演练·T1/T2`。
账户库「科目类」select 新增选项 `资产·调用`（id `6YHCF8zrmOHj`）。
