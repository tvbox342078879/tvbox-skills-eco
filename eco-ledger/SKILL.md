# eco-ledger · 账房司

大生态的**总账房**：每笔进出记分录，定期对账，差额进暂记，终验有卡口。

## 两本账

| 库 | id | 用途 |
|---|---|---|
| 📒 账房·总账 | `Xjqn2Wf5EKPSGIXqQ2K6Dc` | 分录流水（14 字段，凭证号引用会话台账） |
| 📒 账房·账户 | `6cQgwWQqqKoeFAiTcb08Cx` | 科目表实例（25 户期初，含 10 技能版本户） |

坐标唯一事实源：`scripts/core_ledger.py`。

## 记账语义

- **分录**：`借方账户/贷方账户/金额/币种`。账户余额 = Σ借 − Σ贷（按币种分组）。
- **币种**：记录数/版本号/事项数/分数/字节数。版本号 `x.y.z` 编码为 `x*10000+y*100+z`。
- **守恒律**：任何时刻 Σ所有账户余额 按币种 = 0。不平 = 账本自身损坏（最高优先级）。
- **冲销不改写历史**：冲销 = 交换借贷方向 + 正额（或等价负额），原分录永不动。
- **三态纪律**：读失败 ≠ 读空。`rows_of` 返回 `(rows, ok)`，ok=False 时调用方必须中止，不得当空表。

## 命令

```
ledger.py status      建账状态/闸门/快照
ledger.py init        期初建账（幂等防重，账户库非空即拒绝）
ledger.py balance     余额表 + 试算平衡（含「有余额但未登记」告警）
ledger.py post        记分录（幂等：同凭证号+指纹跳过；写前过闸门预检）
ledger.py reconcile   账实对账（资产·数据户 vs 库实际行数）
ledger.py writeoff    差额平账（差额 → 暂记·无主变动，账龄纪律）
ledger.py settle      期末结账快照（**并回写账户库「当前余额」**）
ledger.py finalcheck  终验五卡口：①docsync ②账实差额 ③版本一致 ④信号源 ⑤凭证完备
ledger.py db create/retire  库操作（retire 强制 --archive 快照 + 回读 0）
```

## 统一调用入口（S165·跨界闭环）

> 用户原话：「做跨对话，跨任务的，跨场景，跨生态的调用机制闭环，合并进账房，做统一调用入口，
> 不然如同刚才一样，调用麻烦，做好联动和分工接入」

**分工**：`tvbox` 是态射（单个原子动作）；`ledger call` 是函数（把动作组合成有出入参、有记账、
有闭环的一次调用）。本层**不复制** `tvbox` 的命令定义，一律经它派发——唯一一处 subprocess。

```
ledger.py verbs                   列出 14 个调用动词 + 四个界
ledger.py call <动词> [参数…]      跨界调一次（参数原样透传给底层技能）
ledger.py relay <链路名>           跨场景接力：逐步跑 + 逐步入账
ledger.py map                     调用地图：谁能调谁 / 有无幽灵命令
ledger.py audit-call              调用体检：路由—登记—记账 三方一致
ledger.py metrics                 调用业态：各界调用次数与成功率
```

| 界 | 解决什么 | 凭证号 | 科目 |
|---|---|---|---|
| 💬 对话 `dialogue` | 别的会话/定时任务挂出来的事（跨对话） | `DLG-YYYYMMDD-nnn` | 跨界·对话 |
| 📋 任务 `task` | 一路产出是另一路输入；收口结论（跨任务） | `TSK-…` | 跨界·任务 |
| 🎬 场景 `scene` | 找源→测活→入库→快照 接力（跨场景） | `SCN-…` | 跨界·场景 |
| 🌐 生态 `eco` | 归口、调用图、体检（跨生态） | `ECO-…` | 跨界·生态 |

**每次调用落一笔分录**（1 事项数），备注写全：`判定｜动词 → 命令｜耗时｜首行输出`。
四态判定：`✅ok / ❌fail / ⚠️partial / ❓unknown`——`❓` 是超时/起不来，**不折叠**（M-R60）。

动词：`debt`（欠账总览）`from-job`（只捞定时任务挂的）`mine`（按技能反查）`done`（带证据收口）
`claim`（接活+改代码前查账）`scan/harvest/liveness/ingest/snap`（场景链）`who/ask`（归口）`map/audit-call`（自省）。

### 用定时任务实测出来的一族缺陷（S165 第二轮）

拿真定时任务压测，暴露的不是"功能不够"，而是**退出码不可信**——同一族错误在四处重复：

| 位置 | 症状 | 根因 |
|---|---|---|
| `ledger.main` | `return 2` 全被吞 | `a.f(a)` 不接返回值 |
| `ledger.dispatch` | 硬编码 `return 0` | 判定算对了没交出去 |
| `link.dispatch` | 整个 link 系恒 0 | `DISPATCH[a.cmd](a)` 不接返回值 |
| `conductor.cmd_whoami` | 缺参打印用法却 exit 0 | `return` 而非 `return 2` |
| `call_bus` quiet | 零字节输出 | `quiet` 被写成"全关" |

后果最典型的一条：`ledger call ingest`（没给候选文件）**一条都没入库，却判 ✅ok**。

**这族缺陷在生态里是第三次出现**，而且跨语言：

| 语言 | 写法 | 为什么吞 |
|---|---|---|
| Python | `a.f(a)` | 不 `return`，函数掉到末尾返回 `None` |
| Python | `DISPATCH[a.cmd](a)` | 同上 |
| Shell | 函数体内 `exit 1` | `exit` 在函数体里只结束**那段逻辑**，调用方拿到的是函数返回值 |
| Shell | `case` 分支裸调用 | 返回值被 `case` 吃掉，`main` 掉到最后一行 → 恒 0 |

判据一句话：**判定算出来之后，有没有一条 `return` 把它送到进程退出码上**。
三种语言的错法长得不一样，错的是同一件事——所以每次改判定逻辑，都要顺手 `echo $?` 验一次。

修法与判据（别退回去）：
1. **dispatch/main 必须 `return`**，别在模块层再归一一次（入口 `_as_exit_code` 已处理 bool/int）。
2. **quiet = 只留关键行**，不是静默。定时任务要的正是"这次动了什么"。
3. **必填参数前置校验**：动词表里 `[方括号]` 内是可选，`<尖括号>` 才是必填；
   首版把 `[<定时任务名>]` 当必填，`debt` 被自己的校验拦住。
4. **技能名先核存在性**：不存在的技能"名下 0 条欠账"是**假绿**——不是没欠，是没人认这笔账。
   建议只给一步之差的（`prob-hub`→`probe-hub`），不给"看起来像"的（会把用户带偏）。

### 另外两个真缺陷（本层暴露）

- **`core_ledger.add_entries` 静默类型错**：批量新增接口要 `[{字段: {类型: 值}}]`，原实现多包了一层
  `{"properties": …}`，每个 value 不是 dict → `validate_properties` 返回 `{}` → 报
  「校验后为空」**但 exit=0**。账房真实写入走 `post()`（扁平，恰好对），所以只在建账/补登等
  边缘路径发作——**同一条通道一半对一半错**，最难发现。已改为两种入参都接。
- **`settle` 只拍快照不回写余额**：诊断显示「账册不符」（最多 5 户挂红），处方却不写。
  已补回写；`balance` 另加「有余额但不在科目表」显式告警（此前这类户**记账了却一行都不显示**）。

## 纪律（每条都来自已发生的事故）

1. **settle → post → close**：凭证必须在闸门关闭前落账（L160 教训：close 后写库被静默拒）。
2. **终验相关分录未平 → finalcheck 拦截**。
3. **删库三件套**：快照 → 删 → 回读 0，缺快照直接拒绝（S160 规则）。
4. **包装器不吞错**：所有子进程透传 stdout（F02）。
5. **期初只建一次**：账户库非空即拒绝重复建账（F13）。
6. **账记了要看得见**：新户必须先登科目表再记账；`balance` 的 ghost 分支就是这条的探针。

## 联动

- 输入：会话台账（凭证号空间）、version_guard / docsync / signal-check 输出（只消费不重查）。
- 输出：日结快照 `scripts/daily_snapshot.json`；暂记账户余额 = 生态可控性体温计。
- 方向单向：账房只读检查器输出，检查器不调账房（防 F12 循环依赖）。
- **调用总线例外且单向**：`ledger call` 会调其它技能，但**其它技能不调 `ledger call`**
  （它们要记账就直接 `ledger post`）。否则会形成 A 调 B 记 A、B 调 A 记 B 的记账环，
  试算永远平不了。
