# tvbox-source-blacklist（失效源治理）

> TVBox 数据源体系的**质量闸门**。核心命题：失效源（停用的采集站、死 host）不应反复污染源总库；
> 一旦判定失效，按 **host 拉黑**，未来新源检测时主动触达、直接隔离到失效库。

## 1. 用途
- 从实测结果提取失效 host / 单条，写入**失效源库**（🗑 失效源库 `92dSuG6uUbxitGuyx4Saaf`；实时计数以 `tvbox block stats` 为准，文档不写死——规则47 数字唯一权威源）。
- 新源入库**前**调用拦截判定：命中拉黑 → 不进源总库，直接归档失效库。
- 支持复测：对整域拉黑 host 重新探测，疑似复活则从库移除（标 `已复活`）。

## 2. 触发词
失效源 · 拉黑 · 拦截 · host 屏蔽 · 失效库 · 停用源 · 死链

## 3. 用法（引擎 `scripts/blk.py`）
```bash
blk.py mark                       # 从 /tmp/probe_result.json 提取失效 host/单条 → 写失效库
blk.py check <api接口>            # 单条拦截判定（退出码 0=放行 1=拦截）
blk.py guard --candidates x.json # 批量：读候选 → 拆 放行/拦截 两份，拦截的归档失效库
blk.py list [--host 关键字]       # 查失效库
blk.py stats                      # 统计
blk.py review [--limit N]         # 复测整域 host，识别复活
```
- **拉黑三档**：整域(host全灭) / 单条(部分失效，保守) / 单条(host为空，按 api 精确)。
- **拦截计数**：每次 `check`/`guard` 命中会把对应失效库条目的「拦截次数」+1（实测反馈闭环）。

## 4. 联动（L7：与源总库、快照的闭环）
本技能是 `tvbox-source-hub` 的 **`ingest` 统一入库管线**的第一道闸：
```
候选源 → blk.py guard 拦截 → 放行部分: 分类→实测→入源总库→snapshot
                          → 拦截部分: 直接归档失效库（不污染源总库）
```
> 用户原话："根据 host 对失效源标记拉黑，以后新源检测时触达这个源，不再进行源总库入库，直接放到失效库"
> —— 本技能即该意图的落地：拦截判定是**主动触达**的，不是等人想起。
