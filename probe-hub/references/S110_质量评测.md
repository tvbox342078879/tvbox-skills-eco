## 3.11 ★ 质量评测：画质 / 速度 / 广告（S110）

> 用户原话：「数据源质量如何把控，比如播放速度，广告，画质，能把这个做进去闭环么」

`livecheck` 只回答**能不能拉到播放地址**，不回答**拉到之后好不好用**。
「假通过」大量存在：接口返 200、播放地址非空，但真去拉那个 m3u8 是 403/超时；
或者能拉但只有 480p、首片 8 秒、中间插两段广告。

| 脚本 | 作用 |
|---|---|
| `scripts/quality.py` | 单条评测：拉主清单 → 读 RESOLUTION → 拉首个分片测耗时与速率 → 扫广告特征 → 合成质量分 |
| `scripts/quality_batch.py` | 接两库：读库 → 取播放地址 → 8 并发评测 → 回填 6 字段 |

```bash
python3 quality.py <m3u8地址>                                  # 单条
python3 quality_batch.py --db 成品源库 --workers 8             # 批量回填
python3 quality_batch.py --db 成品源库 --limit 20 --dry        # 试跑不写库
```

**回填字段**（两库同名）：`最高画质` / `首片耗时` / `下载速率` / `广告判定` / `质量分` / `质量证据`

### 评分模型（校准两次才对）

**画质是门槛，速度只是加减分**——这条是踩坑踩出来的：

| 版本 | 权重 | 结果 |
|---|---|---|
| v1 | 画质40/速度40/广告20，速率 2MB/s 才满分 | 29 条 1080p **全卡 65 分**，26KB/s 与 326KB/s 同分 → 速度无区分度 |
| v2 | 画质50/速度30，按实测分位数定档 | 360p+402KB/s 拿 **100 分**，反超 1080p+169KB/s(94) → 本末倒置 |
| **v3（现行）** | 画质定基准 + 速度/首片有限加减 | 90 种组合**全矩阵严格单调**，任何速度下 1080p>720p>480p>360p |

基准分：`1080p 92 / 720p 76 / 480p 60 / 360p 44 / 未知 56`；速度 ±8、首片 -10~0、广告 -15/-30。
档位取自 111 条实测分位数（速率 P25=174 / P50=225 / P75=316 KB/s）。

### 三条必须写进结论的限制

1. **沙箱测速 ≠ 用户家宽**。云端视角与运营商/地域都不同，速度只能作**同批源之间的相对比较**，不得当绝对值断言。对外文案一律写「沙箱实测 X KB/s（相对参考）」。
2. **线路源库无法评测**。620 条全是 `csp_` / `./xxx`，沙箱没有 spider 环境解析不出播放地址 → 620/620「无法判定」。这不是失败，是结构性限制。**质量评测只对成品源库（真实测活通过的源）有意义**。
3. **广告判定是启发式**。域名黑名单 + `EXT-X-DISCONTINUITY` 特征；短剧源天然分片短会误判成「疑似」，最终要人眼确认。

### 四个解析坑（都会导致「好源被判死」）

| 坑 | 症状 | 修法 |
|---|---|---|
| 画质按宽度分档 | `1920x1080` 里的 1080 比 1900 阈值 → 判成 480p | 改按**高度**分档（1080/720/480/360 是短边） |
| mp4 也测速 | 整文件只拉到开头，算出 1KB/s | 非 HLS 直接标「未测速」 |
| 测速把握手算进分母 | 好源被误杀 | 用 `time_starttransfer` 剥掉连接开销，加 0.15s 下限 |
| CMS 播放地址没洗 | `$$$全集完结$` 粘在 URL 末尾 → 12 条里 4 条假 404 | 按 `$` 切段，优先取 `.m3u8` |
