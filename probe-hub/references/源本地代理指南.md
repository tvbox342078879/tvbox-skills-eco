# DsPlayer 源本地代理指南（t3 源全引擎）

> 面向源作者与 AI 源开发助手。讲清楚两件事：
> ①各引擎的源**怎么拿到壳子的本地代理地址**（函数/变量）；
> ②源内**代理回调钩子怎么写**（函数名、入参、返回契约）。
> 本文档是壳内权威口径，与代码同步维护（改动代理注入面时必须更新本文）。

---

## 一、一句话总表

| 引擎 | 源内拿代理地址 | 代理回调钩子（源内实现） | 返回契约 |
|---|---|---|---|
| **dr3** | `await ctx.getProxyUrl()`（async；裸名 `getProxyUrl()` 同样可用） | `proxy(params)` 钩子 | 五元组 `[status, contentType, content, headers?, toBytes?]` |
| **dr2** | 全局**同步**函数 `getProxyUrl()`；拼完整回调链用 `js2Proxy(...)` | `proxy(obj)` 钩子（proxy1 协议） | `[code, type, content, headers?, base64?]` |
| **cat 直连源** | 全局 `getProxyUrl(local)`（宿主直注）；`_ENV` 同步注入 | `proxy(array, json)` 钩子（catvod/proxy2 协议，经 `js2Proxy` 的 `from=catvod` 进入） | `{code, buffer, content, headers}` |
| **py** | env 注入 `proxyUrl` 字段：模板 `getProxyUrl()` 直读；影图系源从 `__init__` 的 `t4_api` 参数拿 | `localProxy(param)` 或 `proxy(param)`（模板双命名） | `[code, mime, content, headers?, toBytes?]` |
| **t4**（drpyS 服务端源） | 源函数内 `let {getProxyUrl} = this;` → `getProxyUrl()`——drpyS **服务层注入的环境变量**，返回局域网/外网代理地址 | `proxy_rule` 钩子（this 注入 `input`/`proxyPath`/`getProxyUrl`） | 服务端职责，壳不转发 |
| **php** | `$this->getProxyUrl()`（BaseSpider 注入：桥通道=服务层 proxyUrl；php -S 通道=自身脚本 `?do=proxy&`） | `localProxy($params)` 方法（两通道统一钩子） | 桥通道走网关五元组；php -S 通道直出 HTTP |

**通用约定**：代理地址形态统一为

```
http://127.0.0.1:<端口>/api/<siteKey>/proxy?do=<引擎>&siteKey=<siteKey>
```

- `<端口>` **动态**（9978 起，被占顺延到 9998）——**禁止写死 9978**，必须用上面表格里的函数/变量拿；
- 网关未启动时注入值是**空串**，源内应降级（拼出来的链接不可用，不要硬编码兜底地址）；
- 局域网设备拉流不走这个地址（见 §七）。

## 二、dr3 源（ESM 单文件，壳内推荐格式）

> 引擎说明：dr3 源由壳内 **qjs_ultra 引擎**（自研 QuickJS + C 扩展）执行，原 fjs 引擎已退役（2026-09-27 换核）——源内看到的 `globalThis.fjs` 只是兼容保留的桥名，与 fjs 引擎无关。

### 拿地址

```js
export default {
  meta: { title: '示例', host: 'https://example.com' },
  // ...
  async category(ctx, tid, pg, filter, extend) {
    // 写法一（推荐）：ctx 方法，async 必须 await
    const proxy = await ctx.getProxyUrl();
    // 写法二：§8.1 裸名（同为 async 函数，一样要 await）
    const proxy2 = await getProxyUrl();
  },
}
```

- `ctx.getProxyUrl()` 返回：`http://127.0.0.1:<端口>/api/<siteKey>/proxy?do=drpy3&siteKey=<siteKey>`（末尾无 `/`，直接追加 `&url=...` 等参数）。
- **坑**：dr3 的 `getProxyUrl` 是 **async 函数**（dr2 是同步函数）——裸名跨引擎移植源时忘 `await` 会拿到 Promise，字段全 undefined。
- 拿到后自拼参数：`proxy + '&url=' + encodeURIComponent(原链)`。

### 回调钩子（源内 `proxy` 钩子）

```js
// 网关收到 /api/<key>/proxy?... 请求 → 调源内 proxy 钩子
async proxy(ctx, params) {
  // params = 请求全部 query（url/do/siteKey/自定义参数）+ 注入能力字段：
  //   params.__range      —— 播放器发来的 Range 头原文（分段解密流用）
  //   params.__mediaProxy —— 流式出口基址（302 用，见 §五 toBytes=2/3）
  const url = params.url;
  const bytes = await 解密下载(url);            // 例：AES 密文图/加密 ts 段
  return [200, 'image/jpeg', bytes, {}, 1];     // 五元组，见 §五
}
```

- 典型场景：封面/图文密文解密中转（如 AES 图床）、wasm 解密的 ts 段（壳对该分支自带段缓存 + inflight 去重，播放器超时重连不重复解密）。

## 三、dr2 源（drpy2.min.js 体系）

### 拿地址

```js
// 全局同步函数（drpy2.min.js 内置，内部调宿主注入的 getProxy(true)）：
const proxy = getProxyUrl();
// → http://127.0.0.1:<端口>/api/<siteKey>/proxy?do=js&siteKey=<siteKey>

// 拼完整图片回调链（对齐 catvod Global.js2Proxy，自动带 from=catvod）：
const p = js2Proxy(false, 'siteType', siteKey, encodeURIComponent(url), JSON.stringify(headers));
// → ...proxy?do=js&siteKey=<key>&from=catvod&siteType=...&siteKey=<key>&header=...&url=...
```

- `js2Proxy(dynamic, siteType, siteKey, url, headers)` 五参数顺序与 URL 编码必须按此写（对齐 FongMi catvod 原版）；源内 siteKey 传空时壳回落真实 key。
- 宿主未注入时 `getProxyUrl()` 返回空串（壳约定：不编造硬编码地址）。

### 回调钩子（源内 `proxy` 钩子，proxy1 协议）

```js
function proxy(params) {
  // params = { url, do, siteKey, header, from?, ... }（全部 query）
  const data = 解密或下载(params.url);
  return [200, 'image/jpeg', data, {}, 0];   // [code, type, content, headers?, base64?]
}
```

## 四、cat 直连源（catvod JS，单文件或依赖 catLib）

### 拿地址

宿主对 cat 源幂等注入（`__cat_selectors_ready` 哨兵）：

- `globalThis.getProxyUrl` = 宿主 `getProxy` 本体 —— `getProxyUrl(local)`，返回 `...proxy?do=js&siteKey=<key>`；
- `globalThis._ENV`（空对象兜底，drpy-node catvod.js env polyfill 同款）。

```js
function category(tid, pg, filter, extend) {
  const p = getProxyUrl(false) + '&from=catvod&siteType=&siteKey=' + siteKey +
            '&header=' + encodeURIComponent(JSON.stringify(headers)) +
            '&url=' + encodeURIComponent(vodPic);
}
```

更常见的是直接用 `js2Proxy(...)`（dr2 段的写法，cat 源同样可用）。

### 回调钩子（源内 `proxy(array, json)`，catvod/proxy2 协议）

网关按请求里 `from=catvod` 分流到 proxy2 协议：url 按 `/` 切成数组、header 单独 JSON 解析后传入：

```js
function proxy(paths, params) {
  // paths = params.url.split('/')；params = { header: {...} }
  const url = paths.join('/');
  const data = 解密(url);
  return { code: 200, buffer: 0, content: data, headers: {} };
  // buffer:1 = content 是 base64（壳转字节）；0/缺省 = content 直写
}
```

## 五、代理返回契约（统一口径）

网关 `_writeProxyResult` 按元组第 5 位 `toBytes` 解释 content（对齐 drpy-node api.js）：

| toBytes | content 形态 | 行为 |
|---|---|---|
| 缺省/0 | 字节（bytes/Uint8Array）或字符串 | 直接回写响应体 |
| **1** | **base64 字符串或 dataURL** | 解码为字节回写（JS/py 引擎传二进制字符串时用） |
| **2 / 3** | `http` 开头的原始 url 字符串 | **302 到 `/mediaProxy`**（壳流式代理，Range 转发/段缓存）——大流（视频/直播）别自己拉全量，交给它 |
| **4**（py 大载荷） | `file://` 槽文件路径 | 流式回写零解码（py 端 ≥64KB 大响应专用，写完即删） |

- 返回 `null` / 长度 <3 → 网关回 502；
- headers 位可省略；
- 《drpy3 源写作指南》§6.8 的第 5 位 bool 写法（true/false）是 bundle 旧口径，落本表「缺省」路径，兼容可用；**新源建议用数字口径**；
- **空图兜底**：图片解密失败必须回 1×1 透明 GIF，**绝不能回 404/空体**（播放器/卡片会判整批失败白图）：

```js
// 1×1 透明 GIF（43 字节，base64 → toBytes=1）
return [200, 'image/gif', 'R0lGODlhAQABAIAAAAAAAP///yH5BAEAAAAALAAAAAABAAEAAAIBRAA7', {}, 1];
```

## 六、py 源（hipy 影图系）

### 拿地址（三种等价通路，按你源所属生态选）

1. **hipy/drpys 模板**：壳以 env 注入（JSON），模板函数 `getProxyUrl()` 直读 `env['proxyUrl']`；
2. **影图系源**：`__init__(self, t4_api)` 的 `t4_api` 就是代理地址（影图壳约定）。从它 `split('siteKey=')[0]` 得基址后自拼 `?do=py&siteKey=<key>&url=...`（壳注入的地址**已带** `&siteKey=`，网关 query 兜底路由，照影图写法拼不会丢）；
3. **直接读 env 字段**（壳注入完整 JSON）：`proxyUrl`（代理地址）、`requestHost`（网关根）、`mediaProxyUrl`（流式出口）、`ext`（源 ext 原文）。

注入形态：`http://127.0.0.1:<端口>/api/<key>/proxy?do=py&siteKey=<key>&extend=<ext>`。

### 回调钩子

```python
def localProxy(self, param):        # 模板命名 localProxy / proxy 均可
    # param = 全部 query dict + __range/__mediaProxy 注入字段
    url = param.get('url')
    data = decrypt_download(url)                          # bytes → 直接回写
    if not data:
        return [200, 'image/gif', TRANS_GIF_BASE64, {}, 1]  # base64 字符串 → toBytes=1
    return [200, 'image/jpeg', data]
```

- 壳经 AIDL `call(key, 'proxy', env, [query])` 调用；大载荷（≥64KB）走槽文件直传（`slotDir`），源返回 `file://` 引用即可，免 base64 双向编解码。

## 七、服务端跑的源：t4（drpyS）与 php

这两类源**不在壳进程内执行**，代理地址由 **drpyS 服务层注入**（壳网关对其恒回 501 `T4 源代理在服务端`——这是设计不是缺陷）。

### 拿地址（标准写法，官方源同款）

drpyS 把环境变量挂在**源函数的 `this`** 上，每个函数里解构后直接调：

```js
// lazy / proxy_rule / category / detail ... 每个需要的函数里都这么写
async lazy() {
    let {input, flag, getProxyUrl} = this;   // ← 服务层注入的环境变量
    return {
        parse: 0,
        // 拼法一：追加 query（走默认 ?do=ds 分发）
        url: getProxyUrl() + '&url=' + base64Encode(hdUrl),
        header: {...},
    };
}
```

`getProxyUrl()` 返回：`<protocol>://<hostname>/proxy/<module>/?do=ds&extend=<ext>`——**protocol/hostname 由服务端按 public 配置/访问入口解析**，所以拿到的是**局域网/外网可达**的代理地址（这是它和壳内三引擎恒回环的本质区别），不是 `127.0.0.1` 硬编码。

```js
// 拼法二：取基段后拼自定义路径（配合 proxy_rule 的路径形态）
let proxy_path = 'hls/xxx/segment.m3u8';
let url = getProxyUrl().split('?')[0].rstrip('/') + '/' + proxy_path;
// → http://host:port/proxy/<module>/hls/xxx/segment.m3u8
```

**不要**拿 `t4_api` 去解析自拼代理地址——t4_api 只是接口入口参数，代理地址的唯一正道就是 `this.getProxyUrl()`（官方源「设置中心」「央视大全」均此写法）。

### 回调钩子（源内 `proxy_rule`）

```js
proxy_rule: async function () {
    let {input, proxyPath, getProxyUrl} = this;   // input=query 参数；proxyPath=路径段
    let url = proxyPath || input.url;             // 拼法二对应 proxyPath，拼法一对应 input.url
    // ...解密/改写后按 §五契约返回
    return [200, 'application/vnd.apple.mpegurl', 改写后的m3u8文本];
}
```

### php 源

php 源跑在 `class Spider extends BaseSpider` 模板上（两条执行通道共用），**BaseSpider 已内置代理能力，写法与全引擎统一**：

```php
public function init($extend = "") {
    $proxy = $this->getProxyUrl();   // 代理回调基址，两通道都可用
    // 影图系封面中转：$proxy . 'url=' . rawurlencode($pic)
}

// 本地代理钩子（drpyS 网关与 php -S 通道统一入口）：
public function localProxy($params) {
    // $params = 全部 query（url/do/ext/__range/__mediaProxy…，桥通道同 JS 源）
    $data = 解密或下载($params['url'] ?? '');
    if (!$data) {
        return [200, 'image/gif', self::TRANS_GIF_BASE64, [], 1];  // 空图兜底
    }
    return [200, 'image/jpeg', $data];   // 五元组契约，与 drpyS 网关同款
}
```

`getProxyUrl()` 按通道返回：

- **drpyS 桥通道**（php 源经 drpyS 服务执行）：`_bridge.php` 把服务层 env 注入 Spider（`setEnv`），返回 `<protocol>://<host>/proxy/<module>/?do=ds&extend=`——局域网/外网可达，语义同 t4 JS 源；
- **php -S 直跑通道**（插件 php-runtime 的 t4_demo 站点源，每个 .php 即 T4 API）：`run()` 自感知，返回自身脚本 `http://<host>/<源名>.php?do=proxy&`——**localProxy 就是回调端点本身**（网关 501 无妨，源自足）；`run()` 已内置 `do=proxy` 分发（五元组直出，`toBytes` 1=base64 / 2,3=302 直跳 / 缺省直写）。

两类通道壳网关都不转发 php 源代理——桥通道由 drpyS 服务端承接，php -S 通道由源自身端点承接。

### 封面提示

t4 源的封面也可直接给 `data:image/...;base64` 内嵌（壳 2026-10-07 起原生支持，见 SOURCE-COMPAT #28），大图建议仍走代理短链。

## 八、局域网与投屏说明

- 三引擎注入的代理地址**恒为本机回环**（`127.0.0.1`）——它只给**壳自己**（卡片/播放器）用；
- 局域网设备（投屏/外部播放器）可达性由网关在**回调时**按请求 `Host` 头拼（`__mediaProxy` 即此形态）——源内做 302/流式出口时用 `params.__mediaProxy`，别自己拼局域网 IP；
- `getProxy(local)` 的 `local` 参数：true=回环地址、false=局域网地址形态（js2Proxy 的 `dynamic` 参数同义）；壳当前对 false 形态未启用独立注入（与回环同址），源内无需区分。

## 九、常见错误速查

| 症状 | 原因 | 处置 |
|---|---|---|
| 图片/流全白、代理 404 | 源内写死 `9978` 端口 | 一律 `getProxyUrl()`/env 拿，端口动态 |
| dr3 源拿代理得到 `Promise`/undefined | `getProxyUrl` 是 async 忘了 `await` | `await ctx.getProxyUrl()` |
| dr2 源同写法在 dr3 挂 | 两引擎 getProxyUrl 同步/异步不同 | 跨引擎源用 `await ctx.getProxyUrl()`（dr2 无 ctx 时分支处理） |
| 网关 502 `source proxy returned nothing` | 源钩子返回 null / 元组不足 3 位 | 检查钩子名与返回契约 |
| 图片解密失败整批白图 | 兜底回了 404/空体 | 回 1×1 透明 GIF（§五） |
| 影图系 py 源代理死链（siteKey 空） | 壳注入地址无 `&siteKey=`（老版本） | 升级壳；现版已带，源从 t4_api split 提取即可 |
| drpyS 源拼出错误代理地址 | 拿 `t4_api` 解析自拼（t4_api 是接口入口不是代理地址） | 函数内 `let {getProxyUrl} = this;` 直调（§七） |
| 播放大流经代理卡顿 | 源自己拉全量再回写 | toBytes=2/3 让壳 302 到 mediaProxy 流式 |
