## 为什么必须有它

S148 就已经能写源了，也跑通了（api.yyzy-tv.vip，7/7 全过），
**但产物落在 `/tmp/forge/spider.py`——一次关机就没了**。

「验完不留档」这件事**没有任何机制会报警**。它不报错、不告警、不影响任何一次运行，
它安静得跟正常没两样。这正是本模块要堵的失效方向：**不是报错，是没发生**。

## 它的位置

探源司第 6 个业务模块，与「监测 / 搜索 / 采集 / 测活 / 破甲」并列。
前五个管**别人做好的源**，这一个管**自己要造的源**。

## 用法

```bash
tvbox probe forge verify <源.py> [--save]   # 验源；--save 则「通过」后留档到 sources/
tvbox probe forge list                      # 留档清单 + 索引/磁盘不一致项
tvbox probe forge classify <api>            # ★实测判源类型（CMS采集/m3u8直链/JSON配置/无法判定）
tvbox probe forge classify --in x.json --out y.json   # 批量，供写库前定字段
```

### `classify` 的判据：只看响应行为，不看 url 路径

**这一条是实测打脸打出来的。** 第一版按 `api.php/provide/vod` 这类路径推断，
认为「路径像 CMS 就是 CMS」，一次性填了 93 条。抽查那 5 条待判的，**4 条判错**：

| 接口 | 按路径推断 | 实测 | 打脸点 |
|---|---|---|---|
| 子域名带 `m3u8` 的那条 | m3u8直链 | **CMS采集** | 域名带 m3u8 不代表返回 m3u8 |
| 非标准路径那条 | 无法判定 | **CMS采集** | 路径不标准不代表不是 CMS |
| `ac=class` 返回视频列表那条 | 不是标准 CMS | **CMS采集** | 见下 |

最关键的一条：**真标准 CMS 的 `ac=class` 也返回视频列表，不是分类。**
说明该参数本来就不是 CMS 标准的一部分——拿它当判据，等于拿一个不存在的标准去判。

现在的判据：

| 判定 | 依据（实际读响应体） |
|---|---|
| `CMS采集` | `ac=detail&pg=1` 的返回**同时**含 `vod_play_url` 与 `vod_play_from` |
| `m3u8直链` | 返回体以 `#EXTM3U` 开头 |
| `JSON配置` | 返回体是带 `sites`/`lives` 的 json |
| `无法判定` | 连不上 / 非 200 / 超时——**不折叠成「没有」也不折叠成「失败」**（M-R60） |

`classify` **只读不写**。写库仍要走 `build.py` 的 `_wrap` 按 schema 包装后再 `batch_update`，
因为 `源类型` 是 `select` 字段，手写 `{'text': ...}` 会静默失败（回 `success:true` 但不落库，
这个坑已实测踩过一次，12 条全绿却一条没变）。

## 三条铁律

### 1. 没验过的不许进 `sources/`

`--save` 只在 `verdict == 通过` 时生效。三态各有处置：

| 验证结果 | 含义 | 处置 |
|---|---|---|
| 通过 | 5+2 项全过 | 允许留档 |
| 失败 | 源本身写错了 | **拒绝**留档，退出码 1 |
| 无法判定 | 站点慢/网络不可达，**源未必有问题**（M-R60） | **拒绝**留档，退出码 0 |

「无法判定」也拒绝留档，理由不是「它有罪」，而是**还没验成**。
把没验成的东西放进库，等于给下一个人埋雷。

### 2. 正、负两面账都要清

`forge list` 会同时报两种不一致：

- **磁盘上有、索引里没有** → 绕过 forge 直接 `cp` 进来的，验证结果未知
- **索引里有、磁盘上没有** → 文件被删了但账没销

只查一面等于留一个后门：绕过命令放进去的源，永远不会被任何检查看见。

### 3. 不做「配置驱动自动生成源」

S161 实测遮天法 v3.1 的真实完成度：

| 项 | 宣称 | 实测 |
|---|---|---|
| 核心能力 | 10 项 | **7 项只有定义、无调用点**（`retry_with_backoff`/`aes_cbc_decrypt`/`break_referer_lock`/`extract_player_url`/`generate_signature`…） |
| 配置段 | 23 段 | **4 段从未被读取**（`fields`/`encryption`/`retry`/`special_classes`） |
| 「化龙·九变·九种协议」 | 9 种协议 | **26 行、1 个方法** |
| 13 层播放提取 | 13 层 | 第 1 层 `group(1)` 抓的是**变量名** `player_aaaa`，不是 URL |
| m3u8 清洗 | 修正 MEDIA-SEQUENCE | `#EXT-X-ENDLIST` 出现 **2 次**，第 4 行就插了一个 |

这套「改配置就能适配新站」的写法在我们这里**未经验证**，不引进。

本模块只负责**收**（留档）、**验**（真跑）、**列**（盘点）。
「写」这个动作仍然是人/AI 逐站写——**这是诚实的能力边界，不是缺口**。
遮得住的是「写不出来」，遮不住的是「假装能自动写」。

## 留档规范

- 目录：`sources/`，索引 `sources/index.json`
- 文件名：`<host主域去点>.py`，例 `yyzy_vip.py`（主机 `api.yyzy-tv.vip`）
- `getName()` 写站点中文名，不许写「优质」「通用」这类无信息量的名字
- 每次 `--save` 都记：`verified_at`、逐项 `steps`、`ok_n/total_n`、来源 `src_path`

## 探针（自检 ㉘）

判据三条，**缺一条就判红**：

| 判据 | 断言 | 为什么这么定 |
|---|---|---|
| 坏源被拦 | 语法错 + 逻辑空，两个都必须被判非通过，且都不许落进 `sources/` | 只看一种坏法会漏掉另一种：语法错拦住了不代表逻辑空也拦得住 |
| 索引未污染 | **逐名核对**索引里没有 `bad_syntax`/`bad_empty` | 只比条数会漏「一进一出」：旧脏被清、新脏被加，条数不变 = 假绿 |
| 不偷存 | 不加 `--save` 时 `sources/` 文件集合不变 | 防止「反正要留档，加不加参数都存一份」 |

### 两条踩出来的教训（都写进探针了）

**① 探针造的脏，探针必须自己擦。**
第一版「清理后清零」只看「这次跑完索引条数有没有回落到 before」。
故障注入演练时坏源被错误留档 → **脏数据固化进索引**，磁盘文件却被删了，
于是变成「索引有、磁盘无」的孤儿账，而那时 `before` 早被抬高，判据照样绿。
修法：注入前先 `_revoke` 清场 + 判据改成逐名核。

**② 写后必须回读该字段的值（M-R77）。**
`_save_index` 用 tmp 文件 + `os.replace`，写完立即 `_load_index()` 回读，
核对 `file` 与 `last_verdict` 两个字段——不只看「写没写成功」。
S160 踩过：`json.dump(d, open(fp,'w'))` 不关句柄就 load，读到半截。

### 故障注入实测记录

把 `if verdict != '通过'` 短路成 `if False`（模拟"什么都不拦"）：

```
⚠️ 写源留档探针不达标：坏源被拦=False 索引未污染=False 不偷存=True
❌ 写源留档·没验过的不许进 sources/ ：捕获=否 清理后清零=否 假阳性基线=净
探针结果: 27/28
```

还原后：`✅ 捕获=是 清理后清零=是 假阳性基线=净`，`28/28`。
索引只剩真通过的 `yyzy_vip.py`，脏数据被探针自己擦干净了。

## 成品源库字段落法（P018 第②项·三系口径 1025 修订）

| `源类型` | `可进包` | `体系`（三系口径） | 条数 | 说明 |
|---|---|---|---|---|
| `CMS采集` | 是 | **直链系** | 94 | 标准苹果 CMS，api 是 http 直链、type=1、客户端自带解析，**不需要 jar**（1025 改正：原误标「需jar」） |
| `js源码` | 需类包 | **脚本系** | 12 | `drpy2.min.js`，js 版的 py，需 js 引擎宿主（1025 改正：原误标直链系） |
| `CMS采集` | 空 | 待判 | 2 | 待补 |
| `py源码` | 需py引擎 | **脚本系** | 1 | `yyzy_vip.py`，真 py（1025 改正） |
| `JSON配置` | 是 | 按包内线路逐条打标 | 1 | 轻量 json |
| `m3u8直链` | 是 | **直链系** | 1 | 直播 m3u |
| 空 | 是 | 留白 | 1 | 502 无法判定，按三态留白（P020） |

**三条容易搞混的（三系口径 1025 更新）：**

- **`体系` 按「靠什么活」三分：csp 系（jar 真身）/ 直链系（type=1 且 api 为 http 直链，含 CMS 采集站）/ 脚本系（py/js/壳/解析器/判不出）**。
  CMS 采集站 api 是 http 直链 → **直链系**，不是 csp 系；py/js 源 → **脚本系**。
  想找 py 源要看 `源类型`，不是看 `体系`。
- 历史口径「需jar/直链系」两分已废弃；「需jar」≈ csp 系。存量迁移按 S161 判据表逐条 readback。
- **`平台形态` 与 `源类型` 选项集完全相同，是冗余字段**，不必两处都填。
