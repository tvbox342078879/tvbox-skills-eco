# 分类完整性检测（S101 · 正文）

> 本文件是 `SKILL.md` §3.7 的正文正本（M-R77 法①外置）。

> 用户 2026-10-16 反馈："有的线路打开只有某几个分类，点其它分类是空的"。
> 根因是**分类树取数不完整**——本技能管其中第①坑（第②坑 `?ac=list` 写死在整包坊 §3.1）。

**病根**：苹果CMS 用 `type_pid` 分层——`0` 是父分类，非 0 是子分类。只取父分类 → 缺细分；数据挂子分类 → 点开为空。

**检测**：`livecheck --kind class`（真请求 `?ac=class`），或 `--batch` 里 `kind=class`。

**四态判据（`check_class`）**：

| 判定 | 含义 | 体征 |
|---|---|---|
| `完整` | 父子俱全，子分类挂对了爹 → **可取数** | 父 N / 子 M 均有 |
| `仅父级` | 只有 `type_pid=0` 的父分类 → **会缺细分/点空** | 父 N / 子 0 |
| `仅子级` | 只有子分类无父分类 → 分类栏会乱/无归类 | 父 0 / 子 M |
| `无分类` | 接口不返回分类树（非苹果CMS / 分类接口缺失） | 无可解析树 |
| `无法判定` | 分类接口超时/不可达（≠死，M-R60） | 全路超时 |
| `失败` | 分类接口 4xx | 全路 4xx |

**实测（S101，3 源均判"完整"✅）**：

```
✅ [class] 完整 — 父10/子34（https://cj.lziapi.com/api.php/provide/vod?ac=class）
✅ [class] 完整 — 父7/子44（https://360zy.com/api.php/provide/vod/at/json?ac=class）
✅ [class] 完整 — 父8/子40（https://api.xinlangapi.com/xinlangapi.php/provide/vod/from/xlyun/at/xml&ac=class）
```

**与成品源库联动**：`harvest promote` 前若 `kind=vod`，分类完整性属加分证据——判「仅父级」者入库标注 `分类完整性=仅父级`（不拦，只警示）。
> 容错：`_parse_class_tree` 兼容 JSON / XML `<ty pid=>` / list 三形态，且**须显式带 `type_pid` 语义**才认作分类树。
