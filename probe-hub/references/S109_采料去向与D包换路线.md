### 为什么"D 包换路线"是一条独立高频动作

- D 包**零 jar 零 spider** → 换设备/换壳子都不怕，是**最稳的底座**；
- 但直链**会失效**（作者停服 / 换域名 / 防盗链）→ 必须**周期性用新采的活直链替换**；
- 而 csp 类的 L/G 包"换内容"是改配置指向（jar 不动），**性质完全不同**——所以 D 包需要**独立的一条供料线**。

### 采料 → 换路线 的完整回路

```
harvest scan/pull   ──►  取回站点/直链候选
        │
        ▼
livecheck.check_auto ──►  真实测活（点播真拉 vod_play_url / 直播真拉分片字节流）
        │                 只留「通过」，失败/无法判定三态如实标注
        ▼
harvest promote     ──►  写入「探源司·成品源库」DB_PROD（拿来即可放进 json）
        │
        ▼
用户据成品源库      ──►  给 D 包（DmaxPro908）换掉失效路线，补入新活直链
```

### 硬约束（沿用探源司既有铁律）

- **不拉流验证，不交付**（S097 用户铁律："你没实际拉流就给做json…我设计这个技能是要真实可用"）；
- 直链筛选判据 = `api.startswith('http(s)://')`（与 `split_box.py`/`split_jsm.py` 同口径，M-R38 单一事实源）；
- 供 D 包的直链**必须走测活闸**——失效直链进了 D 包会直接"转圈"。
