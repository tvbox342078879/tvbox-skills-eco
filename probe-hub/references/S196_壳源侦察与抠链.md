# S196 · 壳源侦察与抠链（shellcrack 正本）

> 索引在 SKILL.md §3.16（M-R77 法①外置）。本文件是唯一权威正本。

## 定位

**第三类料源**：CMS 站 `ac=detail` 的 `vod_play_url` 给的不是 m3u8 直链，而是**播放页壳**
（`/share/<hash>`、`/play/<id>` 等页面）——直链（harvest 管）和 py 源（forge 管）之外的第三类。
壳内 JS 变量里藏着真直链，本模块负责发现与变现。

## 命令

```bash
tvbox probe shellcrack probe  <api> --name X [--save]   # 形态分诊：直链站/壳/API死，是壳当场抠
tvbox probe shellcrack crack  <页面URL> [--save]         # 抠单个壳
tvbox probe shellcrack scan   [--in 清单.json] [--save]  # 批量（内置 scripts/shellcrack_cands.json 14 站）
tvbox probe shellcrack status                           # 壳库 readback（入库后必须回读）
```

## 金律正则（顺序即契约，不可换）

| 优先级 | 正则目标 | 模板指纹 |
|---|---|---|
| 1 | `const url=…m3u8…`（相对，须 urljoin） | Artplayer（相对 url 或绝对直链） |
| 2 | `const vid='…'` | DPlayer+hls.js |
| 3 | `const vid="…"` | 同上 |
| 4 | `var main=…m3u8…` | **第三模板**：DPlayer+ckplayer 双挂（+var playlist 多码率+var mp4 备份，茅台 S196 发现） |
| 5 | 裸 `https://…m3u8` | 页面内直出 |

**const url 必须排在 vid 之前**——否则 vid 双引号正则先命中 hex id（无 .m3u8）抢匹配（S196 实测坑）。
vid 值可能跨行含空白：命中后 `re.sub(r'\s+','',…)` 再 urljoin。

## urljoin 金律

壳内相对路径、master 清单子清单行、分片行都可能是 `/` 开头绝对路径——**一律 urljoin**
（对 http 绝对行也安全）。`base+` 拼接会双路径 404（茅台站实测：`…/ccGxXzM7//20261021/…`）。

## 判活闸（与 livecheck 同构）

「已抠」必须**真拉分片 >1KB**。三态：
- `已抠`：分片真拉到且 >1KB，备注记段数/首片/速率
- `壳死`：页面拉不到
- `抠出但链死`：m3u8 拿到但清单无分片/分片过小/分片 404
- `待抠`：页面通但正则未命中＝非 CMS 模板，**如实报，不硬凑**

## 混合形态定性（新浪 xlyun，S196 实测）

`api.xinlangapi.com` 的 `from/xlyun` 变体接口**活着**，但返回的是 play 壳（每片一个 hash，
不带 .m3u8 后缀）——上轮 from_probe 判「未中」实为「接口给壳」新形态。抠得出单片直链
（`play/<id>` + `/index.m3u8`），但**进不了 type=1 直链 json**（TVBox 需 .m3u8 后缀），
须 spider 嗅探。如实登记进壳库，不硬进包。

## 由来与教训

S196 跨站实验（LunaTV 实测清单 10 站）验证流程可复制后固化为模块 G。实验三收获：
①第三模板 `var main` 现身；②通用脚本 bug：master 子清单/分片行 `base+` 拼接 404（改 urljoin）；
③新浪「接口给壳」定性翻案。
