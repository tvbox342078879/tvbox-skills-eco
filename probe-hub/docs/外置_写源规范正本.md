## 三、写 drpy3 源的三条硬判据

从正本提炼，落进 `forge` 的检查顺序：

1. **能声明的全部声明**——`rule` 字段覆盖"分类→列表→详情→播放→搜索"五件事，
   `class_name`/`class_url` 一对就能让 `home` 零代码；**只有真需要写代码的环节才上钩子**。
2. **钩子优先、缺省回退**——同一源内混用是常态，钩子存在走钩子，没写的环节回退声明式引擎。
3. **`js:` 片段内是 drpy2 老写法**——`request()` 而非 `await ctx.req()`；可渐进迁移。

## 四、边界（诚实）

这两份文档描述的是 **drpy3 宿主运行环境**（DsPlayer 的 QuickJS + libquickjs_bridge）。
我们的 `forge verify` 验的是 **py 源**（`livecheck --spider` 五步真跑），
**不验 drpy3 js 源**——写 js 源时本目录只是格式参考，能不能用一律以宿主实跑为准（M-R60）。
