## 3.5.1 ★ 黑名单主键与三层分级（S144·**M-R96**·含并入的 M-R97/M-R99）

> **M-R96**（合并原 M-R97 指纹归一化口径 + 原 M-R99 写库判真）：
> ① 黑名单（失信库 `hGwE41OpJDOR8CW0sLUwRx`）主键必须是**源指纹**，不是 host；
> ② 指纹归一化**唯一实现** = `probe.py::source_fp()`，禁各技能另写一套；
> ③ 判定数据写入必须**读回字段值**，`success=true` 不等于写进去了。

### 为什么不能用 host（三处实测硬伤）

①**同 host 判定不一致**：`m3u8.apiyhzy.com` 下一条通过、另一条不可达 → 按 host 拉黑会连坐。
②**整域判死与活源矛盾**：122 host 中被判「整域全灭」4 个，**3 个实测通过**（`apilj.com`/`aosikazy.com`/`m3u8.apiyhzy.com`）。
③**同源多写法分裂**：`fhapi9.com` 同源有 `/provide/vod`（通过）、`/at/json`（判死）、`/?ac=list`（判死）三种写法 →
不归一化则一条活源对应两条死记录。

### 指纹归一化口径（原 M-R97 · 现属 M-R96）

**S145** 补③④⑤（CMS「取法变体」漏归一导致同站存多条）；**S146** 再补⑦⑧（「同一文件的编码写法」
与「加代理前缀的同一 URL」被当成两条）。

```
① scheme 忽略（http/https 同源）
② host 小写 / 去 www. / 去端口
③ path 去 /at/<格式> 段        ← json / josn / xml 都是输出格式，不是站点标识
④ path 去 /from/<源名> 段      ← 指定播放源，同一站的不同镜像
⑤ path 折叠连续斜杠 + 去尾斜杠
⑥ 丢弃 query 与 fragment       ← ac=list / ac=videolist / at=json 只是取法
⑦ path 做 unquote（URL 解码）  ← %E5%A4%A9%E5%A4%A9 = 天天，同一个文件两种写法（S146）
⑧ path 里出现第二个 http(s):// → 截取其后的内层 URL 递归归一（S146）
                               ← https://gh-proxy.com/https://raw.githubusercontent.com/... 
                                 就是裸 URL 套了一层代理，剥掉代理仍是同一个文件
返回 `<host><path>`（如 cj.lziapi.com/api.php/provide/vod）
```

> **顺序：先剥代理再解码**（反之编码过的代理前缀会先变 `https://` 混进 path，剥时吃掉内层 `/`）。
> S146 踩过：`r'/https?://'` + `inner.lstrip('/')` 把 `path='/https://raw…'` 剥成 `https:/raw…`
> （少一个斜杠）→ 归一对不上**且不报错**。正解 `re.search(r'https?://', path)` + `m.start()>0` + 递归。
> `probe blacklist fp <api>...` 自证；`self-check` 含 6 组合并 + 2 组区分反例 + ⑦⑧ 归一（含少斜杠反例）。

### 分组唯一性（S146 · **M-R103**）

**指纹相同只是必要条件**。一条线路必须**只在一个分组**——同指纹横跨「影视」「直播」= 同一份内容
被当成两条推给用户，这是「只留一条真实线路」在**分组维度**上的漏项。
**同指纹跨分组 / 同组内多条 = 错误**（只留最规范那条）；**同 host 不同 path = 正常**（两个仓库的 js，ℹ️ 提示）。

- **规范度** `_canon_rank(url)` → `(扣分,理由)`，**分越低越规范**：`seaxml`+300、代理+200、
  `/at/`+100、`/from/`+100、简写端点+50、`%XX`+20、query+5、明文 http+1（逐项依据见 CHANGELOG v1.4.0）。
- **「同源」不许靠人眼** `_same_line(a,b)` 三判据，命中任一即同一条：①`total` 相同 ②同片首播相同
  ③文件类 `sha256` 相同。**取不到数据返回 `None` → 不合并、标「待人工」**：判不了≠同一条，
  宁可留两条等人看，不许凭地址相似就删。

**三次收敛的实测轨迹**（依据全在 `CHANGELOG.md`，此处置信结论）：
191 条实际只有 107 个 host（`cj.lziapi.com` 6 条、`api.guangsuapi.com` 6 条、`360zy.com` 4 条）
→ S145 归一化去重到 **114**（`keep 114/114、drop 77/77`，全量翻页复核）
→ **S146 补 ⑦⑧ + 分组唯一性校验，收敛到 109**（删 5 条，三条 CMS 带 `total`+同片首播双证据、
两条仅 URL 编码差异；`删除判真 5/5`）。
终态：**109 条 / 指纹唯一 109 / 重复组 0 / 跨分组 0**，再跑 `dedup` 幂等删 0。

### 三层分级（写入失信库 `拉黑层级` 字段）

| 层 | 判据 | 动作 |
|---|---|---|
| **L1 精确黑** | 失败 ≥2 次 **且** 首末失败间隔 ≥1 天 | 新源进库直接丢弃，不测活 |
| **L2 观察** | 未达 L1（含仅失败 1 次、间隔不足、无时间跨度） | **不丢**，拦下强制真实测活；通过则写 `判死状态=已平反` |
| **L3 域名预警** | 同 host 下 ≥3 个指纹全 L1 | **只降权，永不丢弃**（排序后置） |

### 三条铁律（写死在 `load_blacklist()` 里，不是文档口号）

- **R1 平反优先**：`判死状态=已平反` **不进拦截集**，任一层命中都不再拦。
- **R2 活源免疫**：成品源库 `真实测活=通过` 的指纹**禁止**写 L1（`_live_fps()` 前置校验）。
- **R3 单次失败永不判 L1**：`judge_level()` 对 `fails<2` 或间隔不足一律 L2，代码层堵死。

> **实测（S144）**：262 条 → 237 指纹 → **L1=185 / L2=52 / L3=10 host**，`L1 ∩ 活源 = 0`；
> 6 个曾被整域误杀的活源全部落 L2 标免疫。
> **边界**：`blacklist` 只做「已判死源的记录与检索」，**判死本身仍由 `harvest filter` 的真实测活产生**——
> 本模块不许自己造判死结论。

### 写库判真：读回字段值，不是「写入成功」（原 M-R99 · 现属 M-R96）

`success=true` **不等于**写进去了。S144 实证两种失败形态，只看回执分不出：

| 失败形态 | 回执表现 | 实际结果 |
|---|---|---|
| `select` 字段形态不对 | `success=true`，无 error | **值全为空**，一个字不报 |
| 任一字段名不在 schema | `invalid fields: [...]` | **整条记录被拒**（不是只丢那一个字段） |

正确写法（`select` 传**字符串**，`multi_select` 传**数组**）：

```python
'分组类目': {'select': '直播'},              # ✅ 字符串
'可用体系': {'multi_select': ['直链系']},    # ✅ 数组
'分组类目': {'select': {'text': '直播'}},    # ❌ 服务端报 unmarshal 错
```

**判据**：写入后按**字段集合**读回，**期望非空而实得为空 = 失败**。
`_cloud_insert()` 的 `_count_success` 只验了条数，验不了字段值——
所以关键写入必须另做一次 readback 字段比对。

> **同一字段的三次失败别再踩**：①字段名不在 schema → 整条被拒，报错只提那一个名字，
> 容易误以为「只是这个字段没写进去」，其实整条都没进；②`select` 传 dict → 服务端 unmarshal 报错；
> ③`select` 传得对但**值不在选项枚举里** → 同样是 `invalid fields`，**枚举值必须先读 schema 再写**，
> 禁凭记忆写选项名（失信库的 `拉黑范围` 是 `整域/单条/观望`，不是 `单条(精确指纹)`）。
