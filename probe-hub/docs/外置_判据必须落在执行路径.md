# 判据必须落在执行路径上（S172 定案 · §3.13 ⑥ 正本）

> **一句话**：探针问"改坏了它还亮吗"——但**如果它从来没在验那个东西**，这个问题本身就是假的。
> 这一份是 S171 ⑤ 号缺陷（同侧变量互比）的**续集**：定案了、照做了，还是复发。

## 起象：15 条探针，首版 6 条是假的

S171 的定案是「探针与被检代码同居一文件、共用字面量 → 自己判自己通过；
**改用 AST 只取目标函数的字符串字面量**」。S172 建学习工坊引擎时严格照办，结果：

```
第一版 15 条探针 → 全绿
逐条做故障注入 → 6 条根本没抓住
```

AST 只解决了「取样范围」（不再把整份文件当取样池），**没解决「这个字面量到底在不在判据上」**。
一个字符串在目标函数里出现 3 次，可能是判定条件、可能是报错文案、可能是日志。

## 六个变种（全部实测，全部是第一版踩的）

### a. 报错文案冒充判据

```python
# 目标代码
if re.search(r'(__NUXT__|vite)', body) and len(plain) < 500:
    print('判定：⚠️ 无法判定 —— 200 但正文为空（SPA 壳）')
```

探针查 `'SPA' in lits` → **命中**。但 `'SPA'` 在 `print` 的文案里；
把 `re.search` 那行删了，`print` 还在，探针照样亮。

**正解**：只取**判定位置**的字面量——AST 里的 `ast.Compare`、以及 `ast.If` / `ast.While` /
`ast.IfExp` 的 `test` 表达式（真值测试 `if re.search(...)` 没有 Compare 节点，但**它就是判据**）。

### b. 工具当调用点

```python
def sha256_file(p): ...          # 工具：正确
def cmd_intake(a):
    if h in seen: ...            # 调用点：这里被改成按文件名，工具还是对的
```

探针测 `sha256_file(fa) != sha256_file(fb)` → **永远为真**。
把调用点改成「按文件名去重」，探针照过。

**正解**：**真跑目标函数**。造两个同名不同内容的文件，跑 `cmd_intake`，看 manifest 里是不是两条都算新增。

### c. OR 判据

```python
ok6 = ('__NUXT__' in l6 or 'vite' in l6) and (...)
```

同一正则的并列分支（`(__NUXT__|window.__INITIAL|vite)`）本来就是"任一命中即识别"。
探针再写一层 `or`，就把"三选一"降成"三选零"——删掉两个还剩一个，永远绿。

**正解**：**并列分支必须全在**（`all(k in l6 for k in spa_need)`）。
理由：识别能力是"少一个就少认一种"，不是"有一个就够"。

### d. 结果验不出路径

```python
def classify_failure(msg):
    for k in _UNKNOWN_MARKS:
        if k in m: return ST_UNK
    ...
    return ST_UNK          # ← 兜底
```

探针验 `classify_failure('412') == ST_UNK` → 绿。
但**兜底那句也返回 ST_UNK**：把 412 从名单里删掉，结果不变，探针照绿。

**正解**：验**理由**，不验状态。`classify_failure_why('412')` 必须返回
`(unknown, '命中「412」·我方或链路临时问题…')`——理由里得真有 `412`，说明是专门判据命中的。

> 附带的真修：`classify_failure` 原来只有状态、没有理由，本身就是设计缺陷。
> **归因不能只说"无法判定"，得说"凭什么"。**

### e. 并集冒充分支

```python
if sub == 'grounding':   ... print('判定：❌ 不通过 —— …')
if sub == 'coverage':    ... print('判定：❌ 不通过 —— …')
if sub == 'ratio':       ... print('判定：❌ 不通过 —— …')
```

探针取整个 `cmd_gate` 的字面量并集，查 `'不通过' in lits` → 绿。
把 grounding 分支改成"通过"，并集里还有 coverage / ratio 两份，照绿。

**正解**：只取**该分支内部**的字面量。写个 `_lits_of_branch(fnname, 'grounding')`，
用 AST 匹配 `if sub == 'grounding':` 然后只走 `n.body`。

### f. 探针里重算一遍

```python
# 探针里
seq = [1]
for i in range(1, 8):
    seq.append(3 if i == 1 else max(seq[-1]+1, round(seq[-1]*1.9)))
ok = all(seq[i] > seq[i-1] for i in range(1, len(seq)))
```

这是在验**探针自己写的那个循环**。把 `cmd_forge` 里改成 `seq.append(seq[-1])`，探针照绿。

**正解**：从**目标函数的输出**里抽数据——`cmd_forge` 打印「第1天 → 第3天 → …」，
探针跑它、抓 stdout、正则抽 `第(\d+)天`、再判递增。

## 三条硬要求（写判据前先过一遍）

1. **取自执行路径，不取自说明书**。报错文案、日志、注释里的字都不算判据。
2. **能行为测就行为测**。喂输入看返回，比任何静态分析都可靠；静态只用于"这个分支存在吗"这类结构断言。
3. **不许查一个自己会说的话**。提示语里写着「不许报『归因 0 条』」，
   探针若查 `'归因 0 条' not in 输出`，会被这句提示本身命中，恒假。

## 注入回归是唯一验收手段

```
15 条探针 → 逐条注入（把目标改坏）→ 必须当场红 → 还原 → 必须全绿
```

不注入就无法区分"探针在工作"和"探针在睡觉"。**而这二者的外部表现完全一样：都是绿的。**

## 这一轮的镜像缺陷：修一处漏一处

同一个 bug 在三个地方各写了一份拷贝：

| 位置 | 现象 |
|---|---|
| `sort outline` | `re.sub(r'^#+\s*|\s+', '', title)` → 有出处 0/6 |
| `gate coverage` | 同款再写一遍 → 覆盖 0/6 |
| `gate run` | 再写一遍 → 覆盖 0/6 |

**修了第一处、验了第一处，就以为好了**，结果另外两处照旧。
这就是 M-R38「同一判据只许一份实现」为什么是铁律，不是洁癖：
**判据多份拷贝时，"修好了"这句话是不可证的。**

正解：收敛成 `_norm()` 一处，并加探针⑬——AST 走遍全文件的 `re.sub`，
"去全部空白"的实现只允许 1 处（`_norm` 内部），出现第 2 处立刻红。
