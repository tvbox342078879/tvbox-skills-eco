# 原生态保留：写包不许让字段凭空没（S144·P7/P8·M-R101）

> 外置自 `SKILL.md` §3.5.2（M-R77⑥ 法③：论证型长节外置）。
> 主文件只留铁律 + 索引行；完整推演、校验器判据表、正确写法、`prune` 两态、`addto` 段落点全在本文件。

## 0. 为什么这一节存在

`lightjson` / `repack` / `prune` / `addto` 四条命令都是同一个危险动作：

> **读原包 → 改结构 → 写新包**

只要中间用「白名单重建」写代码，原包里没被列名的键就整体消失——而 `json.dump` 照样成功、
退出码照样 0、站点数照样对得上，**人完全看不出来**。这是静默缺陷的典型形态：
不是功能坏了，是功能空转。

> **铁律：结构可以变，字段不能凭空没。只做 reorder，不做 select。**

## 1. 实跑抓现行（不是推测）

S144 真跑时 `check_preserve` 当场抓到这条：金标准版 `lightjson` 的透传白名单

```python
order = ('spider', 'wallpaper', 'logo', 'warningText', 'lives')
tail  = ('parses', 'flags', 'hosts', 'rules', 'ads')
```

把作者包的 `version` / `customKeyNotInWhitelist` 全吃掉了。**这不是推测，是实跑红出来的。**

## 2. 校验器 `check_preserve`

```python
check_preserve(pkg_in, cfg_out, *, allow_drop, strict_passthrough, mutable)
```

| 判据 | 内容 | 不通过即 |
|---|---|---|
| ① 顶层键 | 原包有、新包无 → 红（`allow_drop` 里显式声明的除外） | `sys.exit(1)` |
| ② 站点字段 | 同 key/api 的站点，原条有、新条无的字段名 → 红 | 同上 |
| ③ 透传值 | `PRESERVE_PASSTHROUGH_KEYS` 必须值完全相等 | 同上 |
| warn | 输出站点数 > 输入（疑似混入） | 只提示不拦 |

`mutable` 是给 `addto` 用的：**本来就要改的段**（加一条线必然动 `sites` 或 `lives`）
跳过「值相等」比对，但**仍然校验字段不丢**——改是允许的，丢是不允许的。

## 3. 正确写法（别再写白名单）

```python
cfg = {}
for k in order:          # 已知键按金标准顺序排
    if k in pkg:
        cfg[k] = pkg[k]
cfg['sites'] = keep
for k in tail:
    if k in pkg:
        cfg[k] = pkg[k]

# ★ 关键三步：未列名的兄弟键全部补回，一个都不许丢
_extra = {k: v for k, v in pkg.items() if k not in set(order) | set(tail) | {'sites'}}
if _extra:
    cfg = {**_extra, **cfg}
```

「reorder 而不是 select」的落地方式就是最后那三行：白名单只决定**顺序**，
不决定**准入**。没列名的键走 `_extra` 原样补回。

## 4. `prune` 的两态必须分开（P8 修的不是校验，是误删）

旧 `_rebuild` 只认**测活通过**的 api → 「无法判定」的条目被一起删掉，
与 docstring 承诺的「无法判定不保留也不标死，单列待复测」直接矛盾。

**网络抖动一次就误删好源，是不可逆损失。**

- 保留 = **通过 ∪ 无法判定**；只有**明确失效**才删
- 跑完自动复核：
  1. 每条保留条目都能在原包溯源
  2. 无判死条目混入
  3. 三段条数期望 = 实得

这条与 §3.5.3「分母不是答案」同源：**判据不足时不许替用户做不可逆决定。**

## 5. `addto` 段落点：段落由形态定，不由参数默认值定

旧写法：

```python
tgt_key = 'sites' if a.type == 'sites' else ('lives' if ... else 'parses')
```

在**未指定类型时默认落 `parses`**——采集站被写进解析器段，写入成功、回读也在、
零报错，只有装进盒子才发现点不开。

| 形态 | 段落点 |
|---|---|
| `采集` / 普通直链 | `sites` |
| `m3u8` / `m3u` / `/live` | `lives` |
| 仅 `--type parses` 显式指定 | `parses`（`parses` 是**解析器**不是线路，绝不自动落） |

## 6. 一句话判据

> 写了新包，先问「原包里有哪些键我这次没提到」——答不出来就说明是 select。
> 校验器的存在不是为了通过，是为了在你想不起来的时候替你红一次。
