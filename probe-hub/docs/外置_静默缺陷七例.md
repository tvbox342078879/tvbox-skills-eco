# 静默缺陷七例：实测证据与推演（S169/S170/S171/S172/S195 · §3.13 正本）

> **一句话**：共同形态是**不报错、退出码 0、结果一直不变**——不是"功能坏了"，是"空转"或"归因错位"。

## 一、七例与实测证据

| # | 缺陷 | 实测证据 |
|---|---|---|
| ① | `上次检查` 写不进云端：列是 `date`、代码按 `text` 写，回执照样 `success: true` | `status` 永远「—」、`due` 永远到期、每轮重跑全量 |
| ② | 存活只看仓库主页（本网络时通时断） | 6 仓库 4 个 25s→000，但 API 全 200＝**监测面缺口伪装成健康度** |
| ③ | 黑名单按"失败几次"判死，不问"为什么失败" | 证书过期也是 2 次失败→判 L1；4 条误杀，其一 30 万条 |
| ④ | 网盘 412 并进「下载失败」（`pan` 命令） | **坏 token 也是 412**＝拦截在验签之前；同出口其他站 200 → **机房 IP 段被 CDN 边缘拒**（与 IPv6 无关） |
| ⑤ | 探针**自己判自己通过**（S171，连犯三次） | 判据字面量写在探针同文件里 → 改坏目标代码后判据仍被自己满足，恒过；改用 AST 只取目标函数字面量才抓得住 |
| ⑥ | **判据没落在执行路径上**（S172｜学习工坊 15 探针首版 6 条是假的） | AST 只缩小取样范围，没解决「这字面量是不是判据」 |
| ⑦ | 外部材料自带的 `self_test` 不能当证据（S195） | 上传的《遮天破甲模块》源码其 `self_test()` 是**假绿**——`except ImportError: pass` + 无条件 `print("✅")`，没测过也报全通过 |

## 二、逐例推演

### ⑤ 为什么比前四条更阴

前四条是**代码空转**，⑤ 是**校验空转**——探针与被检同居一文件、共用字面量（**同侧变量互比**）。

> **写探针先问：把目标改坏，它还亮吗？**

### ⑥ 是 ⑤ 的续集

S171 定案"AST 取目标函数字面量"，S172 照做了，15 条探针仍有 **6 条是假的**——
AST 只解决取样范围，没解决"这字面量在不在判据上"。

六变种（文案冒充判据／工具当调用点／OR 判据／结果验不出路径／并集冒充分支／探针里重算）
逐条正解见 [`外置_判据必须落在执行路径.md`](外置_判据必须落在执行路径.md)。

### ⑦ 外部材料的自检不能当证据

上手第一件事是**用构造数据证伪**（非法填充必须拒、真图必须逐字节还原），而不是跑它的自检看绿灯。
判定与处置见 [`../references/S195_吸收材料结案.md`](../references/S195_吸收材料结案.md)。

## 三、判据与验收

- 存活按 `API ok`→存活、`notfound`→已封禁、`限流/失败`→才退回主页
  （非主页判定的 `status` 显示「存活依据=…」）；
- 时间列走 `_cloud_upsert(date_cols=...)`；
- 证书类封顶 L2；**不可达类失败单列、带成因、给处置阶梯**；
- `self-check` 五条命门探针锁死。

> **验收**：回读 ≠ 回执；判定要说清凭什么；归因错位比不报错更毒。

## 四、三条硬要求

1. 取自**执行路径**，不取自说明书（报错文案里的字不算）；
2. 能行为测就行为测；
3. 不许查**一个自己会说的话**（提示语里写着"不许报归因 0 条"，那串字本身会命中探针）。

## 五、`pan` 另两条判据

1. 用户贴的是**整段文案**，含口令 `/~xxx~/`（极像 id）——只认 `/s/<id>`，口令单独输入返回空；
2. **`format_type` 判改名包**——实测 4 个 `.apk` 里 2 个原生是 `application/zip`，`.apk` <100KB 必预警。
