# 不许看见脚本就直接跑（S148 定案 · M-R104 · §2.1 正本）

> **一句话**：直接跑脚本只得"命令结果"；走技能得"结果 + 判据 + 验收 + 留痕"。
> 前者出错时没人告诉你错在哪。

## 一、病根：S148 全量实测

一次长会话 **12884 次工具调用**里：

| 项 | 次数 |
|---|---|
| `Skill` 工具被调用 | **3** |
| 探源司被加载 | **0** |

全程直接 `python3 scripts/probe.py ...`。后果不是"慢"，是
**SKILL.md 里的流程约束根本没被读**：

- §3.7 的分类空壳坑
- §3.5.1 的黑名单三铁律
- M-R60 三态契约

全靠"碰巧记得"才遵守，**不是被技能强制的**。

## 二、S189 现场：本节第二次复发

用户说「追踪原仓库」——触发词里明写有「上游仓库 / 作者仓库 / 原作者 / 原仓库」，
`conductor whoami` 也判得对，**但仍然没人调用本技能**，
直接手写 curl + 自拟判据跑完了整条链路。用户原话：「探源司怎么没看到触发」。

## 三、执行层补丁

`~/.codebuddy/hooks/skill_route_guard.py`（M-R133）：
命中真触发词且本轮未加载本技能时，PreToolUse `exit 2` 强制先 `Skill`。
判据见 `ecosys-conductor/SKILL.md §8.8`。

## 四、代价：没走流程欠下的三笔账

1. 上游状态没写 `DB_UPSTREAM`，下次还得从头查；
2. 没有快照对比，答不出"这仓库比上次更新了什么"；
3. 判据自拟，没走 `monitor check` 的四类信号口径。
