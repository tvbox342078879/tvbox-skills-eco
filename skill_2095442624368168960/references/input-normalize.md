# 输入归一化（把任何来源变成可排版的结构）

> 用户给过来的东西可能是 Markdown、Word 文本、纯文本、网页链接、甚至是一段口述要点。
> 排版前必须先归一化成同一个内部结构，否则组件选型会乱。

---

## 一、归一化目标结构

无论输入是什么，先整理成这份中间结构，再映射到组件：

```
meta
  ├─ 主标题           —— 全文唯一 H1
  ├─ 副标题           —— 一句话补充，可无
  ├─ 分类标签/日期    —— 头图卡上的元数据
  ├─ 底部摘要         —— 一句话钩子，放头图卡深色条
  └─ 作者 / 身份说明

body（有序区块列表，每块打上 role）
  ├─ { role: lead }            导语 / TL;DR
  ├─ { role: section, 编号 }   大章节标题
  │    ├─ { role: sub }        子标题
  │    ├─ { role: para }       正文段落
  │    ├─ { role: list }       并列要点
  │    ├─ { role: steps }      有序步骤
  │    ├─ { role: code }       代码块
  │    ├─ { role: table }      对照表
  │    ├─ { role: quote }      引用
  │    ├─ { role: keypoint }   重点观点卡
  │    ├─ { role: callout }    提示/警示
  │    ├─ { role: timeline }   时间线
  │    ├─ { role: image }      图片
  │    └─ { role: divider }    分割线
  └─ { role: ending }          收束总结

tail
  ├─ 作者签名段
  ├─ 结尾行动区（点赞/在看/转发）
  ├─ 来源标注（可选）
  └─ 话题标签（可选）
```

**输出 HTML 前，区块列表必须是确定的** —— 不要在写 HTML 的过程中临时决定"这段要不要做成卡片"。

---

## 二、按输入类型的处理

### 2.1 Markdown 文件

最理想的输入。按 `references/theme-<id>.md` 末尾的「Markdown → 主题映射规则」表直接转换。

需要人工判断的三种情况：
- **连续短段落**（每段 <40 字）→ 合并成组件 09 清单列表，否则版面会碎。
- **三层以上嵌套列表** → 拍平成两层，公众号里深缩进会挤成一条。
- **表格超过 4 列** → 拆成两张表，或转置成「参数 + 值」的条目卡（组件 10）。

### 2.2 Word / WPS 文本

粘贴过来的 Word 文本通常丢掉了列表符号和代码块缩进。识别方法：

| 特征 | 判定为 |
|---|---|
| 行首 `·` `•` `-` `1.` `1)` | 列表 / 步骤 |
| 整段等宽字体或含 `$` `#` `{}` `<>` | 代码块 |
| 行首缩进且短句、上下有空行 | 引用 |
| 独占一行且短（<20 字）、后面跟长段落 | 子标题 |
| 含 `http://` `https://` 独占一行 | 来源标注 |

Word 过来的文本**必须重新加全角标点**——Word 的中文标点常常是半角。

### 2.3 纯文本 / 口述要点

这是最难的输入，需要**先补结构再排版**：

1. 让用户确认主标题（或由内容提炼 3 个备选让用户挑）。
2. 按语义切分大章节，编号 01/02/03……每章 300~600 字为宜。
3. 每章内至少放一个「非段落」组件（列表 / 卡片 / 引用 / 表格），否则整章都是灰压压的文字块。
4. 提炼一句收束金句作为组件 16 的内容。
5. 缺作者信息时，主动询问，不要留 `{{作者名}}` 占位符。

### 2.4 网页链接 / URL

1. 先抓取正文，剔除导航栏、评论区、相关推荐。
2. 图片**必须下载到本地或上传图床**后替换 URL —— 直接用原站图片在公众号里会被防盗链拦截。
3. 抓取后按 2.1 的 Markdown 规则处理。
4. 无论如何要在文末加 `G06 来源标注`，写明原文出处。

### 2.5 用户已有 HTML 想换主题

1. 先把 HTML 反解成 §1 的结构（忽略原有样式，只保留语义）。
2. 丢弃全部旧样式，用新主题组件**重新组装** —— 不要做样式替换，改不干净。

## 三、Markdown 元素 → 语义 role（通用）

| Markdown | role | 说明 |
|---|---|---|
| `# ` | meta.主标题 | 全文唯一 |
| 首个 `> ` 块 | lead | 导语 |
| `## ` | section | 大章节，编号 01/02/03 |
| `### ` | sub | 子标题 |
| `#### ` | sub | 与 `###` 同级，**不再分第四层** |
| 普通段落 | para | 默认 |
| `- ` / `* ` | list | 并列要点 |
| `1. ` 且每项只有一行 | list | 转成清单列表 |
| `1. ` 且每项有标题+说明 | steps | 转成步骤/条目卡 |
| ` ``` ` | code | 走 G01 |
| 行内 `` ` `` | 行内代码强调 | 主题「强调 d」 |
| 表格 | table | 走 G04 / 主题组件 11 |
| `![alt](src)` | image | 走 G05 |
| `---` `***` | divider | 主题组件 14 |
| 非开头的 `> ` | quote | 主题组件 08 |
| `**粗**` | 强调 a | |
| `==高亮==` | 强调 b | |
| `<u>x</u>` `++x++` | 强调 c | |
| `~~x~~` | 强调 e | |
| 文末 `> ` | ending | 主题组件 16 |

## 四、归一化后的自检

进入排版前，确认这 6 条：

- [ ] 有且仅有一个主标题
- [ ] 章节数 3~8 个（少于 3 个说明结构太粗，多于 8 个说明切太碎）
- [ ] 每章至少 1 个非段落组件
- [ ] 代码块已确认缩进方式（`&nbsp;` 补位，不用 `white-space:pre`）
- [ ] 图片路径已全部替换为可公网访问的地址
- [ ] 作者 / 结尾互动文案已确定，无残留 `{{占位符}}`

任一条不满足，先补齐再排版。
