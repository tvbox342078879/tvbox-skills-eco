## 1.3 可执行骨架（`scripts/pipeline.py`，S068 建档）

> 本技能从"纯文档 SOP"升为**"文档 + 脚本"双轨**：把 §2/§3/§4/§5 里**最机械、最易错**的五步固化为可复跑命令。
> **文档仍是 SSOT**（脚本口径严格跟随 §0-§10；冲突以文档为准），脚本只是"把文档的手工动作自动化"。

```bash
python3 scripts/pipeline.py <命令>
```

| 命令 | 对应章节 | 作用 |
|---|---|---|
| `fetch <URL> --out <bin>` | §2 | 抓取 + 伪装形态识别（首字节魔数 + 双UA md5 判明文直出）|
| `health <file>` | §3 + §2.5 | 体检（type 分布/lives/spider/相对路径/本地助手依赖）+ 静态体系识别 |
| `spider <src\|path> [--base <配置URL目录>]` | §2.5.2 | **下载 spider 解包定 A/B**（zip 内 `assets/*guard*`→B，仅 `classes.dex`→A）；自动剥离 `;md5;` 后缀 |
| `split <file> --outdir <dir>` | §4.1/4.2/4.3 | 分类拆分（py/采集/直链/其他 + lives + parses，各产独立文件）|
| `dedup <file>` | §4.5 | 全量去重（站线 api+ext / lives name+url / parses url），落盘 `dedup_*.json/.txt` |
| `probe <file> --workers 12` | §5 | 全量测活（并发但全量，判定码 200\|206\|301\|302\|303\|307\|308），落盘 `alive_*.txt` |
| `run <URL> --workdir <dir>` | §1 | 一把梭：抓→体检→拆分→去重→测活（不替代 spider 下钻与入库登记）|
| `newapi <URL> [--probe] [--no-ingest] [--dry]` | §2→§3→§4→§5→§6 | ★ **新接口处理**一条链：抓→体检→拆→去重→（测活）→落线路源库。任一步失败即停并明说停在哪步；测活全灭不落库 |
| `packin <zip\|json> [--dry]` | §2.5 + §4 | ★ **整包入库**：zip 解包取全部 json 成员，逐个按体系归位后入线路源库；成员失败逐条列出，fail>0 退出码即 1 |

**边界（脚本不做的事，仍按文档人工执行）**：
- **入库/登记/复盘**（§6/§8）——涉及知识库写操作与判断，不脚本化
- **新体系建系**（§2.5.4）——`split` 报"新体系"后，人工建文件夹并在 §2.5.1 补行
- **18+ 隔离**（§4.6）——归类终点需人工判定，脚本只做通用拆分
- ID 类常量（`SYS_FOLDER`）与 §2.5.1 表**共用同一事实源**：文档改表时须同步脚本常量（M-R38 纪律）

> **`newapi` / `packin` 的三态纪律**：这两条是**唯一**会把外部内容写进源库的命令，故口径从严——
> ① 任何一步失败**立刻停**，不跑后续步骤（不制造"半截产物被当成品"）；
> ② 落库门面（`link.dest_db` / `link.add_records`）不可达时**报错退出**，绝不降级成"不落库还报告成功"；
> ③ `fail>0` 即退出码 1——"大部分成功"不等于成功（M-R60）。

## 2. 抓取

```bash
/usr/bin/curl -s -L -m 30 -A "okhttp/3.12.0" "<URL>" -o /root/.codebuddy/artifact/xxx_raw.bin
```
- **必须用绝对路径 `/usr/bin/curl`**（shell 里 `curl` 偶发 not found）。
- 存到 `artifact/` 下，扩展名统一 `.bin`，先看首字节判断真身：
  ```bash
  head -c 16 xxx_raw.bin | od -c
  ```
- 双 UA 验证伪装：换 `User-Agent` 再抓一次，比对 md5。一致 = 明文直出。

### 伪装形态识别表（经验积累）
| 现象 | 真身 | 处理 |
|---|---|---|
| 首字节 `\xff\xd8\xff` 但尾部有 base64 | JPEG 嵌套 | 取尾段 base64 解码（饭太硬） |
| Content-Type 标 `image/*` 但内容是文本 | MIME 障眼 | 直接当文本读（王二小/菜妮丝） |
| 带 BOM `\xef\xbb\xbf` + 两个空行 | 明文 json | `encoding='utf-8-sig'` 读 |
| 首行 `xxx,#genre#` | 明文 TXT 直播源 | 见 §4 三形态处理 |

## 2.5 体系识别（**收到 json 后第一个动作，先于一切加工**）

**拿到包后，第一件事不是拆、不是测，而是判定它属于哪个体系。** 体系决定：spider 怎么处理、csp 站能不能跑、最终成品包的命名前缀。

> **成品包命名铁律：`<体系><日期>_<站数>站[_补充]`**，例如 `A1015_156站_含黄蚂蚁11组`、`C1014_29站.json`。**没有体系识别，命名就是瞎起。** 这就是为什么体系识别必须排在最前。

### 2.5.1 四大体系（库内既定，判据如下）

| 体系 | 名称 | 判据（看 spider + csp api 形态） | 库内文件夹 |
|---|---|---|---|
| **A** | CatVod 标准系 | spider 是**标准 jar**；csp 站 api 为**裸类名**（`csp_Nmvod`/`csp_Czzy`） | `jxJHRZHyNzjY6fONPlFTe1` |
| **B** | moji Guard 系 | spider 是**加壳类**（moji guard） | `AJJixTz2yohkUz4Pu1zAXB` |
| **C** | 零 jar 纯直链系 | **无 spider / 无 csp**，站点全是 `type=0/1` 直链、采集 | `j7bD2jgogJxILWwKQv7ZMJ` |
| **D** | Amns 系 | 裸类名 + **`Amns` 后缀**（如 `csp_xxxAmns`） | `pqSV3xwMuZsgBLmPQSKdGh` |

> 另有独立分类：**🔞 成人直链系**（`SbPKgzcnGAsQ3cKjbRIJT4`），凡 18+ 产物一律归此，且**体系判定照常做**（它只是终点不同，见 §4.6）。

### 2.5.2 识别流程（固定三步 · 正本 `docs/manual_2_5_2_识别流程.md`）

**三步不可跳**：① **后缀即体系**（文件名/扩展名给强信号）② **技术血缘**（spider/jar/csp 引用判同族）③ 两者冲突或都判不出 → **标「待确认」**请用户拍板。**禁凭站点内容主题猜体系**。
> **S114 改锚（2026-10-18）**：体系归属看**jar 挂了什么**，不看站点清单用了什么——有 spider 体系随 jar（标准A/加壳B/Amns D/非标准E?），无 spider 且无 csp 才是 C；csp 无 spider 标 `A?` 查实录（采集丢字段≠作者没挂）。可平移三态判定见标准1015§二补。
> 每步判据表见 docs 正本。

### 2.5.3 体系识别产物（必须落盘 + 写进复盘）

| 产出 | 内容 |
|---|---|
| **体系结论** | `体系 = A / B / C / D`（含 🔞 标记；S114 起 `?`=待下钻/待实录确认，E=非标准 jar 待人工） |
| **判据留痕** | spider 真身、csp 数量、是否带 Amns 后缀 |
| **成品包名** | `<体系><日期>_<站数>站[_<补充>]`，如 `A1015_156站_含黄蚂蚁11组`、`C1014_50站_直链版`；S114 起加**内容标签**（`_直链N+cspM`/`_纯直链版`/`_仅py版`），如 `A1018_112站_cluntop_直链92+csp20` |
| **投递目标** | 该体系文件夹 id（见 2.5.1 表）；**无匹配 → 自动新建体系(§2.5.4)** |

### 2.5.4 新体系自动加入（A/B/C/D 都不匹配 → 自动建系 · 正本 `docs/manual_2_5_4_新体系自动建系.md`）

**触发**：后缀/技术血缘判定不出 A/B/C/D/🔞 任一。**做法**：① 抓 spider/jar 指纹 ② 查已有枝 ③ 仍无 → **建新系**（`create_folder.py`，命名=字母+系名）④ 更新《索引·底包总库》对照表 ⑤ 落复盘。**禁硬塞进近似的已有体系**。
> 建系命名规范、需同步的四处清单见 docs 正本。

### 2.5.5 体系校验（每次入库必做 + 定期全查）

**A. 入库时校验（单包，随流程走）**
- 包命名前缀是否 = 识别出的体系？
- 投递文件夹是否 = 该体系文件夹？
- 若是 18+ → 是否已归 🔞 且带 `🔞` 前缀？
- 三项有一项不符 → 修正后才算完成。

**B. 定期全查（每积累若干包 / 用户要求时）**

逐项核对，输出校验报告：

| 检查项 | 判据 | 不符时的动作 |
|---|---|---|
| **位置正确性** | 每个包的体系前缀 == 所在文件夹 | 移动到正确文件夹 |
| **命名一致性** | 全部符合 `<体系><日期>_<站数>站[_补充]` | 重命名 |
| **18+ 归位** | 含 18+ 的包必须在 🔞 | 移入 🔞 + 加 `🔞` 前缀 |
| **重复品** | 跨文件夹 / 同文件夹内的 md5 重复 | 标注 `_重复可删`（**库无删除 API，只能标注**） |
| **体系文档同步** | 文件夹内说明文档的"包清单"与实际一致 | 更新文档 |
| **新体系遗漏** | 有包不属于 A/B/C/D → 应已建新体系 | 补建体系文件夹 |

**校验三铁律：**
1. **md5 是重复的唯一判据**：名字不同不代表内容不同（本项目 zoho 就有 4 组 md5 相同的重复节点）。
2. **库无删除 API**：重复品只能**重命名为 `xxx_重复可删(原因)`**，提示用户手动删；**绝不假装删掉了**。
3. **先结构后内容**：先判 A/B/C/D/E（结构），再判是否 🔞（内容），顺序不能反。

## 3. 体检

```bash
python3 - <<'PY'
import json
from collections import Counter
d = json.load(open('xxx_raw.bin', encoding='utf-8-sig'))
print('TOP KEYS:', list(d.keys()))
if 'sites' in d:
    print('sites:', len(d['sites']), dict(Counter(s.get('type') for s in d['sites'])))
print('lives:', len(d.get('lives',[])))
print('spider:', d.get('spider'))
PY
```

### 关键判据
- `sites` 里 **type=3 占比高** → csp 包，依赖 dex jar，**站点价值低、lives 价值高**
- `spider: ./xxx.jar` / `./api/...` **相对路径** → 自托管整包
  - **必做**：拿配置 URL 的目录当 base 去探测 jar 与资源是否 200
  - **绝不做**：整包转存知识库（云盘 `download_url` 是短时效链接，做不了长期配置）
- `ext` 含 `127.0.0.1:9978` → 依赖本地助手，**没装就是空壳**，统计时扣除

## 4. 生成「用户可增删的 json」（核心）

### 三形态 → 三处理

**A. 已是 TVBox json 包** → 原样入库 + **拆 lives / 拆 py**（见 4.1、4.2）+ **提解析**（4.3）

**B. 纯 TXT/M3U 直播源**（`#genre#` 或 `#EXTM3U`）→ **自动拆成独立 json**（见 4.1）
```json
{ "lives": [ { "name": "...", "type": 0, "url": "<原URL>", "epg": "http://epg.51zmt.top:8000/api/diyp/?ch={name}&date={date}" } ] }
```

**C. 单站采集接口**（`xxx.php/provide/vod`）→ 最小 sites json
```json
{ "sites": [ { "name": "...", "type": 1, "api": "<URL>", "searchable": 1, "quickSearch": 1, "filterable": 1 } ] }
```

### 4.6 18+ 内容也走本流程（一视同仁，只多一步"单独隔离"）

**规则：18+ 内容与其他内容执行完全相同的流水线，不走简化、不走例外、不走跳过。**

> **历史教训**：曾因"18+ 特殊"而反复改口（先并包 → 又重打包入 18 库），白做一步。根因就是**把 18+ 当成了例外**。现在钉死：**18+ 就是普通产物，只是目的地不同。**

**18+ 全套流程（与 §1.0 六类完全一致）：**

```
抓取 → 体检 → 分类拆分 → 全量去重(§4.5) → 全量测活(§5) → 纯可用版 → 归类入库 → 登记 → 复盘
```

| 18+ 产物的类型 | 一样要做 | 唯一不同 |
|---|---|---|
| 18+ **lives** | 拆线 + 全量去重 + 全量测活 | 归 18+ 分类，不混入普通直播库 |
| 18+ **直链** | 拆条 + 全量去重 + 全量测活 | 归 18+ 分类，不混入普通直链库 |
| 18+ **采集/py/其他** | 同 py/采集流程 | 归 18+ 分类 |
| 18+ **素材/封面素材** | 拆条 + 去重 + 测活 | 归 18+ 分类 |
| 18+ **解析** | 提取 + 去重 + 测活 | 归 18+ 或解析库（按来源） |

**18+ 三条硬规矩：**
1. **完整走流程**：去重、测活、命名、登记、复盘，一个都不少——**不许因为"是 18+"就跳过测活或去重**。
2. **单独隔离**：产物**只落「18+ 独立分类」**（源总库内专用分类），**绝不与普通库混放**；命名带 `18_` 前缀便于识别。
3. **入库位置唯一**：目标库就是那个 18+ 分类，**开工前一次问清、定死后不再改**（避免重复"并包又重打"的返工）。

> **一句话：18+ 走的流程和别人一模一样，唯一区别是终点站在「18+ 专区」。**

| 坑 | 铁律 |

| `actions[0] type 无效` | 字段名是 **`type`** 不是 `action` |
