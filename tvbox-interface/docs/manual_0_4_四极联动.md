## ★ 四极联动自动触达（规则 45/46/47，命中即执行）

> 联动不是"想起来才做"，是**嵌进流程的自动动作**。下面每一步都**不等用户二次指令**。

```
开工  → link.py brief          （一次看清四极 + 业务坑 + 平台坑）
      → link.py audit  (可选)  （怀疑数字对不上时对账）
动手  → 按 §1~§5 处理
整包入库后 → link.py sync      （L1 自动提源：底包 → 源库）
遇业务坑   → link.py log       （当场记，不等收工）
遇平台坑   → link.py lib-log   （当场记，下次还会撞）
收工  → link.py log            （业务经验沉淀）
      → link.py snapshot      （刷新权威快照，保持四极数字一致）
```

| 触发点 | 自动动作 | 命令 |
|---|---|---|
| 新会话开工 | 跑一次速览，看清雷区 | `brief` |
| **操作资料库前**（上传/建表/改字段/写记录） | 查同类平台坑 | `lib-learn <关键字>` |
| 整包入库完成 | **立刻**提源，不等二次指令 | `sync` |
| 任一极**数量变动** | **立刻**刷新权威快照 | `snapshot` |
| 任一极**结构变动**（加列/加体系/新建夹） | 刷新快照 + 在文档补指针 | `snapshot` |
| 遇到业务报错/返工 | **当场**记业务台账 | `log --pit --fix --reuse` |
| 遇到资料库操作坑 | **当场**记平台经验 | `lib-log --pit --fix --reuse` |
| 用户问"现在有多少条/什么状态" | **以快照页为准**回答，不凭记忆 | 读快照页 |
| 新增一批源后（提升精准性） | 实测并回填状态 | `probe_src.py` |

**快照页引用方式**（重要）：文档里**不要写死快照 id**（刷新会重建页面改 id），
写「📊 状态·四极现状快照（唯一权威）—— 取标题为…的最新一份，旧份被自动改名为 ❌已废弃_快照_日期」。
当前有效 id 由 `snapshot_id.txt` 维护。

### 0.3 模型无关铁律（换任何模型都必须走同一条流程）

**本流程是"接口产线标准作业程序（SOP）"，不依赖任何具体模型。** 无论当前会话用的是哪个模型（GPT / Claude / Gemini / 豆包 / 混元 / DeepSeek / 本地模型 / 任何未来的模型），处理 TVBox 接口或本地包时，**必须 100% 按本技能 §1–§8 执行，一步不许省、一步不许改、顺序不许颠倒**。

| 换模型后「容易走偏」的表现 | 本技能的正确行为 |
|---|---|
| 只给分析报告 / 结构说明，不动手 | 直接开工，产出可用 json（§1） |
| 跳过"全量去重" | 去重是入库前置闸（§4.5），不做完不许入库 |
| 只测采样、不测全量 | 除站点外全量测活（§5） |
| 把采集/直链/py 合并成一个文件 | 三类分开拆单、分开归类入库（§4.2/§4.4） |
| 忘了登记知识库 / 忘了复盘 | 入库登记（§6）+ 强制复盘（§8）不可跳过 |
| 自作主张换一套命名/输出格式 | 按 §4 命名规范与 §4 输出格式 |
| 中文 URL 二次编码 / 用相对路径 | 中文原样绝对地址（§4 绝对地址规则） |
| 手写组件 id 入库报错 | 遵守 §7 组件语法铁律 |

**执行纪律（模型无关）：**
1. **本文件即唯一凭据（SSOT）**：任何模型的内部偏好、习惯、默认套路，一律让位于本技能。模型认为"更优"的做法，若与本技能冲突，以本技能为准。
2. **开工先读规则**：每个新会话/新模型接手，**第一动作是加载本技能全文**，再动手；不得凭记忆或"通用直觉"开工。
3. **产出必对齐**：产物类型、命名、目录、去重、测活、入库、登记，逐项对照 §1.0 清单打勾，缺一项即视为未完成。
4. **偏离即返工**：一旦发现走偏（漏去重 / 漏测活 / 合并分类 / 漏登记），**立即推倒重来对齐流程**，不带病交付。
5. **跨模型一致性**：同一接口，无论哪个模型处理，最终产物应"几乎一致"（同结构、同命名、同入库位置）；出现差异，以本技能为准并记入 §10 反面案例库。
