# 3 1 分类参数写死

### 3.1 ★ 分类参数写死检查（S101 — "点分类是空的"两坑之一）

**症状**：某条线路打开后**分类栏只有几个大项、点其它分类是空的**（用户 2026-10-16 反馈）。

**根因（两坑，本技能各管一个）**：

| # | 坑 | 归属 | 说明 |
|---|---|---|---|
| ① | 只取**父分类**丢子分类 | **探源司 `livecheck --kind class`** | 苹果CMS 分类树 `type_pid=0` 是父、非 0 是子；只取父 → 细分点开为空。详见 probe-hub §3.7 |
| ② | api 里 **`?ac=list` 写死** | **本技能（本节）** | api 写死 `?ac=list`/`?ac=videolist`/`?ac=detail` → 壳拼分类参数时被顶掉 → 点分类仍返回默认列表 → 显示为空 |

**为什么写死 `?ac=` 会出问题**：TVBox 壳点某个分类时，会往 api 后面**拼 `?t=<分类id>` 或 `&t=<分类id>`**。若 api 已写死 `...?ac=list`，壳再拼就变成 `...?ac=list&t=5`——部分接口对**参数顺序敏感**或直接忽略 `t`，于是无论点哪个分类都返回默认页（表现为"分类是空的/全是同一批"）。

**检查（`pipeline.py health` 已内建，§3.1 段自动告警）**：

```bash
tvbox health <配置.json>        # 体检时自动扫描 sites[].api
```

正则 `[?&]ac=(list|videolist|detail)\b` 命中即判"写死"，输出形如：

```
⚠️ 分类参数写死 2 条（§3.1）→ 点分类可能空：
     · [list] 索尼  https://suoniapi.com/api.php/provide/vod/?ac=list
     · [list] 魔都  https://www.mdzyapi.com/api.php/provide/vod/?ac=list
  → 建议去掉 `?ac=xxx`（让壳自行拼分类参数），或改用 `?ac=detail` 仅在拉详情时用
```

**处置（生成 json 时）**：
- **`?ac=list` / `?ac=videolist`** → **去掉**（写成 `.../provide/vod/`），让壳自行拼分类参数 → 分类可正常切换。
- **`?ac=detail`** → 仅在**拉详情**用途时保留；作为分类源写死同样有隐患，建议也去掉由壳拼。
- 例外：个别接口**必须**带 `?ac=list` 才返回列表（壳无自动拼接能力时）→ 保留但**在复盘标注**，供后续复测。
