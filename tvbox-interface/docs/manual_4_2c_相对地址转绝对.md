# 4 2c 相对地址转绝对

> 从 SKILL.md 外置（S130 P008 瘦身），正文未改。

### 4.2c 相对地址 → 绝对地址：**先验证可行性，再动手**（S100·实证固化）

**触发**：包内出现 `./` 开头的相对地址（`spider: ./xxx.jar` / `sites[].api: ./py/xxx.py` / `./lib/xxx.js` / `./tvbox.txt`）。

#### 为什么要转（本质）

| | 相对地址 | 绝对地址 |
|---|---|---|
| 形态 | `./py/央视.py` | `https://catbox.top/py/央视.py` |
| 解析 | **相对于 json 自身所在位置**（壳拿 json 来源 URL 当 base 拼） | 自带协议+域名+路径，**与位置无关** |
| 隐患 | json 一旦**换地方**（存本地/换域名/转交）→ base 失配 → 资源加载失败 | 谁拿到都能直接用 |

> **用户要的是"拿来即可放进 json"的成品**（P-R1 同族诉求）——相对地址是"寄生"在作者站点上的，脱离原站即失效。故：**能转则转**。

#### 铁律：转换前必须过"活体 base 验证"三步

**相对转绝对的前提是"知道真实 base 且它活着"——前提不成立就转不了，禁止硬编造。**

```
遇到 ./ 相对地址：
  ① 找候选 base（按优先级）
     a. 配置自身的目录（json 的 URL 去掉文件名）
     b. 同站主域（如 盒子迷.top → catbox.top，作者常有主站/镜像）
     c. 作者 GitHub raw（takage99/xxx → raw.githubusercontent.com/takage99/xxx/main/）
  ② 逐个探测资源可达性
     for base in 候选:  GET {base}/py/xxx.py  →  记 HTTP 码
  ③ 判定
     ├─ 命中 200 → 该 base 是真实的 → 转绝对 ✅
     └─ 全 404 / 全不通 → base 已死 → 转不了，如实告知 ❌（不硬编）
```

#### 转绝对时的两个规范（缺一不可）

1. **中文域名 → punycode**：`菜妮丝.top` → `xn--yhqu5zs87a.top`
   - punycode 是纯 ASCII，TVBox 壳兼容性更稳；**中文域名保持中文常因编码问题加载失败**。
2. **协议补全**：`//xxx.top/a.jar` 或缺协议 → 补 `https://`（优先 https，不通降 http）。

#### 实证案例（S100，两次对照）

| 案例 | 相对地址 | base 探测 | 结果 |
|---|---|---|---|
| **菜妮丝** | `spider: https://tv.菜妮丝.top/jar/fty1004.jar;md5;...` | punycode 域名探测 200 | ✅ **转成功**：改 `xn--yhqu5zs87a.top`，jar 实测可达 |
| **盒子迷** | `spider: ./...`、`./py/央视.py`、`./js/drpy2.min.js` | 盒子迷.top / catbox.top / takage99 GitHub **全 404** | ❌ **转不了**：`盒子迷.top` 只是静态介绍页（仅 `assets/`），**不托管 py/js/lib**；真实归属 base 已下线 |

> **反例警示（盒子迷）**：不要看到 `./` 就条件反射去拼同域绝对地址——**先探活再动手**。当时实测 4 个候选 base 全 404，结论是"**相对路径无法转绝对，因为原始资源服务器是死的**"。硬编一个猜的域名 = 造废源。

#### 与测活的联动（重要）

**相对地址（`./py/xxx.py`、`./lib/xxx.js`、`./xxx.txt`）无法直接 HTTP 测活**——它们没有独立 URL，脱离 base 无意义。故：
- 入库时**单列"不测类"**（区别于 http 类的"可测类"），**不折叠成"失败"**（M-R32/M-R60：无法判定 ≠ 死）。
- 若要测：先按上述三步找到活 base → 转绝对 → **再按 4.2.1 常规测活**。
