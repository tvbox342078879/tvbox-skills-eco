# 1 0 自动加工清单

> 从 SKILL.md 外置（S130 P008 瘦身），正文未改。

### 1.0 自动加工清单（一次抓取，全部产出）

抓到包后，**自动扫这几类，逐类处理，不遗漏**：

| 类型 | 自动动作 | 章节 |
|---|---|---|
| **直播类**(`lives` / `type=0` 源) | 拆成单独 json + **全量测活** + 归直播库 | §4.1 |
| **py 类**(`type=4` / `.py`) | 拆成单独 json + **全量测活** + 归纯py库 | §4.2 |
| **采集类**(`type=1` 苹果CMS) | 拆成单独 json + **全量测活** + **归采集库（独立）** | §4.2 |
| **直链类**(`sites` 里的 `type=0`) | 拆成单独 json + **全量测活** + **归直链库（独立）** | §4.2 |
| **其他类**(`type=2/3`) | 拆成单独 json + 全量测活 + 归其他库 | §4.2 |
| **解析**(`parses`) | **提取有效解析** + 归解析库 | §4.3 |
| **🔞 18+ 内容**(直链/直播/素材) | **同上面六类一样走全套** + 归 18+ 独立分类 | §4.6 |

**核心原则：**
- **采集、直链、py 三类走同一套流程骨架**（拆分→去重→全量测→归类），但**必须分开归类入库**（三个独立文件 / 三个独立库）
- `sites` 与 `lives` 都有 `type=0`，**看归属决定**：在 `lives` → 直播；在 `sites` → 直链
- **能出的全部出**：抓到包先看 type 分布 + `lives` 有无 + `parses` 有无，各类各跑
- **全量去重是入库前置闸**（§4.5）：**先拆分 → 再去重 → 后测活 → 才入库**
- **18+ 走同一套流程**（§4.6）：不简化、不跳过、不走例外，只多一步"单独隔离到 18+ 专区"

**固定顺序（不可颠倒）：**
```
抓取 → 体系识别(§2.5) → 体检 → 分类拆分 → 【全量去重】 → 全量测活 → 纯可用版 → 分开归类入库 → 登记 → 复盘
```

**命名铁律：整包成品名 = `<体系><日期>_<站数>站[_补充]`（如 `A1015_156站_含黄蚂蚁11组`）。** 体系未识别 = 不许命名、不许入库（§2.5）。

**速度第一。** 少问、少 dry-run、少读回，除非真的会出错。
只在「目标库/合并对象不明确」时才问一句，其余一律按本技能默认值执行。
