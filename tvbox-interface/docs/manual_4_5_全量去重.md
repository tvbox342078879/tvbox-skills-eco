### 4.5 全量去重（入库前必做，贯穿所有类型）

**入库前，必须对每一类产物做全量去重。去重是"入库前置闸"，不做完不入库。**

#### 4.5.1 去重范围（六类全覆盖）

| 类型 | 去重键 | 说明 |
|---|---|---|
| **lives 直播** | 组内 `name+url`；全量 `url` | 同名同地址只留 1 条；跨组同一路也去 |
| **py 线** | `api + ext` | 同脚本同参数只留 1 条 |
| **采集线** | `api + ext` | 同采集接口同参数只留 1 条（**勿只用 `api`**，不同 ext 可能是不同源） |
| **直链线** | `api + ext` | 同直链地址只留 1 条 |
| **其他线(type2/3)** | `api + ext` | 同上 |
| **解析(parses)** | `url` | 同解析地址只留 1 条 |
| **整包 sites** | `api + ext` | 站点重复时保留优先者 |

> **判据统一：同名同源才算重复。** 同名不同源、同源不同名一律保留（可能是别名或多线路备份）。

#### 4.5.2 去重方法（按类型）

**A. 站线类（py/采集/直链/其他）—— 按 key 去重**
```python
seen = set(); out = []
for s in sites:
    k = (s.get('api'), str(s.get('ext','')))
    if k in seen: continue
    seen.add(k); out.append(s)
```

**B. 直播类 —— 先组内去重，再全量去重**
```python
# 组内：同组同名同 url 只留一条
# 全量：跨组同名同 url 也去（防同一路被塞进多个组）
```
- **频道行级去重**：同组内完全相同的 `频道名,url` 只留 1 条
- **同 url 不同名**：保留（可能是别名）
- **同名不同 url**：保留（可能是多线路备份）

**C. 解析类 —— 按 url 去重**，同名保留第一个

#### 4.5.3 去重后处理

1. **统计去重前后条数**：`去重前 N → 去重后 M（删 K 条重复）`
2. **落盘去重记录**：`dedup_<类型>_<来源>.txt`（列出被删的重复项）
3. **去重后的文件才允许上传入库**
4. **跨包去重**（进阶）：若目标库已存在同名产物，先下载对比，避免重复入库

#### 4.5.4 去重与测活的顺序

```
拆分 → 【全量去重】 → 全量测活 → 纯可用版 → 入库
         ↑ 先去重再测活，避免对重复项做无谓测活
```

> **顺序铁律：先拆分 → 再去重 → 后测活 → 才入库。**
> 去重放测活前，能省去对重复项的测活开销；也避免重复项测出不同结果造成混淆。
