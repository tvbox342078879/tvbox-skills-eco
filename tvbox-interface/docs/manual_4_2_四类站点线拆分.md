# 4 2 四类站点线拆分

> 从 SKILL.md 外置（S130 P008 瘦身），正文未改。

### 4.2 四类站点线（py / 采集 / 直链 / 其他）→ 全部拆分成单独 json + 全量测活 + **分开归类入库**

**触发**：`sites` 里存在任一站点线。**四类走同一套流程骨架，但归入不同库。**

#### 4.2.0 站点线分类（第一步先分类，再统一加工）

先按以下特征给每条 site 打标签，**四类各归各的**：

| 类 | 判据 | TVBox type |
|---|---|---|
| **py 类** | `type=4`，或 `api` 为 `.py` / `drpy` / `hipy` / `csp_*.py` | 4（或带脚本的 3） |
| **采集类** | 标准苹果CMS：`xxx.php/provide/vod`、`?ac=videolist`、返回 `{"list":[...]}` | 1 |
| **直链类** | `type=0` 的站点（m3u/txt/xml 直链），或返回 xml/纯流 | 0 |
| **其他** | 非标 JSON 采集（脏格式，靠 ext 映射）、内置 csp 内置类 | 2 / 3 |

> **注意区分**：`type=0` 的**站点**（有分类/搜索的直链影视站）走本节；`lives` 段的 `type=0`（直播源）走 §4.1。二者都叫 type=0，但归属不同——**看它在 `sites` 还是 `lives` 里**。

#### 4.2.1 统一加工流程（四类通用）

**对每一类，逐条处理：**

1. **拆成单独 json**：每条线一个最小 sites json
   ```json
   { "sites": [ { "name": "...", "type": <0|1|2|3|4>, "api": "<绝对URL>", "ext": "<原ext>", "searchable": 1, "quickSearch": 1, "filterable": 1 } ] }
   ```
   - py 类命名：`py_<来源>_N条.json`
   - 采集类命名：`采集_<来源>_N站.json`
   - 直链类命名：`直链_<来源>_N条.json`
   - 其他类命名：`其他_<来源>_N条.json`
   - **同时留合集版**：`<类型>_<来源>_全部N条.json`
2. **全量测活**（**四类都必须全量，不允许抽样**）：
   - **py 类**：请求脚本 → 看能否返回含 `class`/`分类` 的合法 JSON
   - **采集类**：请求 `api`（`?ac=list` 或直接 GET）→ 看返回 `{"code":1,"list":[...]}` 或类似结构
   - **直链类**：请求站点根/api → 看返回合法 xml/json 列表
   - **其他类**：按各自接口试
   - 判定活：HTTP `200|206|301|302|303|307|308` **且**响应体结构合法
   - 逐条 `✅/❌` 落盘：`alive_<类型>_<来源>.txt`
   - 生成"纯可用版"（剔除死亡条目）
3. **分开归类入库**（**四类归四处，不混**，见 4.4 归类表）

> **关键：采集与直链必须分开归类入库**——不合并成一个文件，用户要能分别管理。

#### 4.2.2 与整包的关系

- 站点全部健康 → 整包也入根目录（备查）
- 站点大量死亡（如 csp 包）→ **整包不入库**，只把存活的拆线归类
- 四类中存活 0 条的 → 跳过该类，不产空文件
