### 2.5.4 新体系自动加入（遇到 A/B/C/D 都不匹配的包 → 自动建系）

**规则：不能只认识 A/B/C/D。** 遇到无法归入现有四系的包（新后缀、新加壳、新结构），**自动新建"体系 E/F/G…"**，一套做完，不等用户提。

**触发条件（满足任一）：**
- csp api 带**没见过的统一后缀**（不是裸类名、不是 `Guard`、不是 `Amns`）
- spider 解 zip 后是**新的加壳特征**（非 `ProGuard`、非 `ftyguard`/`wexguard` 的第三种 guard 资源）
- 结构是**全新的组织形式**（如纯 js、纯 py、无 sites 只有 lives+其他）

**自动加入流程（固定四步）：**
```
1. 判据留痕：记录该新体系的特征（spider 真身结构 / api 后缀 / 结构形态）
2. 建文件夹：在底包总库根目录建「📁 体系E·<特征>」，记录返回的 folder id
3. 建说明文档：内部建「体系E·<特征>（主用xxx）」doc，写清：体系特征 / 判据 / 本体系内的包
4. 归入包 + 登记：包命名 <体系E><日期>_<站数>站，移入该文件夹，并在 §2.5.1 表补一行
```
