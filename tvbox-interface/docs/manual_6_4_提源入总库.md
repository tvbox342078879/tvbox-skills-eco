### 6.4 有效数据源自动归入「数据源总库」（必做）

> **每个包处理完，凡测活通过的站点线 / 直播源 / 解析，必须抽出"数据源"行，批量进 source 总库。**
> 成包入库是"整包"维度，数据源入库是"线路"维度 —— 两者都要做，缺一不可。

**目标表**：`线路源库` database `pNwZ9uBOTz6FzRuvu8nryI`（S160 起 py/csp 合并同库，用 `源类型` 字段区分）
字段：`名称 | host | 分组类目 | api接口 | 源类型 | 体系 | 可用体系 | 状态`

> ⚠️ **旧库已停用，勿再写入**：本手册原写 `数据源总库 wW5xpbS…` 与 `备用库 G9B1GzfR…`，
> 两库自 S144 起已清空废弃（0 条）；S160 又把 py/csp/成品三库合并为「线路源库 + 成品源库」。
> 坐标一律以 `tvbox-source-hub/scripts/core.py: SRC_DBS` 为准（M-R38 单一事实源）。

**「可用体系」判定表（唯一判据，不用猜）**

| api 形态 | 依赖 | 可用体系 |
|---|---|---|
| `http(s)://...`（macCMS采集 / 直播源 / 远程 js·py / 远程 json） | **零 jar 依赖，跨系通用** | **全系**：A+B+C+D |
| `csp_XxxGuard` | 依赖 moji **加壳** spider | **B** |
| `csp_XxxAmns` | 依赖 Amns 系 spider | **D** |
| `csp_Xxx`（裸类名，无 Guard/Amns 后缀） | 依赖**标准 dex** spider | **A** |
| `./` `../` 相对路径 | 依赖作者资源包，**判死不入** | 不入库 |

> 依据实测：`guard系 95 条全部带 Guard 后缀`、`lytvs系 76 条全部不带` —— **后缀即体系**，这是硬规律，不是经验猜测。
> 🔞 是**正交的内容维度**：源本身是成人内容则额外勾选 🔞，与 A/B/C/D 并存。

**执行步骤（一把梭，别分步确认）**
1. 提取：包的所有 `sites`(`api`) + `lives`(`url`) + `parses`(`url`)
2. 去重：**以 `api接口` 为唯一键**，先与库内已有（导出 CSV）比对，剔除重复
3. 判体系：按上表
4. 批量写：`batch_add_database_records`，**每批 ≤100 行**
5. 回填：新增源的「可用体系」随写入一起落，不用二次更新

**提取时的字段映射**
- `名称` = 站点 `name` / 直播源 `name`
- `host` = URL 的 host 部分，或 csp 类名的小写下划线形式（如 `csp_Pan Ali` → `csp_panali`）
- `分组类目` = 按名称/section 猜，取已有 select 选项之一
- `api接口` = 站点 `api` / 直播源 `url`
- `入库时间` = 当天
- `状态` = 正常 / 待查
- `体系` = **保留旧值语义**（A→lytvs系、B→guard系、http→直链系），与新列并存
- 表 ≤12 行 → 直接 `insert_after` 表头行 id 插一行
- 表 >12 行 → **分两段整表替换**（table_edit.md 配额铁律）：
  1. `insert_after`(旧表前的 Heading 锚点) 插入**段1**（表头 + 前11行新内容）
  2. **读回段1真实表 id**（`get_doc_reviews.py` 定位）
  3. `delete` 旧表（**单独一次提交**）
  4. `insert_after`(段1新表 id) 插入**段2**（表头 + 剩余行）
- **禁止**：同一批里 delete+insert 超大表（524 会丢失旧表且新表没落）
- **禁止**：content 里写 `id=` 或裸 `TableRow`（必须全程 `<Table>` 包裹）
